# Codex Top for Windows

把 Codex 任务进度和账户额度放到 Windows 桌面上。

用一个紧凑的悬浮圆环查看任务状态，点击展开关注列表，在工作时随时了解哪些任务正在运行、等待处理或已经结束。

**Windows 11 x64 · C# / WPF · .NET 10 · GPL-3.0**

[从源码构建](#从源码构建) · [问题反馈](https://github.com/BuTangTang/Codex-Top/issues) · [集成说明](docs/INTEGRATION.md) · [验证记录](docs/VALIDATION.md)

当前版本：**0.1.9 开发预览**。基于 [BuTangTang/Codex-Top](https://github.com/BuTangTang/Codex-Top) 的产品设计与状态处理规则开发，程序内名称及可执行文件名为 **Codex Top / CodexTop.exe**。Windows 工程位于本仓库的 `windows/` 目录，独立构建；不代表已与 macOS build 27 完成功能对齐。与 OpenAI 没有官方关联。

## 功能一览

- **桌面圆环**：以数字、颜色和状态提示展示任务概况；鼠标悬停时轻柔放大，移开后平滑缩回。
- **完成反馈**：正在关注的任务由运行/待处理变为完成时，绿色对勾描画并轻微回弹；约 1.6 秒后恢复当前状态，全部完成则保持静态对勾。外环继续表示其他任务的运行或待处理状态。
- **四种显示方式**：桌面圆环、屏幕顶部、常驻浮窗、仅系统托盘，适应不同工作习惯。
- **关注任务**：按任务名称或项目搜索、多选，支持自动关注新建并开始的任务；子任务状态聚合到主任务。
- **直接取消关注**：点击任务右侧的 `×` 即可移出列表，已结束任务也适用；需要时通过 `＋` 重新加入。
- **账户额度**：显示当前账号实际返回的额度周期、剩余比例、更新时间和重置时间。
- **外观设置**：深浅主题、圆角菜单、面板比例与可见任务数调整，以及减少动态效果选项。
- **托盘驻留**：主窗口和设置窗口不占用任务栏，隐藏后可通过系统托盘找回。

## 快速开始

### 1. 准备环境

使用 **Windows 11 x64**，并确保本机已有 Codex 任务记录。查看账户额度还需要已登录的官方 **Codex CLI**。

便携包自带 .NET 运行时，日常使用无需安装 .NET SDK。Windows 10、ARM64 与 WSL 环境尚未验证。

### 2. 构建并启动

当前分支提供源码，尚未发布 Windows 下载包。按下文[从源码构建](#从源码构建)并使用 `-Publish` 生成 Windows x64 便携包 `CodexTop-Windows-x64-0.1.9.zip`。

解压整个压缩包，运行 **`CodexTop.exe`**。默认显示桌面圆环，右下角系统托盘也会出现程序图标。

### 3. 选择关注的任务

点击圆环展开面板，再点击 `＋`，搜索并勾选任务，最后点击 **应用选择**。也可以在 **监控设置** 中启用“自动关注新建并开始的任务”。

默认使用 `CODEX_HOME` 指定的数据目录；未设置时使用当前用户的 `.codex` 目录。若任务未显示，在 **监控设置 → 选择数据目录…** 中选择包含 `state_*.sqlite` 的目录。

## 操作指南

| 操作 | 效果 |
| --- | --- |
| 鼠标悬停圆环 | 放大约 12%；移开后恢复原尺寸 |
| 点击圆环 | 展开任务面板 |
| 拖动圆环或面板标题空白处 | 移动窗口 |
| 点击面板外部 | 收起临时展开的面板；常驻浮窗保持显示 |
| 点击 `＋` | 选择关注任务 |
| 点击任务右侧 `×` | 取消关注，不终止或删除 Codex 任务 |
| 点击“已结束” | 展开或收起已结束任务列表 |
| 点击任务内容 | 尝试通过 `codex://threads/<id>` 返回对应任务 |
| 右键圆环 / 点击面板 `⋯` | 打开菜单，切换显示方式、主题或进入设置 |
| 左键 / 右键托盘图标 | 展开收起面板 / 打开菜单 |
| 菜单 → 最小化到系统托盘 | 隐藏桌面窗口，保留托盘入口 |

任务跳转依赖本机 Codex 对外部链接的支持；合成测试任务不能跳转到真实对话。

### 显示方式与外观

| 显示方式 | 行为 |
| --- | --- |
| 桌面圆环 | 常态为小圆环，点击展开，点击外部后收回 |
| 屏幕顶部 | 显示紧凑摘要，鼠标进入后展开，移开后收回摘要 |
| 常驻浮窗 | 持续显示任务列表，不因点击其他窗口而收起 |
| 仅系统托盘 | 通过托盘图标打开临时面板 |

四种显示方式共用关注列表。取消“置顶为常驻浮窗”会返回之前的显示方式。

在设置中可切换深浅主题，将面板比例调整为 **60%–120%**，或设置 **1–12 条**可见任务，超出部分滚动查看。圆环常态直径为 44 DIP，不随面板比例变化；跨屏时按目标屏幕的 Windows 缩放比例绘制。

圆环动效遵循“减少动态效果”选项及 Windows 动画偏好。开启该选项后，悬停不再放大。

待处理与出错通过橙色、红色外环提示，中心保留运行数量，不叠加微小感叹号。完成提示只针对观察到的新完成状态，普通刷新、打开程序或重新选择历史任务不会反复播放；开启“减少动态效果”时显示静态完成提示。

面板取得焦点后，可使用以下快捷键：

| 快捷键 | 操作 |
| --- | --- |
| `Ctrl` + `+` / `-` | 放大 / 缩小面板 |
| `Ctrl` + `,` | 打开监控设置 |
| `Esc` | 收起面板；常驻浮窗返回之前的显示方式 |

## 任务状态与账户额度

### 刷新方式

| 内容 | 刷新方式 |
| --- | --- |
| 任务状态 | 根据本地记录变化更新，并约每 2 秒检查一次；支持暂停 |
| 账户额度 | 启动时读取，之后约每 60 秒查询一次 |
| 手动刷新额度 | 菜单或设置中点击“刷新账户额度”；两次查询至少间隔 5 秒 |

额度是**定时查询，不是实时推送**。鼠标停在额度文字上可查看更新时间与重置时间；点击额度文字会打开官方用量页。暂停任务刷新不会暂停额度查询。

额度通过本机官方 Codex CLI 的账户接口获取，单次请求超时为 15 秒。只显示接口实际返回的周期，不保证每个账户都有相同的周期；查询失败时显示不可用，不用历史任务日志估算剩余额度。显示延迟还受服务端更新和网络影响。

### 状态与计时

支持运行中、等待处理、失败、已完成、已停止及未知等状态。任务状态来自已写入本地的记录，可能存在延迟；运行记录超过 15 分钟没有活动时显示未知。

缺少可靠开始时间时，计时显示 `--:--`。等待状态下显示的是**本轮开始到进入等待时的耗时**，不是已经等待了多久。

### 数据访问

任务数据库和活动日志以只读方式访问；本工具不创建、删除或终止 Codex 任务。账户查询由 Codex CLI 完成，需要能够连接账户服务；工具不直接读取或复制认证文件，也不发起额度重置或购买。

工具自身的显示偏好、关注列表与数据目录设置保存在：

```text
%LOCALAPPDATA%\CodexTop\settings.json
```

## 常见问题

**为什么看不到任务？**

先确认本机已产生 Codex 任务记录，再检查设置中的数据目录。任务选择器只展示当前数据目录中可读取的任务；可点击 `＋` 搜索任务名称或项目。

**为什么账户额度显示不可用？**

确认官方 Codex CLI 已登录，且使用的 Codex 数据目录与该登录环境一致。如果未自动找到 CLI，在 **监控设置 → 选择 Codex CLI…** 中指定 `codex.exe`，再点击“刷新账户额度”。

**点击 `×` 会停止正在运行的任务吗？**

不会。它只取消本工具的关注状态，也会阻止自动关注立即把该任务加回来。通过 `＋` 可以重新关注。

**窗口不见了，任务栏里也找不到？**

程序默认不显示任务栏图标。展开右下角系统托盘的隐藏图标，找到 Codex Top，点击图标或使用菜单中的“找回窗口”。再次运行程序也会唤回已有实例。

**为什么展开面板一直不收起？**

先检查是否启用了“常驻浮窗”。该模式会保持显示；切换回“桌面圆环”后，点击面板外部即可收起。操作本工具的设置或任务选择窗口时，面板会保留展开状态。

## 从源码构建

开发环境需要 **Windows 11 x64、PowerShell 7、Git 和 .NET 10 SDK**。SDK 版本约束见 [global.json](global.json)，只安装 .NET 运行时不足以编译项目。

在本仓库根目录打开 PowerShell 7，执行：

```powershell
# 进入独立的 Windows 工程目录
cd windows

# 运行核心测试并构建 Windows 程序
./scripts/build.ps1

# 生成自带运行时的 Windows x64 便携包和源码包
./scripts/build.ps1 -Publish
```

以上命令在 `windows/` 中运行；输出位于该目录下的 `artifacts/`，程序为 `artifacts/CodexTop-Windows-x64/CodexTop.exe`。若使用单独导出的 Windows 源码包，先进入含有 `global.json` 的解压目录，直接运行构建脚本，无需执行 `cd windows`。若输出目录中的程序正在运行，请先退出再重新打包。

脚本优先使用项目内 `.tools/dotnet`，否则使用 PATH 中的 SDK；源码仓库不包含 SDK。源码打包使用项目自身的 `.gitignore` 规则，也支持从没有 Git 元数据的源码压缩包生成发布包。

### 验证与调试

执行 Windows 窗口回归：

```powershell
./scripts/build.ps1 -WindowTests
```

这项检查需要交互式 Windows 桌面，会创建隔离的测试窗口，验证透明边缘、悬停缩放、跨屏位置、展开收起、焦点交接及托盘行为。出现“点击开始交互检查”窗口时，将它置于前台；60 秒内未获得前台焦点会报告失败。测试不会读取真实任务或账户。

只有一块屏幕，或两块屏幕使用相同 DPI 时，不会将结果报告为已经覆盖混合 DPI 场景。

| --- | --- |

| `--show` | 启动后直接展开任务面板 |

所有入口共用单实例限制。更换启动参数前，需要先退出已有实例。

### 项目结构

```text
src/
  CodexTop.Core/           # 任务读取、状态归约、关注策略与额度查询
  CodexTop.Windows/        # WPF 窗口、系统托盘、设置、主题与图标
tests/
  CodexTop.Core.Tests/     # 核心回归
  CodexTop.Windows.Tests/  # 实际 Windows 窗口与交互检查
scripts/                  # 构建、源码打包和合成测试数据生成
docs/                     # 实现记录、验证证据与已知限制
```

`.gitignore` 排除本地 SDK、参考副本、构建输出、个人设置、认证文件、数据库和活动日志。测试数据由脚本临时生成，不提交真实任务记录。便携 ZIP 作为 Releases 的下载附件管理，源码仓库保留可重新构建的工程和许可说明。
