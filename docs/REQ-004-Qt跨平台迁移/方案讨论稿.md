# REQ-004 迁移到 Qt、实现跨平台：方案讨论稿

状态：**讨论稿，未审核**（2026-11-10，用户：“我现在想迁移到 qt 你做个方案，实现跨平台”）。这是写需求之前的方案讨论，里面的取舍要你拍板后才写成需求文档；不改任何现有代码。

## 一句话

用一套 Qt 程序同时出 Mac、Windows（以后可加 Linux）三个版本，界面和规则照搬现在的 Mac 版；Mac 原生版在 Qt 版追平之前继续用、只修问题，追平后退役；`windows` 分支上那份 C# 版不再往前做。

## 现在的情况

- **Mac 原生版**（主线 `main`）：Swift 写的，大约 9,600 行。分两层：
  - **数据层**约 4,100 行：读 Codex 状态库和任务记录（含压缩记录）、读 Claude Code 会话、状态判断、关注规则、额度、用量统计、钩子安装。这一层和界面无关，规则最多、测试最多（330 多项）。
  - **界面层**约 5,500 行：悬浮球、展开面板、刘海、菜单栏、任务选择、设置、用量卡片、各种动画。这一层大量用了 Mac 专有的窗口能力。
- **Windows 版**（GitHub 上的 `windows` 分支）：别人用 C#/WPF 另写的一份，约 4,500 行，停在 10 月 9 日，功能是 Mac 版早期的样子（圆环、四种显示方式、额度），没有 Claude Code、LED 点阵、用量卡片这些。
- 两份代码各写一遍规则，已经开始对不上；以后每加一个功能都要写两遍。这是迁移的主要理由。

## 方案对比

| | A. Qt 6 + C++，界面用 QML（推荐） | B. Qt 6 + C++，界面用 Widgets | C. Qt for Python（PySide6） |
|---|---|---|---|
| 悬浮球、LED 点阵、面板展开收起这类动画 | 擅长：自带动画、透明、按像素对齐 | 能做，但都得自己画、自己算动画，工作量大 | 同 A，但慢一些 |
| 和你现有经验 | 新学 QML，C++ 部分通用 | 和 PVTC 上位机迁移同一套，最熟 | 需要 Python 打包经验 |
| 常驻后台的资源占用 | 低，空闲时可以做到不重绘 | 最低 | 偏高（带 Python 运行时，约多 40～60 MB） |
| 安装包大小 | 约 40～60 MB | 约 30～40 MB | 约 80～120 MB |
| 数据层 | C++ 重写，按现有测试样例逐条对照 | 同 A | Python 重写 |

推荐 A：这个程序的看点就在悬浮球和面板的动效，QML 做这些最省事；数据层用 C++，常驻占用低。如果你更看重和 PVTC 用同一套技术、少学一样东西，选 B 也行，界面动画要多花大约三成时间。

## 迁移思路（以方案 A 为例）

1. **先做技术验证（约 1 周）**：只做一个能拖动、置顶、透明的悬浮球，带 LED 点阵和绕圈动画，分别在 Mac 1 倍外接屏、2 倍内置屏和 Windows 11 上实看；同时量空闲时的 CPU 和内存。过不了这一关就回头换方案，不往下做。
2. **搬数据层（约 2～3 周）**：把读记录、判断状态、关注规则、额度、用量统计用 C++ 重写。现有 330 多项测试用的合成样例原样拿来，Swift 版和 Qt 版对同一批样例输出要一模一样，才算搬完。
3. **搬界面（约 3～4 周）**：悬浮球、展开面板、任务选择、设置、用量卡片，样子和交互照现在的 Mac 版。
4. **补各平台专有的部分（约 2 周）**：见下一节。
5. **并行试用、切换**：Qt 版在你两台屏幕和一台 Windows 上并行用一段时间，追平后 Mac 原生版停止更新。

总计大约 2～3 个月（按每周正常推进估），手机连接组件不在这个数里（见待定 4）。

## 哪些地方各平台不一样

| 功能 | Mac | Windows | 说明 |
|---|---|---|---|
| 悬浮球、常驻浮窗 | 有 | 有 | 两边都能做；Windows 要额外处理多屏不同缩放 |
| 刘海模式 | 有 | 没有刘海 | 只在 Mac 上提供，Windows 改成“屏幕顶部” |
| 菜单栏 / 系统托盘 | 菜单栏图标 | 右下角托盘 | 同一套功能，两种入口 |
| 开机启动 | 系统登录项 | 注册表启动项 | 各写一小段 |
| 点任务跳到 Codex / Claude 桌面 App | 现有链接方式 | 要先确认 Windows 版 App 是否认同样的链接 | 技术验证时一起确认 |
| 数据目录 | 用户目录下的 .codex / .claude | 用户目录下的 .codex / .claude | 规则一样，路径写法不同 |
| Claude Code 钩子 | 现有小程序 | 要出一份 Windows 版小程序 | 命令写法换成 Windows 的 |
| 安装包、签名 | 签名、公证 | 签名（可选） | 打包脚本两套 |

## 风险

- **透明置顶小窗在 Windows 上的表现**：多屏不同缩放、切换窗口时会不会抢焦点、会不会挡住全屏程序，要在技术验证阶段实测。
- **1 倍屏清晰度**：现在 LED 点阵靠整数点位置保证不糊，Qt 版要在同样的两块屏上逐像素核对。
- **资源占用**：常驻程序最怕空闲时还在重绘；验证阶段就量，达不到现在 Mac 版的水平不往下做。
- **两份代码并存期**：搬迁期间 Mac 原生版只修问题、不加功能，否则会越追越远。
