# REQ-004 迁移到 Qt、实现跨平台：详细设计

版本：v0.1 **已通过**（2026-11-10，用户：“可以，拆任务”）。依据[需求 v0.1（已通过）](requirement.md)。任务见 [tasks/progress.md](tasks/progress.md)；开始写代码要等你说开始。

## 1. 一句话

在本仓库新建 `qt/` 目录，分三块：**数据层**（纯 C++，只依赖 Qt 的基础库，照搬现在的读取和判断规则）、**界面层**（QML 画面 + 一层 C++ 把数据交给界面）、**平台层**（Mac 和 Windows 各自的窗口细节、入口、开机启动）。先花约一周只做悬浮球的技术验证，过关后按“数据 → 界面 → 平台 → 并行试用”的顺序搬。

## 2. 总体结构

```
qt/
├── core/        数据层：读记录、判断状态、关注规则、额度、用量、钩子安装（不碰界面）
├── app/         界面层的 C++ 部分：把数据层的结果交给 QML，管理几个窗口
├── qml/         画面：悬浮球、面板、任务选择器、设置、用量卡片
├── platform/    平台层：mac/（少量 Objective-C++）和 win/（少量 Win32）
├── helper/      Claude Code 钩子小程序（Mac、Windows 各编一份）
├── tests/       测试和共用的合成样例
└── packaging/   Mac 打包签名、Windows 打包脚本
```

- **为什么数据层不用界面库**：这样数据层可以单独编译、单独测试，速度快，也方便以后加 Linux。
- **依赖**：Qt 6.8（长期支持版，到 2029 年），用 CMake 编译；读 Codex 状态库用 Qt 自带的 SQLite（以只读方式打开）；解压缩记录复用原生版里已经带着的 zstd 源码；不额外引入其他第三方库。
- **许可**：本项目是 GPL-3.0，Qt 以动态链接方式使用开源版即可。

## 3. 技术验证（先做，约一周）

只做一个悬浮球，验证需求 R-01 的三条，然后写一份验证记录交你看，过了才往下。

做什么：
- 一个透明、无边框、置顶的小窗口，里面是 LED 点阵数字和一圈绕着跑的彗星，可以拖动、贴边。
- 点阵用自己写的一个“点阵画布”控件直接往显卡提交一批小方块，位置全部取整到物理像素，1 倍屏不做圆角——和原生版现在保证清晰的办法一样。
- 彗星动画只在有任务在跑时开，静止时整个窗口不再重绘。

量什么、怎么判定：

| 项目 | 怎么测 | 过关标准 |
|---|---|---|
| 清晰度 | 1 倍外接屏、2 倍内置屏截图，用现有的逐像素检查脚本数“半亮”像素 | 点阵区 0 个半亮像素（同原生版 122 的结果） |
| 焦点 | 正在别的程序里打字时点悬浮球、拖动它 | 输入焦点不丢、全屏程序不被挡 |
| 空闲占用 | 收起、没有任务在跑，放 10 分钟 | CPU 平均接近 0，内存不超过原生版同条件 |
| 动画占用 | 彗星一直转，放 10 分钟 | CPU 和原生版同一个量级 |
| Windows | 远程那台 Windows 上同样做一遍（缩放 100%／150% 各看一次） | 同上；界面实看由你操作 |

## 4. 数据层（照搬规则）

逐个对应原生版的文件搬，规则和中文提示一字不改：

| 搬什么 | 说明 |
|---|---|
| 任务模型和七种状态 | 原样 |
| 读 Codex 状态库 | 以只读方式打开最高版本的状态库；读不到、版本不认识时的提示照原生版 |
| 读 Codex 任务记录 | 冷启动只读尾部、之后只读新增；超长行只看开头；状态判断规则照搬 |
| 读压缩记录 | 后台一次读完、同一时间只解一个文件、结果缓存，照原生版 |
| 读 Claude Code | 会话记录、运行登记（含进程是否还在）、钩子事件，照搬 |
| 关注规则 | 自动关注、手动移出优先、按天数移出已结束、老会话重新跑也加入，照搬 |
| 额度 | 照原生版启动 `codex app-server` 通过标准输入输出问额度 |
| 用量统计 | Claude、Codex 近 7 天，照搬 |
| 钩子安装 | 只在 settings.json 原文里插入或删除自己那一段，备份、回读，照搬 |
| 刷新节奏 | 文件有变化时快速刷新，平时按原生版的间隔；暂停刷新时全部停 |

**结果对齐的做法（R-07）**：原生版的测试样例现在是写在测试代码里临时生成的。先给原生版的检查工具加一个“导出样例和结果”的命令（只是开发工具，不改 App 行为），把每组合成输入和原生版算出的结果存成文件，放到 `qt/tests/fixtures/`；Qt 版的测试读同一批文件，结果必须一模一样。以后两边任何一边改规则，都重新导出一次，差异一眼就能看出来。

**数据目录**：两个平台默认都是用户目录下的 `.codex`、`.claude`，支持 `CODEX_HOME`、`CLAUDE_CONFIG_DIR` 和设置里手动选择（R-19）。Qt 版自己的设置放在各平台的标准位置：Mac 是“应用支持”下的 `Codex Top Qt` 文件夹（和原生版分开，并行试用互不影响），Windows 是 `%APPDATA%\Codex Top`。

## 5. 界面层

### 5.1 窗口

| 窗口 | 用在哪 | 说明 |
|---|---|---|
| 悬浮球 / 展开面板 | 悬浮球模式 | 同一个窗口，收起是球，展开是面板，和原生版一样从球的位置长出来 |
| 常驻浮窗 | 常驻模式 | 一直显示的面板 |
| 顶部面板 | 屏幕顶部、Mac 刘海 | 刘海只在 Mac 上有 |
| 托盘 / 菜单栏弹出面板 | Mac 菜单栏、Windows 托盘 | 点图标在图标旁边弹出 |
| 任务选择器、设置 | 都有 | 普通窗口 |

所有小窗口都设成“不抢焦点”：点它、拖它时，你正在用的程序继续保持输入状态（R-01 第二条）。

### 5.2 画面

- **悬浮球**：点阵画布 + 原生版同一份排版规则（字形、宽度、外圈灯的位置直接从原生版搬，数字都是整数点）；彗星、事件变色跑两圈、减速停下、OK 庆祝、Zz 呼吸都用同样的时间参数。
- **面板**：分段列表、行首竖条灯、等宽计时、标签、底栏、用量卡片，尺寸和间距用原生版现在的数值（每行 54 点、已结束 36 点、底栏 42 点等）。
- **配色**：深色 #0B0D10、浅色 #F3F4F6，状态色、来源色和原生版同一张表。
- **字体**：Mac 用系统字体（苹方），Windows 用微软雅黑 UI；等宽数字两边各选系统自带的等宽字体，计时宽度按实际字体量好后固定。
- **缩放**：设置里的缩放比例对整块画面生效，和原生版一样。

### 5.3 数据交给界面的方式

一个“任务仓库”对象（对应原生版的同名部分）在后台线程刷新数据，算好以后整份交给界面线程，界面只读。列表用 Qt 的列表模型，只在内容真变化时通知界面，避免没必要的重绘（R-20）。

## 6. 平台层

| 事 | Mac | Windows |
|---|---|---|
| 不抢焦点的小窗口 | 把底层窗口设成不激活的面板，加入所有桌面、不出现在切换器里 | 窗口加“不激活”“工具窗口”属性 |
| 刘海位置 | 读屏幕的刘海区域 | 不提供 |
| 菜单栏 / 托盘 | 菜单栏图标，弹出面板贴在图标下面 | 托盘图标，弹出面板贴在任务栏上方 |
| 开机启动 | 系统登录项（和原生版同一种方式） | 当前用户的“启动”注册表项 |
| 打开任务 | 现有的 `codex://`、`claude://` 链接 | 同样的链接，技术验证时确认 Windows 版 App 是否认 |
| 钩子小程序 | 现有命令写法：小程序在才运行，否则直接成功 | 用 Windows 的命令写法；小程序是一个很小的 exe，只记会话编号、类型和时间 |
| 减少动态效果 | 读系统的“减少动态效果” | 读系统的“显示动画”设置 |

Mac 部分大约 300 行 Objective-C++，Windows 部分大约 300 行 C++，其余全部共用。

## 7. 导入原生版设置（R-25）

Mac 上 Qt 版第一次启动、自己的设置还不存在时：
1. 只读打开原生版的设置文件（应用支持下 `Codex Top/preferences.json`），格式是原生版现在写的 JSON。
2. 认得的字段原样拷到 Qt 版自己的设置里：关注列表、排除列表、自动监控、显示方式、配色、缩放、可见行数、数据目录、Claude 开关等；不认得的字段跳过。
3. 原生版文件不改、不删；之后两边各管各的。
4. 读不了或格式不对：从默认设置开始，提示一次“没能导入原生版设置”。
5. 钩子是写在 Claude Code 自己的设置里的，不用导入；Qt 版启动后会认出原生版装的那一条（小程序路径不同时，按原生版已有的“旧路径条目先删再加”规则换成 Qt 版的）。

## 8. 打包

- **Mac**：用 Qt 自带的打包工具把运行库放进 App，签名；做成 dmg。并行试用期间用不同的应用标识（加 `.qt` 后缀），和原生版能同时装。
- **Windows**：用 Qt 自带的打包工具收集运行库，出一个免安装压缩包；需要的话再加安装程序。签名先不做（可选）。
- **编号**：沿用现在的版本号和构建号规则，Qt 版构建号单独从 1 开始计，避免和原生版、别的会话撞号。
- **远程 Windows（D-09）**：在那台机器上装好 Qt 6.8 和编译工具，我经 SSH 拉代码、编译、跑测试；界面实看你来点。

## 9. 测试和验收

- **数据层**：读共用样例文件，和原生版结果逐项比对；钩子安装、用量统计、关注规则的测试照原生版补齐。只用合成数据和临时目录。
- **界面**：两个平台的打包版真实窗口实看，Mac 两块屏；关键画面和原生版并排截图对比；悬浮球点阵逐像素核对。
- **资源**：和原生版同条件各量一次空闲 10 分钟、动画 10 分钟。
- 每一步的结果写进 `docs/validation/` 下的验收记录。

## 11. 风险和应对

| 风险 | 应对 |
|---|---|
| Qt 在 Mac 上做“不抢焦点的面板”需要改底层窗口 | 技术验证第一件事就做这个；做不到就停下来重新讨论 |
| Windows 多屏不同缩放下点阵发糊 | 点阵按物理像素取整；验证时 100%／150% 都看 |
| QML 空闲时也在重绘 | 动画只在需要时开；验证时量空闲占用 |
| Windows 上 Codex／Claude 桌面 App 不认现有链接 | 认不了就退回“打开 App + 复制编号”，如实提示 |
| Windows 上 Claude Code 跑钩子用的命令环境不同 | 验证阶段在远程 Windows 上实测一次钩子 |
| 两份代码并存期规则跑偏 | 原生版只修问题；样例文件两边共用，有改动都重新导出比对 |
