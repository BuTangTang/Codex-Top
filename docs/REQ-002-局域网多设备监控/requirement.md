原有基础目标继续有效：手机与电脑以账号密码连接同一账号范围，跨网络在指定电脑的原 Codex 任务双向收发文字；支持多电脑且不串会话，账号之间隔离；任务通知可直达对应对话，真实待批准操作可在手机处理。后台／锁屏通知、真实审批等是否可用须查对应验收记录，本汇总不作完成承诺。手机原生新建按 D-05 继续暂缓，不能借本次整理重新开放。

## 远程升级增量需求 v0.12（草案，待用户审核）

D-37（2026-10-01）：用户要求“做一个远程升级，不然每次都要连接手机，怪麻烦的”。范围为已安装的Telegram原生Android客户端。目标是后续版本可在手机联网时直接升级，保留同一账号、聊天记录、草稿与本地缓存。

建议本次采用以下行为，待用户审核：

- 在“我的”原版本行保留检查更新入口；应用启动或回到前台时，按现有更新检查节奏静默核对真实新版本。
- 有新版时沿Telegram原更新行和原下载进度呈现，由用户点击下载、安装，不另加自动弹窗或新页面。
- 安装包下载在手机完成；下载完成后交给Android原系统确认覆盖安装。无需连接电脑，不要求静默安装。
- 无网络、下载失败或取消时可继续使用已装版本；重新检查和重试沿原更新入口。
- 只交付与当前应用匹配的正式安装包，版本必须能区分新旧；升级后保留账号和本地数据。

验收：手机从上一版完成联网检查、下载、系统确认和覆盖；升级前后账号、会话记录、草稿、缓存保持。没有新版本时不打扰聊天；断网、下载取消和恢复后重试不能阻塞日常使用。电脑端发送恢复补丁及既有手机收发验收按原范围继续，不能用升级成功替代消息验收。

本增量只提交需求草案，尚未写设计、划分任务或编码。当前原代码有更新布局和安装入口，但现有构建关闭了接线；可用正式APK发布源还需在下一设计阶段确定，未将可达的服务版本接口当作安装包分发能力。

## 1. 产品目标

用户在手机 Codex Top 中查看电脑上的 Codex 会话、接收通知，并在同一会话继续对话。电脑上的 Codex 保持开启，继续管理原任务；手机消息与回复进入同一任务，不以停止桌面任务、接管执行或另开一套执行器替代。

支持多台电脑。手机选择来源电脑及其项目、历史会话，也能发起新会话。跨网络通信经过自建服务器，服务器不成为界面中的“云端会话”分类。

## 4. 主要使用流程

1. **开始使用**：手机和电脑端使用各自账号密码登录，手机展示自己账号下的电脑和会话。所选电脑全部可访问的会话无需先加入关注即可浏览；用户与同事之间不共享电脑、项目或会话。管理员预建账号即可直接登录，首版不提供激活或自助恢复流程。
2. **继续会话**：选择已有会话 → 查看其电脑和项目 → 输入消息 → 原电脑的 Codex 同一任务收到消息 → 回复同步回手机。进入另一台电脑的列表不能改变已打开对话的发送目标。
3. **创建会话**：新建 → 选择电脑 → 选择该电脑真实可用的项目 → 输入首条消息 → 创建并发送 → 打开真实的新会话。不能用本地占位行或另一套执行器的任务冒充成功。
4. **从通知进入**：收到任务通知 → 点击 → 打开对应电脑的对应会话；需要登录时，完成登录后仍应恢复该目标。目标不可访问时说明原因，不能跳到别的任务。
5. **手机审批**：进入需要批准操作的原会话 → 查看待处理操作 → 在手机确认或拒绝 → 对应电脑的原任务处理该决定并回传实际结果。不能把决定应用到其他任务。
6. **状态与异常**：连接中断、电脑离线、任务等待处理等状态如实表达。服务收到消息与 Codex 已执行不能混称“完成”；未知投递结果不得虚报成功。排队、运行中追加消息和断线重试的具体交互仍需后续设计与验证。

## 5. 需求验收要求

### 图片、文件与主导航（D-23／D-24，待实施）

- 手机向指定桌面原对话发送图片、文件，桌面能读取实际附件；桌面原对话中的图片、文件回到手机后可预览或打开、保存。仅气泡出现、路径文本或上传成功不等于双向收发通过。
- 附件发送立即进入记录，传输进度不阻塞继续输入；失败保留并可重试，结果不明时不盲目重复发送。切换页面、恢复网络和桌面回传不产生重复附件消息。
- 三个主入口保留各自导航和阅读位置；从电脑／项目进入对话后逐层返回，不跳到全局会话列表。默认50条最近对话，新活动置前；修改上限不删除项目历史。
- 进入聊天隐藏主导航，状态区域高度稳定，图片和文件复用原版附件交互。以上为后续验收目标，当前仅完成需求记录，未开始实现或验收。

### 普通聊天体验（D-22，统合 D-16／D-17／D-19／D-20／D-21）
