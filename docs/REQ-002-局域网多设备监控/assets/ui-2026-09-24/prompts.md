## 共同提示词

```text
Use case: ui-mockup.

为 Codex Top 制作中文 Android App 高保真设计评审图。这是交互概念图，不能画成已实现功能的证明。

画布横向 3:2，三台等大手机正面平行排列，屏幕比例约 9:19，占画布高度约 85%。整张画布使用不透明浅灰 #ECEFF3 背景，无透明区域、黑色背景、斜透视或大片无用留白。手机边框使用细线，不能有厚重样机边框。顶部标题适中，各屏外侧有编号和页面名，底部小字“交互草案 · 示例数据”。

手机界面采用白色与浅冷灰底、近黑色中文系统无衬线字体、#0866FF 蓝色强调、纤细分隔线、克制的圆角。信息密度参考微信常规列表和聊天页：顶栏约 52dp，底部导航约 56dp，列表行约 64–72dp，水平边距约 16dp，正文约 16sp，主标题约 20sp，次要文字约 12–13sp，线性图标约 22dp。这些是生成参考，不是已经冻结的实现尺寸。

原样沿用提供的蓝色 C 与橙点 Logo。不要巨大 Logo 卡片、宣传大标题、渐变、装饰光晕、管理后台或大面积状态面板。中文清晰可读，留出真实可点击范围，列表不能被底部导航遮住。

主导航恰好三项：“会话”“电脑”“我的”。只有主页面显示主导航，带返回箭头的对话、新建等子页不显示主导航。登录页也不显示主导航。无独立通知中心。

手机操作的是电脑上 Codex 的同一任务；电脑 Codex 保持开启。服务器是后台通信设施，不是用户需要选择的会话类型。所有日常文案为中文，品牌 Codex Top 和示例电脑名 MacBook Pro 可保留英文。

禁止二维码、扫码登录、Happier、Relay、CLI、MCP、localhost、IP 地址、英文安装指令、“Cloud sessions / Computer sessions”以及“云端会话 / 电脑会话”分类。不要加入接管、停止桌面任务或另开执行器的操作，不擅自增加好友、群聊、远程文件管理等功能。

不要依据画面自动扩充注册、找回密码、共享权限、手机审批或离线排队规则；未确认能力只能保留在需求讨论中。
```

## 图 01：日常使用

```text
标题：“Codex Top · 日常使用”。三屏从左至右：

01 会话
顶部小 Logo、标题“会话”，右侧加号用于新建。紧凑搜索框，下面有“全部 / 进行中 / 待确认”筛选和小型“全部电脑”入口。列表约六行，展示任务标题、来源电脑和项目、简短摘要、时间、状态。示例标题：登录页调整、修复消息重复、设置页交互、整理项目文档、通知跳转检查、历史记录搜索。保持行高紧凑，蓝色仅用于重点，不做多色大卡片。底部导航“会话 / 电脑 / 我的”，选中会话。

02 对话
返回箭头，标题“登录页调整”，次级文字“MacBook Pro · Codex Top”，小型“电脑在线”状态。显示简短示例对话：用户消息淡蓝、助手消息白色或简洁正文，文字易读。底部输入区含小加号、“发送消息”输入提示、蓝色发送按钮。输入区紧贴键盘预留区，无主导航。不要显示审批按钮、工具安装说明或服务器技术信息。

03 电脑
标题“电脑”，紧凑电脑列表。MacBook Pro 显示在线；办公室电脑显示离线和最近连接信息；行右侧轻量箭头。可有简短同账号电脑说明，不占大面积。底部导航选中“电脑”。名称和状态为示例，不暗示已经实现具体操作系统适配。
```

## 后续设计的核对要点

- 延续两张已确认图，不从早期含扫码的设计稿复制流程。
- 补画二级页面和异常状态时，先核对需求中的未决问题，不能以图片替用户确定功能。
- “待确认”状态不等于手机审批已确认；在线、账号、项目名称均是画面示例。
- 字体、触控区域、滚动、键盘、返回和切换流畅性要在实际 APK 验证，静态设计图不能替代。
- 本组只覆盖手机六页；电脑账号界面尚未在本组重新出图，不扩大本次确认范围。
