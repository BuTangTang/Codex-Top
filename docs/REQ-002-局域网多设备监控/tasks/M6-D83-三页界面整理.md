## 一期：现有数据上的界面整理

只用手机现有数据，不改协议，不改 happier。按顺序做，T3 之后的界面任务依赖 T2 的分组模型。

### T1 摸底：真实列表的工作区缺失比例

- [ ] 在真实手机或模拟器的现有账号上，统计首页会话中 `details.cwd` 有值和缺失的条数，以及同一台电脑上项目名重名的组数。
- [ ] 只记数量，不记路径、标题或正文；结果写进 STATUS。
- [ ] 缺失比例很高时先停下来告诉用户，再决定是否继续按项目分组为默认。

### T2 分组模型 `DialogArrangement`

- [ ] `ProjectPaths.normalize` 改为公开方法，现有 `contains` 行为不变。
- [ ] 新增 `com/butang/codextop/DialogArrangement.java`：输入会话列表和设置，输出行列表（置顶区标题、电脑标题、离线电脑行、项目组标题、会话行、“已结束 N”），规则按设计第3节。
- [ ] 状态类别从 `SessionStatus.Snapshot` 映射：待处理、出错、运行中、状态未知、已结束。
- [ ] 项目名：最后一级文件夹名，同电脑重名逐级补上级；无工作目录归“未关联项目”。
- [ ] 折叠：有运行中或状态未知时默认展开；已结束合并为“已结束 N”；组内全结束时展开直接列出；空组不显示；手动展开状态只存内存。
