## 1. 目标与边界

沿用已选蓝 C／橙点 Logo、白灰蓝配色与紧凑布局，完成会话／电脑／我的三个入口及所有相关二级页。
通知进入同一对话，手机能选择真实项目、继续原任务并查看真实待处理操作，账号页只显示当前账号和退出；原生新建按D-05后续待对接。
本模块负责呈现、导航和交互接线；不新造账号、机器、项目、消息或审批接口，不把示例数据写进正式路径。
不做扫码、云端／电脑会话分类、公开注册、激活、改密、恢复码、设备管理或上游推广页。

## 2. 依赖与文件交接

- 可先完善不依赖新接口的布局、组件和合成状态预览；预览不读取真实任务，也不当功能完成。
- M1 交回登录功能、状态及通知登录结果回调后，M3 才修改同一登录页面的外观；不更换认证 owner。
- M2 先验证并冻结历史、项目、新建、发送和审批契约，M3 再逐项接线，不写假成功分支。
- M4 独占通知响应和待跳转逻辑；M3 提供页面入口、导航结果展示及通知设置组件。
- locale 文件、登录页面、路由布局和聊天容器有跨任务改动时，由主管按精确文件顺序交接，不同时写入。
- 原生 Mac 登录功能属 M1，M3 如需协助其外观，须等 M1 交回 `Views.swift` 等对应文件；不新增第二份监控窗口。
- 打包、模拟器、小米、桌面操作均交 M5 的主管窗口；本任务不并行打开演示实例。

## 3. 规划唯一文件范围

未来开工先核对路径、当前改动和精确写权；下列 owner 是定位范围，不是整个目录的占有许可。

| 区域 | 既有 owner／页面 | 约束 |
|---|---|---|
| 主导航 | `MobileBottomChromeHost`、`TabBar`、`resolveTabBarTabs`、主路由布局 | 固定会话／电脑／我的，子页仅返回导航。 |
| 会话 | `SessionsList`、`SessionsListStorageChrome`、`DirectSessionsBrowseScreen`、`SessionView` | 统一呈现，保留底层目标身份；不并写 M2 的 RPC 或 M4 的通知 handler。 |
| 新建与选择 | 既有新建页面、电脑与项目选择组件及其 hooks | 只按已冻结能力接线；不调用普通 spawn 冒充原 Desktop 新建。 |
| 电脑与设置 | 原 `/settings/machines`、`SettingsView`、通知／外观／连接／关于组件 | 复用原页面，账号简化图优先于历史含改密图。 |
| 登录外观 | M1 交回的登录组件和错误态 | 只整理表现，不重复密钥、存储或账号逻辑。 |
| 文案与视觉证据 | 本模块涉及 locale、合成样例和脱敏界面说明 | 同一 locale 文件分批写入，禁止写入真实正文或密钥。 |
