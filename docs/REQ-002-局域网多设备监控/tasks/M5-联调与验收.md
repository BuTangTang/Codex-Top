## 1. 目标与执行边界

把 M1～M4 的成果整合为实际可用的安卓 App、Mac 连接与独立云端服务，按真实行为逐项验收。
正式测试使用明确指定的合成账号、项目和测试任务；不向用户正在工作的任务发测试消息。
主管独占桌面／模拟器／小米 Computer Use、统一构建和生产部署窗口，子任务只提供代码、脚本及证据。
本轮已启动本机整合；旧版本的测试和安装记录只作定位参考，不自动复用为本批通过。

## 2. 开始条件与规划文件范围

- 各任务先交回实际差异、写权、专项结果、接口版本、未完成项；源码存在不等于功能已验收。
- 真正新建、审批、忙时行为必须取得 M2 的目标版本能力证据；缺失时禁止声称整体完成。
- 账号和服务采用独立数据，目标设备／系统版本明确；需要 Windows 时单独核验对应适配。
- 主管维护 `docs/STATUS.md`、本任务、`tasks/progress.md` 及阶段验证报告；生产修复返回原任务负责，不并写其文件。
- 验证材料只保存必要的脱敏截图、版本、结果与错误；APK、真实账号、密钥、原始输出不提交 Git。

## 4. 账号和主流程验收

- [ ] 受限预建两个测试账号，重复账号被拒绝；同事正式账号只在实施阶段安全创建和交付。
- [ ] 手机与 Mac 同账号登录、重开保持、错密、退出当前端与换号逐一验证；其他端不被误退出。
- [ ] A 账号不能读取、发送、创建或批准 B 的目标；旧缓存、推送和迟到回调不能串账号。
- [ ] 电脑 Codex 一直开启，手机读取未关注历史、归档和多页正文；来源不可读时明确提示。
- [ ] 至少两台电脑同名项目、同名任务不串线；一台断开不影响另一台目标。
- [ ] 暂缓（D-05）：所选电脑真实项目中新建任务，在原 Desktop 核对存在，首条消息及回复真实回显；不列为本批恢复实施项。
- [ ] 同一原任务手机与电脑连续输入；空闲、忙时、断线、重连及结果未知符合已验证策略。
- [ ] 分别允许、拒绝、重复及过期审批，核对原任务真实结果；桌面先处理时手机不得再次决定。
- [ ] 任何发送和创建结果未知都不能通过盲目重试造成重复执行；故障恢复有可核对证据。

## 7. 停止与失败处理

误入真实工作任务、目标身份不一致、串账号、重复执行、敏感材料泄露或 PVTC 异常时立即停止相关动作，保存最少必要证据交主管处理。
部署出错只撤回本项目，不能重启、改库或删除 PVTC 资源；数据回退以兼容性和备份验证为前提。
结束时明确安装了哪个版本、哪些链路通过、哪些未完成；“完成 tasks 文档”“构建成功”“安装成功”均不能替代产品验收。
