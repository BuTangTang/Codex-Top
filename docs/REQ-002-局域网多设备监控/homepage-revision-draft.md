## 后续首页：常驻、待处理、所有（D-09）

2026-09-24 用户原话：“顶部会话，居中。然后分为三类，一个是常驻的，然后是待处理。然后是所有的，所有的长按或者往左右滑动可以选择置顶之类的。你觉得怎么样，这个你放到req里面，晚点在做。我们继续先做功能的实现”。

状态：**用户明确延后，仅记录需求；不排入当前编码批次**。上方D-08布局保留为当前实现基线，不能因本条文档更新立即替换产品。

- 标题“会话”居中，保留紧凑尺寸与原Logo；具体两侧空间在后续设计核对。
- 分类入口改为“常驻 / 待处理 / 所有”。常驻用于快速找到固定保留的对话，待处理依据真实待回复/审批事实，所有用于可访问会话浏览；账号与来源边界不变。
- 所有列表支持长按打开操作菜单，左右滑动提供快捷操作。用户提及置顶，尚未确定左右方向、菜单完整清单、滑动距离与取消规则，当前不自行增加删除/归档等操作。
- 主管建议：“置顶”与“加入常驻”合并为一个动作，移出常驻可逆；运行中、待处理、已完成等仍作为行内任务状态。此建议未单独获批，不能把常驻当成运行状态或用所有列表掩盖未知状态。
- 已要求的短动画、平滑切换继续保留；最终手势与状态排版在后续设计中确认。

当前优先项不变：桌面Codex保持开启，原任务消息同步手机，手机显示真实状态并能发送到同一对话；不为本条新造接口或修改消息协议。

### D-08 列表事实契约

沿用现有候选 LIST，在 `details.codexLifecycle` 返回 `{v:1,state,eventAtMs,checkedAtMs}`。`state` 允许 running、needs_input、completed、failed、cancelled、unknown；首页只将前三项分别投影到运行中、待处理、已完成，其他状态从电脑全部历史可查。读取采用有界完整行和明确主轮锚点；过期、缺失、冲突及无法确认的事实显式回 unknown，不能保留旧完成。

该字段仅供列表显示，不携带或冒充 Desktop 审批请求 ID，不授予控制权限。`eventAtMs` 是明确事件时间，`checkedAtMs` 是检查时刻，均不能由文件 mtime 估算。运行事实超过900秒降为未知。无新 RPC、无逐行 viewer lease；分页未尽、来源离线或部分读取失败须保留简短恢复/历史入口，不展示伪全量计数。

## 动画保留

保留状态标签指示线滑动、页面前进／返回转场、点击反馈和新消息轻量淡入；动画要短、连续，切换或返回中途可接续，不先闪旧页再重绘。不用大面积玻璃模糊、夸张缩放、长弹跳或不必要的自动动效。尊重系统减少动态效果设置。需要在安装包连续操作中检查，不能凭静态图认定流畅。

## UI 框架调研与已确认选型（2026-09-24）

确认原话：“可以，就使用你的建议吧”。本批采用现有 React Native／Expo、Unistyles 和 Reanimated，独立设计手机展示层，基础控件按需采用 React Native Paper；先验证紧凑三页样板。此确认不代表库已安装、样板已验收或真实业务已接线。

用户提出不必直接参考 Happier 的 UI，希望查找更合适的框架。可将 Codex Top 的手机页面独立设计，继续复用登录、同步和原任务通信能力；组件库不会自动消除多余入口、错误状态或旧品牌文案。

本机核对现有 React Native 0.81.5、Expo 54、Expo Router 6.0.22、Unistyles 3.2.4、Reanimated 4.3.0；动画与样式基础已经存在。优先建议沿用这套基础，按自己的页面结构重做手机展示层；如需新增成品基础控件，先小范围验证 React Native Paper 的输入框、按钮和弹窗，再决定是否引入。聊天列表、三态标签和页面密度按本产品设计，不直接套任何库的默认演示页面。

## 状态必须对应真实任务

| 分类 | 判定依据 |
|---|---|
| 运行中 | 原 Codex 当前轮明确在执行。 |
| 待处理 | 原任务明确等待用户回复或审批。 |
| 已完成 | 当前轮有明确完成记录。 |

不能把最近文件变动当成运行中，也不能把空闲、失败或取消直接改名为已完成。电脑离线、尚未同步和部分历史未加载作为辅助提示，不作为额外任务分类；有最后确认状态时标注其更新时间，没有确认状态时不硬塞三态计数。未确认及异常结束的历史不能删除，仍从电脑页全部历史查看真实结果。

正常情况下不显示同步提示。需要提示时使用一行“部分会话待同步 · 重试”，不要让大段解释和刷新卡占用首屏；错误详情在点击后展开。

## 本轮测试发现的前置问题

- 当前候选列表只有按更新时间计算的 active_recently / idle，不能靠改中文标签达成三态，须接入已有 Desktop observation 或明确轮次生命周期。
- 内部子代理有明确来源标记，但当前候选列表丢弃了该标记，导致内部记录混入；应按来源边界处理，不能按标题猜测或误删用户创建的任务。
- 标题回退把系统注入上下文当成正文标题；须保留真实请求、过滤注入上下文，并优先正式标题。
- 项目过滤只检查工作目录是否在项目路径内，会漏掉 worktree 任务；实际项目归属需准确连接，不能继续用目录包含关系代替。
