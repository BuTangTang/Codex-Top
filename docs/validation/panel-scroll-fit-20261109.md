# 两条任务仍可滚动修复（build 132）

用户以当前 LED 面板为准，反馈只有两个任务时滚轮仍能拉动内容。本次保持既有外观、行高与刷新频率。

## 原因与修改

面板高度原来为上下分隔线共预留 1 个逻辑点，绘制却按目标屏幕各画 1 个物理像素。外接 1 倍屏的两条任务内容高 108，实际滚动视口只有 107；因此之前的按内容大小关闭回弹仍认为存在溢出。

- 窗口高度和 SwiftUI 分隔线共用屏幕倍率、界面缩放计算，面板高度向上对齐物理像素。
- 刘海、状态栏、常驻浮窗和圆环展开各使用自身目标屏幕的倍率。
- 按实际列表视口与完整内容高度禁滚，容忍一个物理像素的取整误差；展开历史、屏幕限制或提示压缩视口造成真实溢出时仍可滚动。

## 验证

- 隐藏窗口、独立临时目录中的合成数据，覆盖 1 倍／2 倍屏幕与界面渲染比例 0.7125／0.75／0.9。旧预算在三个 1 倍场景均复现 108／107 的内容／视口差；新预算六组均容纳完整短列表，展开 28 条合成历史后均保留滚动范围。
- `swift test`：325 项通过；`swift build -c release` 与正式 App 打包通过。已有 LED 代码的不可达分支编译警告未在本次处理。
- build 132 严格签名和安装后可执行文件 SHA-256 回读通过；已有连接组件原样保留，运行中的后台仍报告 build 131。
- 正式包在 Q27G10E2 外接 1 倍屏、显示比例 95% 实测：两条任务上下滚轮无位移；展开“已结束”后可滚到其他行；折叠后两条任务恢复固定。之后恢复单一真实悬浮球，无 Demo 窗口。
- 2 倍屏幕本次为隐藏窗口尺寸回归，未进行内置屏物理拖动验收。

原始测试、构建与安装回读仅放在被忽略的 `.local/scroll-fit-*`，不提交真实任务截图或诊断原文。最新有效包为 132，上一版回退包为 131。
