# 待处理记录核对与来源任务跳转

日期：2026-09-13。应用：v0.1.0 build 3。此记录只对应本次修订。

## 已确认的现象

用户反馈已提交问题卡片，但监控仍显示待处理。只读核对期间，该任务尚没有与最后提问对应的用户回复。随后相同提问 ID 的结构化回复记录到达，安装新版前仍运行的 build 2 已自行恢复为运行中。因此本次现象为答复记录延迟，不能归为读取到答复后仍未清除；也没有证据量化从用户点击提交到落盘的精确延迟。原始日志、任务标题、答案、截图和本机路径均不进入公开材料。

## 本次代码修正

- 聚合任务行可能展示子孙任务的等待状态，旧点击逻辑却始终打开主任务。现在等待状态、计时和导航使用同一来源选择；主任务自身等待时保留主任务，非待处理行沿用原跳转。
- 跳转失败时复制实际目标任务 ID，避免复制错误的主任务 ID。
- 待处理行的悬停说明展示进入待处理和最近活动的时间、缺失时间和答复同步边界；不增加时间菜单或对话正文缓存。
- 当前安装的 Codex 外部协议解析只返回任务标识及受支持的 review 等入口，未提供单条问题或回复位置参数。用户要求的精确问题定位未实现，不以任务跳转代替该验收结论。
