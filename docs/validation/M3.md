## 2026-09-10 补充：自动关注、父子任务与格式恢复

继续使用独立 QA bundle、合成 SQLite/日志和单独偏好目录，非 Demo 读取路径。前半使用 `1757e99`，进程重启时换成本次设置/找回窗口修订包。

1. 初始库只有历史完成任务，首次打开关注数量为 0；随后写入新的运行任务，界面自动出现 1 项。
2. 该样例使用非 UUID 的 `qa-new`。点击后显示“无法打开 Codex，任务 ID 已复制”，在本应用选择器搜索框粘贴得到准确的 `qa-new`。没有发起有效 Codex URL，也未访问 Codex 窗口。此测试仅覆盖无效 ID 分支。
3. 通过选择器取消关注该任务、关闭自动加入，然后创建另一运行任务。多个刷新周期后仍为 0 项；重新开启自动加入时也没有倒灌这两项。
4. 重新开启后创建主任务及子任务：主任务自身完成、子任务明确等待回答。界面只增加一条主任务，显示“子任务 · 等待你的输入或确认”和“1 个子任务”。子任务收到输入并完成后，主任务移入“已结束 1”。
5. 退出并以新版重启，仍只保留该主任务，排除 ID 和自动开关持久化；历史、关闭期间创建及排除任务未被加入。
6. 临时重命名合成数据库的 threads 表，界面显示“当前 Codex 数据格式不受支持”，关注任务为未知；恢复表名后自动恢复“已结束 1”，错误消失。
