# D-69：展开窗口跨屏拖动抖动

日期：2026-09-20。版本：**1.0.0 build 15**。

用户确认抖动发生在按住鼠标跨屏过程中，松手后停止。D-68 字号与窗口尺寸保留。

## 调查与修正

- 旧逻辑在 SwiftUI DragGesture 回调中读取 currentEvent，再换算到正在移动的窗口；临时诊断记录到一次 500pt 的换算偏差和反向跳动。
- build 13 固定事件桌面坐标，build 14 改由 AppKit 接收鼠标事件，但两者都仍通过 setFrameOrigin 自行移动窗口。用户均反馈展开区仍抖动，不能以工具端点操作通过代替用户实际连续拖动结果。
- build 15 把原始 mouseDown 交给系统窗口服务，应用仅跟随原生窗口移动更新锚点和动画终点，不再逐次计算/设置窗口位置。松手后才收整和持久化。
- 原生拖动可能不回传 mouseUp，用仅在手势期间存活的 common-mode 定时器观察左键释放，视图脱离窗口时也收尾。标题按钮保留命中空洞，隐藏的圆环/面板不截取输入。

原生 API 行为依据 [Apple performDrag(with:)](https://developer.apple.com/documentation/appkit/nswindow/performdrag(with:))；事件桌面坐标依据 [Apple unflippedLocation](https://developer.apple.com/documentation/coregraphics/cgevent/unflippedlocation)。

## 验证

- 新增原生输入测试 4 项：同一事件在视图移动后重复处理仍保持同一桌面点；松开提交最后位置且不重复结束；标题按钮和隐藏表面不截取拖动；隐藏的真实 NSHostingView 在 75% 缩放下保留按钮命中空洞。
- 最终 `swift test` 128 项通过、0 失败；release 与 arm64 / x86_64 通用构建通过。最终包已更新本机应用，严格签名通过，安装包可执行文件与 dist 逐字节一致，ZIP 完整性通过。
- 用户在 build 15 上实际拖动展开区跨屏后明确回复“已经正常”。此结论来自用户的连续鼠标操作；此前 build 13 / 14 的工具操作不作为成功证据。
- 最终通用包已核对真实列表、“＋”打开选择器并取消、“⋯”打开菜单、Escape 关闭菜单并收回圆环。新增拖动层没有覆盖这两个按钮。
- 用户本轮新选择的浅色、75%、5 条及外接屏位置保留；最终安装与按钮检查前后全部偏好按语义一致，关注/排除/自动基线按集合比较。保留工作期间正常自动加入的新任务，不覆盖用户的新选择。
- 收尾仅一个真实实例，未运行 Demo，唯一 Computer Use 会话已重置。
- 临时诊断只记录窗口和鼠标几何、事件时间、倍率及动画状态，已从源码移除。真实任务截图、原始诊断和偏好不提交。

诊断事件记录不是屏幕逐帧录像；不把端点截图或事件采样称为完整 FPS 验收。物理拔插/合盖和 Intel 真机不在本次实测范围内。公开 README 图片保留 build 10 来源；本轮不发布或替换 Release。
