# 手机本地正文缓存与安装包瘦身

本批对应 REQ-002 D-17、D-18。用户要求进入对话先显示本地内容，联网后刷新，同时缩小安装包。源码验证、构建与设备验收分开记录。

## 已实现

- 沿用原同步 owner 和加密本地存储，缓存已读正文、对应游标及阅读锚点；重新进入先恢复正文，再增量同步。
- 缓存按账号、服务器和完整来源区分，容量上限 64 MiB，整会话淘汰。缓存不恢复旧运行状态或发送权限。
- 离线冷开提供已有正文入口；联网恢复保留原显式打开桌面任务流程。明确删除或拒绝读取时清理对应缓存。
- 图标改成按需导入；Android release 开启 R8 和资源收缩。
- 删除生产源码未使用的 AudioAPI、VisionCamera 依赖、插件和 AudioAPI 补丁；锁文件仅删除对应两个叶子条目。Expo Camera、Skia 与现有语音能力保留。

## 验证记录

- 正文缓存：275 项不重叠专项通过，完整 UI 类型检查通过；独立复核无新增 P1/P2。
- 离线呈现修正：158 项专项、完整 UI 类型检查及独立复核通过。缓存电脑名仅用于显示，离线暂停追赶动效，不改变真实状态及控制能力。
- 缓存入场计数：25 项聚焦及相邻回归、完整 UI 类型检查、独立复核通过。首批缓存只建立活动基线，之后真实新消息照常计数；未修改滚动命令、位置及动画算法。
- 历史分页离线动效：复用同一 Direct 连接判断，只收起转圈，保持已有请求、游标及本地缓存展开；短正文仍在加载时不改显无效的“较早消息”按钮。最终 12 项聚焦回归、完整 UI 类型检查和独立复核通过。
- 图标：236/234 个注册名与别名保持，233 个组件和 227 个图标数据核对一致；生成结果稳定。
- 配置瘦身：36 项配置测试、8 项安装检查、UI 类型检查通过。
- 图标专项有 1 项既有基线扫描误报：预览页 Ionicons 被通用扫描器当成注册表图标。未为此扩写产品代码，不称全套测试通过。
- 新版 Android 1.0.30/code31 已构建，原包名、签名和 arm64 范围保持；最终修正包已同签名覆盖安装并复验，原账号数据保留。

## 同批连接修复与边界

长任务本机 IPC 快照可达百 MiB。旧接收器逐块复制全部积压数据，导致超时。改为线性分帧，复用实际线上字节计数，只读历史等待扩大到 15 秒，候选窗口仍限制为 256 MiB，并保持精确回执及修订校验。

Mac build49 已安装，连接版本 `1.0.0+codextop.49`、指纹 `a7191fb30c25f518`。99 项控制测试、33 项 lease 复跑、CLI 类型检查、独立 9 项边界复核通过；Swift 205 项和 release 通过。正式公网控制探针一次在约 9.5 秒返回运行中及可追加消息。大帧只在本机 IPC，不上传原始桌面快照。

后续真实模拟器仍遇打开任务超时：小探针初始化 3 毫秒成功，owner discovery 5 秒无回执，仅 1692 字节，不属于正文大帧问题。实体手机是否已恢复发送尚无确认。不能把上述单次探针成功推广为发送问题全部解决。

## 构建说明

使用现有 arm64 包名和签名，原账号数据不清除。增量 prebuild 后，精确清理旧 AudioAPI 插件生成的前台服务声明，并确认自动链接中没有两个已删除依赖。

构建参数沿用现有配置入口：`HAPPIER_ANDROID_ENABLE_MINIFY=true`、`HAPPIER_ANDROID_ENABLE_SHRINK_RESOURCES=true`；本机 R8 需要 `HAPPIER_ANDROID_GRADLE_JVMARGS='-Xmx6g -XX:MaxMetaspaceSize=1g'`。正式构建关闭自动上传源码映射，使用 `SENTRY_DISABLE_AUTO_UPLOAD=true`。首轮 2 GiB 构建堆内存不足中断，不属于 App 运行内存。

旧包 1.0.29/code30 为 183,738,734 字节（175.23 MiB）；最终新包 1.0.30/code31 为 144,378,555 字节（137.69 MiB），减少 37.54 MiB／21.4%。实际 APK 中 JS 25.29 MiB、DEX 10.25 MiB、原生库 74.80 MiB、res 21.18 MiB。已确认 AudioAPI、FFmpeg、VisionCamera 原生库及服务声明消失，仍仅 arm64，非 debuggable。

最终新包 SHA-256：`80599da5b33ea1beb633a0d3e1b221955a0c28f95188a92f54e80b97ae8bf2a0`。签名证书与前版相同，原包名不变；首轮完整 Gradle 构建 6 分 57 秒，最终修正增量构建 2 分 2 秒成功。

后续最小 LINK 修复已通过 16 项真实合成 HTTP／Unix IPC 测试、CLI 类型检查及独立审查：只有已验证关联的桌面发现暂不可用允许继续阅读，发送仍要求真实控制能力。Mac build50 已签名覆盖安装并启动，正式账号和机器身份保留；此改动不代表 owner 无回执的根因已经解决。

build50 下，主管长任务的手机详情曾实际显示运行中；首页冷开仍可能短暂未知，尚不作为所有长任务及实体手机发送问题完全关闭。另一次指定 QA 原任务手机收发已通过，见下文。

## 第一轮真实包验收

模拟器 user10 的原 `butang` 登录保留，账户页回读一致，1.0.30/code31 运行无崩溃。在线打开指定 QA 原任务并缓存正文后，关闭网络（系统显示无默认网络），force-stop 冷开，首页出现缓存入口，点入可读完整已缓存正文。

翻到历史位置后离线返回重进，两个正文锚点分别仅偏移 3／8 像素，未跳到最新；联网后同位置和草稿保留。恢复网络没有自动发送草稿；主管手动发送一条 QA 消息，原桌面任务 8.6 秒完成，手机实际显示运行中→已完成及一条对应回复，输入清空。

实机发现离线顶栏退化为机器编号、首次离线打开残留追赶提示，以及离线重进误算 1 条新活动。三项已补齐并在最终候选包复验：离线冷开电脑名正确，无追赶文案；返回历史位置后两个锚点均仅偏移 1 像素，没有误报新活动。恢复网络后保留历史位置，经顶部刷新恢复已完成与可发送能力。无文字历史分页转圈已沿原显示信号修正；最后交付包再次断网冷开及返回历史位置复验，电脑名正确，无追赶、顶部转圈或新活动误报，两处锚点分别偏移 0／5 像素。原网络设置已恢复。既有收键盘后末尾跟随不足仍未关闭。换号及实体小米本批尚未验收。
