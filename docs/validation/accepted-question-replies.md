# 已接收回答的状态同步

日期：2026-09-22。用户要求“开始修改，不要影响我们的 ui”。本项只修复异步提问已回答后，圆环仍长时间显示待处理的问题；不修改视图、配色、字号、尺寸、菜单、窗口行为或动画。本机安装版本为 1.0.0 build 40，保留回退后的 build 36 外观。

## 原因与处理

本机排查确认同一回答在接收后约 95.6 秒才生成正式任务回复记录。旧实现只读取正式记录，因而把“已接收、尚未继续处理”显示成“仍等用户回答”。日志里的提交尝试尚可能被拒绝，不能直接作为成功证据。

本次通过当前数据目录下现存的桌面 IPC 临时订阅关注中的待答任务快照，仅接受已知版本中明确为 `accepted` 的回答项，并核对任务、活动轮次、问题调用编号、问题序号和提交时间。一组或多组问题未全部回答、同步审批、被拒绝/尚在提交、来源未知时均保留原状态。已确认的回答使用现有运行样式及“已回复，等待继续”详情；不增加界面组件。

辅助读取在后台执行，轮换查询至多 16 个待答任务，单帧上限 64 MiB、累计 96 MiB，连接及读取预算 1.5 秒；JSON 解码前后检查预算，但无法中途抢占 Foundation 解码。超过预算后回退，不能把它当作严格的端到端延迟承诺。只发送初始化及临时关注/取消关注，不启动桌面服务，不恢复任务或取得执行权，也不发送输入。退出时取消关注并关闭连接。快照只临时解析，不保存问题、答案和原始记录；缓存仅保留关联编号与提交时间。Codex 数据目录保持只读。

正式记录仍为主数据源。辅助读取完成后重新核对目标记录，正式回复、停止、失败、新轮次及新问题优先。回执不能修改真实事件时间、运行开始时间或计时回查结果。较久没有后续活动时明确显示未知。

## 验证记录

- 新增 24 项测试：严格回答包装与编号解析 5 项、归约投影 9 项、桌面 IPC 及本地数据源整合 10 项。覆盖已接受/待提交/失败、部分回答、新问题、轮次不匹配、旧历史、错误协议、超时、取消、分帧和大小限制。
- 合成整合场景中，正式回复记录尚未出现时，已接受且完整对应的回答恢复运行；待提交和失败仍待处理，正式停止事件优先，数据库与任务记录逐字节不变。9 MiB 合成快照可读取，读取期间主线程仍能响应。
- `swift test`：197 项测试全部通过；`swift build -c release` 与通用正式包构建通过。安装包包含 arm64/x86_64，严格签名校验通过，实际应用程序摘要与构建包一致。
- 已在更新前备份 build 36 与偏好，安装并启动唯一真实 build 40；逐项偏好完全一致，保留经典圆环、深色、圆环模式、原比例和可见任务数。没有启动 Demo，没有改变 Codex 数据。
- 在 Q27G10E2 外接屏上核对实际 44pt 经典圆环、点击展开、已结束展开/收起及 Escape 收回，布局、字号和颜色保持原样；视图及窗口源文件没有修改。
- 当前真实会话没有新的待答输入可用于测量修复后的接收至变色耗时。本轮分别验证了真实 IPC 协议、合成状态整合及正式应用窗口，尚未取得修复后同一真实回复的端到端延迟样本。

## 兼容性边界

桌面 IPC 为内部版本协议，当前仅解析已核实的初始化及 v11 会话快照。缺少桌面 owner、协议版本变化、历史超过读取上限或通道不可用时，安全回退到原有正式任务记录；不把未知输入伪装成已回答。该路径改善当前桌面端已接受回答的同步，不保证不同 Codex 版本都提供相同接口。
