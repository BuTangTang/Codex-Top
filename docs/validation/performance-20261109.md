# 常驻资源复测与优化（2026-11-09）

用户要求在滚动修复完成后检查资源占用，对照既定目标，未满足则继续完善。

## 口径

沿用[资源目标](resource-targets-20261004.md)与[后续合计口径](connection-performance-20261028.md)：设置关闭、真实悬浮球常驻，主程序和必要连接后台在同一个 60 秒窗口采集，CPU 取累计 CPU 时间差除以墙钟时间；RSS 与 macOS physical footprint 分列。CPU 目标低于 2%，内存目标低于 100 MB，完整安装 App 低于 100 MB（100,000,000 字节）。不降低刷新或消息同步频率，不删除功能，不以重启后的瞬时内存替代稳定结果。

正式窗口位于 Q27G10E2 外接 1 倍屏，深色、显示比例 95%。采样期间停止本轮构建、测试与其他性能探针；热点和内存详情在基线结束后单独采集。真实工作负载会自然变化，不能将不同任务状态下的数值直接算作严格因果降幅。

## 原生第一片：build 133

- Claude 时间解析复用现有 Codex 的 ISO 8601 解析样式，避免每行创建 Foundation 格式器。
- 读取使用字节换行搜索并逐行归约，不生成整批切片数组；每行释放 JSON 临时对象。半行保留至下次、冷读首残行跳过、空行和 CRLF 语义保持。
- 合成日期兼容在旧、新实现均通过；31 项 Claude 专项、329 项全量测试、release、正式打包签名与安装回读通过。正式窗口状态与短列表滚动保持正常。
- 同输入局部微基准确认日期解析与切行成本下降，仅用于证明具体路径收益，不代表整 App 的降幅。

真实任务在安装前自然变为 1 个运行、1 个待处理。30 秒预热后两段 60 秒：GUI CPU 4.600%／4.683%，后台 0.167%／0.200%，合计 4.767%／4.883%，仍未达到 2%。GUI RSS 192.71–227.57 MB；随后独立堆栈记录 physical footprint 65.0 MiB，峰值 74.1 MiB。剩余热点仍为 Claude 的暖增量 JSON 解析。

## 原生第二片：build 134

只枚举文件元数据发现 43 份 Claude 记录对应 40 个会话编号，其中 3 个编号在不同项目目录保留了不同大小的副本。原缓存只按会话编号保存游标和归约器：在大小不同的副本间来回读取会让游标失效，并可能混入另一副本的待答调用编号。

- 改为按具体文件 URL 保存读取进度，每个文件独立归约。
- 输出仍以会话编号为身份，每个会话只生成一个任务；选择明确活动事件时间最新的整份状态，平手用固定 URL 顺序。文件 mtime 仍只控制读取范围，不参与状态择优。
- 合成红测复现重复 ID、错误待答状态与未变化第二轮仍读取 2,283 字节；修复后同一测试通过，第二轮读取量为零。
- 32 项 Claude 专项、330 项全量测试、release、正式包签名与安装回读通过。真实外接屏已核对任务状态并恢复唯一悬浮球；后台继续使用原 131。
- 同为 1 个运行、1 个待处理，两段 60 秒：GUI CPU 1.817%／1.983%，后台 0.150%／0.167%，合计 1.967%／2.150%。第二段仍超过 2%，不能宣称稳定达标。
- GUI RSS 125.50–131.10 MB，后台 RSS 95.29–96.35 MB；随后独立 15 秒堆栈记录 GUI physical footprint 41.2 MiB、峰值 47.4 MiB。剩余 GUI 活跃样本主要在 Codex 路径解析、文件元数据与 SQLite 查询，Claude 重复 JSON 归约热点已消退；下一片继续按该证据优化。

## 原生第三片：build 135

134 的热点支持减少路径文本工作：有界复用父路径、叶名和压缩后缀，父目录本轮解析结果未变时不重新拼接完整路径。缓存最多 4,096 项、单原路径 1,024 字节，所有保留文本 UTF-8 合计最多 1 MiB；文件系统检查与刷新频率保持。根目录双斜杠回归先红后绿，保留原规范化结果。

46 项路径／查询／压缩专项、331 项全量测试、release、正式签名／安装与外接屏窗口检查通过。两条任务上下滚动不移动，运行时间由明确记录恢复，收起后只保留正式悬浮球。

同为 1 个运行、1 个待处理，两段 60 秒：GUI CPU 1.800%／1.817%，后台 0.167%／0.200%，合计 1.967%／2.016%，第二段仍略高于目标。GUI RSS 114.11–126.86 MB，后台 RSS 99.22–101.34 MB；随后独立采样 GUI footprint 45.6 MiB，峰值 50.9 MiB。合成微基准只作为实现路径的局部证据，不代替真实进程结果。

## 原生第四片：build 136

135 独立堆栈仍出现 LED 绘制反复读取 `statusSummary`，同一调用里多次扫描相同任务。分组函数只取一次汇总，视图直接从已算出的分组派生完成与灯圈状态；休眠只改变 OK／Zz 文字，完成状态和计时任务保持。另在两个同步循环开始时取当前关注集合和任务图，避免每个任务重复读取 `@Published` 值；不跨异步等待缓存这些状态。

331 项全量测试、release、签名／安装与正式外接屏窗口检查通过。两段 60 秒：GUI CPU 1.700%／3.850%，后台 0.200%／0.167%，合计 1.900%／4.016%。第二段后半出现最高 22.2% 的 GUI 瞬时值，保留为未解决波动，不能只引用第一段称达标。GUI RSS 119.44–130.25 MB，后台 RSS 95.96–101.81 MB。

随后独立 20 秒堆栈记录 GUI footprint 46.0 MiB、峰值 51.0 MiB；另在 GUI 瞬时 9.2% 时触发 10 秒堆栈，footprint 46.7 MiB、峰值 53.9 MiB。两份堆栈继续显示多处 `statusDetail` 汇总，以及窗口尺寸计算重复筛选、排序 `selected`。条件采样未完整覆盖前一段 22.2% 峰值，不能据此独立解释全部波动；下一片在状态 owner 统一复用当前图的派生结果。

## 原生第五片：build 137

TaskStore 分别复用当前任务图和关注集合对应的 `selected` 排序与 `statusSummary`，图替换或 selectedIDs 改变同步失效。缓存不发布通知、不落盘、不跨图保存文件状态；active、freshTasks 与 finished 保持实时计算，仅读取汇总不触发排序。

新增仅改变子项状态时的热缓存回归，并强化关注集合清空／恢复和子项完成后的断言。故意遗漏失效的变体产生 16 条预期失败；正确实现的 21 项相关检查、332 项全量测试、release、签名／安装通过。正式窗口观察到其他真实任务新增、完成以及待答转运行，最新状态和计数同步更新；未使用 Demo。

137 安装前后的真实工作负载已从早期 1 运行 1 待处理变化为多个任务，并继续变化；采样开始为 4 运行 0 待处理，随后观察到 3 运行 1 待处理，再到 1 运行 1 待处理。两段 60 秒：GUI CPU 6.816%／3.616%，后台 0.167%／0.133%，合计 6.983%／3.750%，GUI 瞬时最高 40.4%。GUI RSS 130.71–156.91 MB，后台 RSS 102.55–102.71 MB。此为真实任务新增、结束、待答变化中的观察，不代表固定负载稳态，不能直接与早期不同负载算严格优化降幅，也不能据此宣称达到 2%。

随后独立 20 秒／1ms 采样记录 GUI footprint 56.3 MiB，历史峰值 109.0 MiB。排除明确等待并按树去重后，主线程 `statusSummary`／`selected` 仅 2／1 个样本，136 同类采样为 13／13，说明这两处重复工作已减少；负载不同，不将样本数折算为因果 CPU 降幅。剩余读取与任务图重建继续分析，实际任务变化期间的高值保留；预热后还需固定负载复测。

完整安装 App 逻辑 96,997,671 字节、分配 98,504,704 字节，体积仍达标；保留137、回退136及仍被后台使用的131，退役133–135后回核保留包签名与哈希。用户反馈验收光标残留后已结束本会话的辅助光标进程，正式应用保持运行。

## 后台隔离定位

在禁网、临时 HOME、禁止读取真实用户数据的独立进程中，仅导入已装 daemon 相关模块、不启动服务即可复现约 174–177 MiB footprint；诊断 GC 后约 165–168 MiB、活 JS 堆约 94 MiB。空 Bun 约 8.5–8.9 MiB；只导入协议根模块，诊断 GC 后仍约 104–106 MiB。

标准 `--smol` 在反序重复实验中仅提早回收初始化垃圾，未减少约 94 MiB 的活堆，未用作产品修复。诊断强制 GC 仅在隔离探针中使用，没有加到产品。

已确认产品依赖复制时丢掉包的 `sideEffects` 元数据，影响无用模块裁剪。候选保留该标准元数据并给无副作用的协议包标记，实际 Bun bundle 少加载 67 个未消费模块；真实协议解析、canonical 复制与打包等 42 项测试、fallback 17 项及类型检查通过。

同源码、同 Bun 的四轮隔离对照中，改前稳定 footprint 177.3／179.9 MiB，候选 160.8／165.5 MiB；诊断 GC 后为 170.4／171.2 MiB 对 160.9／162.6 MiB，仍明显超标。该片只证明小幅收益，活 JS 堆没有下降，继续定位保留对象。尚未部署候选后台，没有候选的正式运行内存结果。

隔离堆及构造来源诊断确认 17,232 个存活 Zod 对象，大量方法闭包与连续约束 clone 的父链占用内存；不含真实会话。未消费 schema 的局部裁剪实验仍不足以解决目标，三份同版本校验库去重与 canonical 约束构造正在验证。真实产品代码未加入强制 GC 或诊断构造器。
