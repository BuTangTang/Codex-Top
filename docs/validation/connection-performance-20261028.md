# 手机连接后台性能优化（2026-10-28）

## 范围与验收口径

目标是降低连接后台的 CPU 与内存，保持手机同步频率、游标和送达行为。原生 build109 的圆环优化与连接组件分开验收；不能以重启后的瞬时值或合成测试替代整体资源与实机验收。

## 定位

原连接组件102此前60秒CPU均值9.21%、footprint228.9MiB。Bun JS采样83.2秒共2106样本，热点为JSON解析、`readJsonlFileForward`，可回溯到子任务发现 `discoverSpawnedThreadIdsFromFilesBounded`。每轮从文件头重新发现子线程导致稳定历史重复解析。

终端诊断重启曾意外继承本机代理变量，TLS目标校验失败；那一段低CPU样本作废。随后去除诊断进程代理继承，恢复正常证书校验和正常连接。未更改账号、服务器或Codex数据。采样已停止，正式后台恢复非采样启动。

## 源码修改

Happier 的 `collectCodexDirectTranscriptRolloutStreams` 复用未变化文件组的子任务ID。每轮检查dev/ino/size/mtimeNs/ctimeNs，读取前后变化则不缓存。新增、截断、替换立即重读；子文件发现每轮继续执行。只存ID及指纹，不存正文、语义tracker或文件句柄。不更改轮询间隔、正文游标或确认逻辑。

缓存上限128项、序列化元数据1MiB；此处不是实际堆内存上限。失败页不缓存，保留原读取失败行为。持续写入文件仍会重读，此优化不解决所有解析和内存成本。
