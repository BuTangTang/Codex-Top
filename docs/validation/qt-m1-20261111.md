## 行为对齐

- Claude 冷读从 64 KiB 开始，遇到只有附件的尾部时逐档乘四。原生代码在读完当前档后检查 8 MiB 阈值，实际最后一档是 16 MiB，用户确认按原生行为移植。
- 普通与压缩 Codex 记录跟随 build 155 的导入识别、缓存升级和本机续聊规则。开始时间缺失保持为空。合成样例还核对了同一毫秒内的事件顺序，以及不足一秒的等待用时。
- Windows 桌面客户端多个数据目录共用同一个命名管道。静态核对已安装客户端 26.1103.7773.0 的协议，客户端快照携带 `rolloutPath`。Qt 校验服务端用户、线程和轮次，并要求快照中的记录路径与选中库中的任务相符；缺少或不符时继续以记录为准。行为验证使用独立合成服务。
- 额度使用 `QProcess` 启动 `codex app-server --stdio`。自动/手动间隔为 60/5 秒，调用者共享请求。假服务验证读写、超时和取消后的进程回收，并覆盖服务提前关闭输入管道再发送看似有效额度的情况。

Windows 文件替换用例在解压进行中，以 NTFS 的 POSIX 替换语义提交同名新文件。读句柄共享删除权限，已开的句柄仍能读旧文件，新打开的句柄读取新文件；结果只接受指纹仍匹配的解码。此处沿用 Swift 用例的原子替换条件。

## 验证环境与复跑

Mac 使用现有的 Qt 6.11.2、Apple Clang、CMake 和 Ninja。Windows 11 x64 使用 Qt 6.11.2 MSVC、VS 2022 Build Tools（MSVC 19.44），在单独的 M1 目录里编译。Windows 批处理保留 ASCII 和 CRLF。

```sh
cmake -S qt -B qt/build -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH="<Qt 6.11.2 macos>"
cmake --build qt/build
ctest --test-dir qt/build -V
```

Windows 在本次检出的 `qt` 目录中运行 `packaging\windows\build.bat`。测试进程的 PATH 含所用 Qt 的 bin，QT_PLUGIN_PATH 指向同一套 Qt 的 plugins，再运行 `ctest --test-dir build -V`。测试使用独立临时目录，额度测试自举假 CLI，小程序测试复制并启动本次编译的 helper，验证通知写入、配置原文保留及撤销。

M1 验证截至数据层和独立 helper。双屏真实窗口验收见 M2，正式安装包、helper 随包运行库和在正式 Claude Code 中配置钩子的体验见 M3。
