## 2. 已证实的问题

### B1 缺陷：同一轮内第二个审批沿用第一个审批的摘要

- **位置**：`CodexRuntime.rememberPending` 用 `pendingIdentity(status)` 作为摘要的有效期标识，内容是 `turnId` 加 `questionIds`；`SessionStatus.candidateSnapshot` 只把提问（`user_action_request`）的 `requestId` 放进 `questionIds`，审批（`permission_request`）不放。
- **后果**：同一轮里出现两个审批时，两者的标识相同，置顶区第二行会继续显示第一个审批的命令。命令摘要是用户判断要不要批准的依据，显示错命令比显示“点开查看”更糟。
- **复现**：
  1. 在电脑上让一个 Codex 会话依次请求两个需要批准的命令（同一轮）。
  2. 第一个请求出现后，在手机上点进会话看到审批，返回列表，置顶区显示“批准：命令1”。
  3. 在电脑上批准第一个，等第二个请求出现。
  4. 不点进会话，看置顶区：仍显示“批准：命令1”。期望显示“待批准，点开查看”或“批准：命令2”。
- **修正方向（待实施时做）**：标识里加入审批的 `requestId`；或状态离开待处理时清掉该会话的摘要。不改变任何界面规则，属于按已通过设计修正。可先用 JVM 测试复现：同 `turnId`、不同审批 `requestId` 的两个快照，摘要应失效。

### G1 缺口：子任务数没有实现

- 需求 D-83e 和设计第4节写明“子任务数显示在聊天页顶部状态条”，T6 已勾选；但手机代码里没有任何子任务数的显示，happier 的候选和状态里也没有这个数。原来的“125 个子任务”只出现在 Mac 面板。
- 要实现需要 happier 提供子任务数，属于协议改动。可行性依据：happier `collectCodexDirectTranscriptRolloutStreams.ts` 读正文时已经通过 `discoverSpawnedThreadIds` 找出主会话派生的子线程编号（带缓存），数量可以随正文页一起返回，不必另扫文件；但这只在读正文时得到，列表和状态里没有。口径以 Mac 面板为准：`MonitorView` 取 `store.graph.children[taskID].count`，即任务关系图里该任务的全部子任务数（累计，不论是否在运行），只在任务未结束时显示。手机若实现，应取同一口径，并核对 happier 发现的子线程集合与 Mac 关系图是否一致。建议把 T6 这一项改回未完成，另列任务，排在二期之后；在此之前聊天页不显示子任务数，不估算。
