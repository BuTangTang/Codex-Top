# 刘海、圆环与数据修订 D-33–D-48

日期：2026-09-10。此记录区分概念图、真实应用、合成预览和构建证据。阶段提交允许保留这里明确列出的实机缺项，不代表全部 R01–R18 已完成。

## 改动

- D-33：每次布局重新获取系统状态按钮坐标；按钮不可用或已在移除的屏幕上时回退可见屏幕。两项新增测试覆盖同一 provider 更新和无效/缺失坐标，不模拟物理显示器通知链。
- D-34：名称统一为“刘海模式”，旧偏好兼容。两翼跟随浅/深主题；左侧待处理优先、右侧最多两行真实剩余额度。缺失、过期和旧记录均如实显示。
- D-35：运行弧使用原生图层重复旋转，同 key 避免刷新重启，相位在暂停时保留。圆环尺寸变化等 SwiftUI 动画完成后才整理原生窗口；代次标记阻止旧回调覆盖新动作。
- D-36：44pt 球内增加淡色底和 11pt `!`，失败用红色、等待用琥珀色；中心仍是运行数，展开或处理完移除提醒。保留原轻呼吸和减少动态效果分支。
- D-37：针对首版实机刘海“仍有点丑”的反馈，两翼各 98pt 收至 88pt，物理摄像头安全区不变；软件遮罩底角 9pt、外侧底角 12pt。收起浅色额外加 30% 白色调色层、描边透明度降至 0.14、摘要改 13pt regular 与 5pt 状态点。展开仍沿用原面板玻璃。
- D-38：圆环拖到上沿松手时，旧实现会主动恢复 hovered，触发 1.08 倍放大。现在实际拖放后保持不悬停，指针先离开再进入才恢复普通悬停反馈；拖动期间的 tracking 变化不触发它。圆环手势保留首次回调携带的位移，松手也核对总位移，过程曾移动至少 4pt 的动作不会作为点击展开。未移动的点击、普通浮窗吸附与待处理轻呼吸保留。

[状态提醒设计图](../design/status-reminder-v1.png) 是用户认可的方向，包含示例数据与放大讲解；不作为实机截图或动画证据。D-37 是随后实机反馈引出的进一步轮廓修订。

## 验证

D-38 的 `scripts/package.sh --universal` 成功：58 项测试零失败（核心 24、几何 14、状态 2、跳转 2、额度 8、摘要 8），arm64/x86_64 release、严格签名和 ZIP 完整性通过。真实桌面包与最终构建的可执行文件一致，`CodexTopDemo=false`。

实际操作由主代理在同一 CUA 工作流中完成，没有并行控制桌面的子代理：

1. D-34 首版真实包：浅色/80% 圆环显示实际运行数，点击展开实际任务和日志额度；设置显示新的“刘海模式/刘海显示器”。切刘海后，真实内置屏状态条显示浅色两翼、左运行数、右周额度；点击后展示浅色任务面板。用户随后要求改善方形黑区和硬描边，形成 D-37；首版截图不作为外观满意的结论。
2. 最终代码的隔离 Demo：观察到 44pt 琥珀色提醒球、内部 `!`、中心运行数；点击后观察到三条合成任务面板。部分 CUA 操作返回状态变化或窗口定位错误，因此不记录这些操作本身为成功，也不据端点截图推断帧率、呼吸周期或快速打断全时间线。深色端点和其他提醒状态未在本次完整复测。
3. 用户在临时 Demo 期间看到示例任务并反馈无法跳转。这是本轮调试造成的使用混淆：已退出 Demo，恢复原 Demo 偏好，将其应用与压缩包移入隐藏测试备份。真实任务没有替换成示例数据。
4. 最终桌面真实包已恢复：实际任务和额度来源可见，演示说明消失；点击真实任务后圆环收回、应用保持运行。只确认导航入口和应用存活，未读取 Codex 对话终点。

上述 D-37 验收后恢复为真实应用、圆环、浅色、80%，保留原任务选择。D-37 新轮廓尚未再次切刘海验收，避免在用户当前使用期间继续切换模式。本阶段两个提示服务均已正常退出并用进程列表确认；D-38 后续交付结果另补，不能把这些端点截图当成拖动修复的实机证明。
