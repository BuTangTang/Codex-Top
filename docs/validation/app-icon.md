# 应用 Logo 接入与安装验收

日期：2026-09-11。用户确认采用蓝色 C 形圆环与橙色提醒圆点的 Logo，并要求接入、安装；随后反馈启动台缺少应用和浮窗文字偏糊。

## 变更与安装

- 源图 `Resources/AppIcon.png` 为内置 imagegen 输出的 1254 × 1254 透明 PNG；提示词见 [Logo 设计](../design/logo-v1.md)。
- 构建脚本用系统 `sips` 生成标准 10 个图标表示（逻辑尺寸 16、32、128、256、512，各含 1×/2×），再用 `iconutil` 打包 ICNS，写入 `CFBundleIconFile=AppIcon`。
- 应用版本 `0.1.0`，构建号 `2`。先更新已有桌面包，再根据用户的启动台反馈移至系统“应用程序”目录并登记 LaunchServices；桌面不再保留第二份安装包。
- 旧应用和偏好检查快照仅保存在忽略的本地目录。未启动 Demo、未修改 Codex 数据、未更新历史 Release 附件。

## 文字清晰度反馈

安装初期保留了圆环、浅色、95% 的设置，用户随后自行切换为常驻浮窗、浅色、90%。在用户反馈文字偏糊后，确认现有 `ScaledPanel` 使用 `scaleEffect` 对内容整体缩放；这属于可疑影响因素，尚不能仅凭代码认定为唯一原因。

在同一个真实常驻浮窗对比 90% 和 100%，100% 下文字目视更清楚、窗口也更大。当前留在浅色、常驻浮窗、100% 供用户比较；未修改字体或窗口渲染代码，用户尚未确认清晰度满意。此次图标接入没有引入内容缩放逻辑。

## 验证边界与下一步

- CUA 对 Launchpad 和 Dock 的直接读取超时，因此启动台核验来自其只读索引与书签，不宣称已看到启动台图标网格。Finder 新 Logo 有实际窗口证据。
- CUA 重连后取得当前真实窗口；不把失效的元素点击或中间动画帧当作操作成功证据。
- 本轮没有发布新 Release、重做 DMG、全量复测其他功能或取得 Intel 真机验收。历史发布包仍是构建 1。
- 继续根据用户对 100% 文字效果的反馈决定是否改动渲染；不能将尺寸变大直接宣称为已修复所有模糊问题。
