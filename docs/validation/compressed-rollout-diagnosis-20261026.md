# 任务记录不可用排查（2026-10-26）

本轮仅诊断，未修改产品源码、安装包、Codex数据库、配置或记录。正式包build102。用户截图1117条记录不可用；当前原生窗口已恢复主任务运行，告警为1116。

## 证据

- 主数据源按数据库最高版本state_5的threads表中archived=0读取所有行，而非仅关注列表。首次只读扫描1130行，其中14条普通文件可读，1116条打开原路径得到ENOENT（文件不存在），不是权限拒绝。
- 1116条均存在可读的原路径加.zst同名文件；文件头全部为Zstandard魔数28b52ffd。无同名普通文件迁移到另一个sessions/archived_sessions目录的证据。
- 压缩兄弟文件合计10,716,073,500字节。使用本机既有zstd -t抽查3个不同大小样本全部通过，不代表逐个验证全部压缩正文。没有批量解压或输出正文。
- 截图中的主任务在本轮检查时普通文件已出现且持续更新；正式窗口实际显示“正在执行任务”。1117→1116与该任务恢复一致，但没有证据确认此前由哪个进程或工具执行压缩／展开。
- 已有只读inspect复现1116条unknown及相同告警；该次扫描1131任务（扫描期间实时增加），341根任务，冷读983040字节约0.059秒，暖读911字节。

## 根因与呈现问题

LocalCodexSource直接使用rollout_path；IncrementalRollout.refresh只stat/open普通文件，未解析压缩兄弟文件。ENOENT统一转成“暂时无法读取任务记录”，并累加全库告警。因此已有压缩记录被误归为不可读，不能据此认定对话丢失。底部全库告警与顶部关注数量范围不同，也没有解释原因。

## 修复方向（未实施）

支持只读识别压缩记录，并区分压缩、缺失、权限及损坏。按关注范围与文件指纹有界解析／缓存；不得每2秒全量解压约10.7GB，也不得从旧时间估算当前状态，或者把所有压缩记录默认视为完成。普通文件恢复后回到原增量读取。告警需说明统计范围与具体原因。按项目要求保留Codex数据只读。
