# 使用说明

圆环中心数字是关注列表中正在运行的任务数，超过 99 显示 `99+`。蓝弧表示运行；需要回答或确认时，浅色主题用淡橙色、深色用淡琥珀色底和内部小 `!`，出错时优先使用红色。提醒优先于运行颜色，中心仍保留运行数量；整个圆球轻微缩放呼吸。全部完成显示绿色对勾，空闲显示 `0`。点击圆环查看具体事项。

## 开始

1. 实际使用请双击 `Codex Top.app`，显示自己的关注任务和额度。本轮 beta.5 的最终测试、通用包和列明实际窗口核对已完成；安装版本、发布状态与实际验收范围以 [beta.5 记录](validation/beta5.md) 为准，中间候选不当作最终包。保留自己的模式和原真实关注列表。
2. 在菜单栏找到 Codex Top 图标，左键直接显示任务；右键打开菜单后可选择“设置…”。设置每次打开时跟随鼠标所在屏幕，不跟随固定的刘海显示器；首次、重新打开或跨屏再次进入时，在该屏幕工作区居中。若已经完整显示在鼠标同屏内，保留原位置和窗口大小。
3. 在“选择任务”中搜索任务名或项目、勾选目标后确认。“全选当前结果”只影响当前筛选结果；取消不会提交草稿。
4. “自动监控新任务”默认开启。打开后，新建并开始的任务会加入；自己取消关注的任务不会反复自动加入。

`Codex Top Demo.app` 只用于隔离测试，不读取真实任务或账户额度。后续验收以真实应用为准，不再把 Demo 切到日常使用的桌面。

## 把界面变小

“设置 → 显示比例”使用原生滑块，可按住连续拖动，在 60%–120% 之间每 5% 一档，共 13 档；旁边显示当前整数百分比，两端分别为 60% 和 120%，点击恢复按钮可回到 100%，滑块位置同步更新。旧版保存的 80%、90%、100% 设置仍兼容，桌面圆环始终保持 44pt。在 60%–75% 时，展开面板顶部的“选择任务”缩为加号按钮，点击作用和悬停说明保持不变，为标题和收起按钮留出空间。

应用或监控窗口取得键盘焦点时，`⌘+`／`⌘=` 放大，`⌘-` 缩小，每次 5%，沿用同一范围、滑块和保存值。`⌘=` 不需要按 Shift。快捷键不会全局拦截其他应用的输入；`⌘,` 打开设置，`⌘T` 显示任务。再选显示方式：

- “常驻浮窗”：一行一个任务，直接拖动整个顶部的标题、空白与上下留白；按钮区域仍用于点击操作。钉住后仅保留浮窗，刘海区域隐藏；取消图钉或关闭浮窗回到刘海模式，系统状态栏图标继续保留。
- “圆环”：只留下 44pt 小圈，悬停只有轻微动效，左键点击才由小圈本体展开任务窗口；展开后移开鼠标仍保留。点击面板外、点右上角收起按钮或按 Escape 缩回，也可切换显示模式。收起时拖动圈本体；D-48 中展开后也能拖顶部，收起回到移动后的球位置。右键圆环打开与状态栏相同的菜单。
- “仅状态栏”：透明背景显示彩色状态点与计数，数字跟随系统菜单栏明暗；左键在按钮下方展开完整任务面板，再次左键收回，右键打开菜单。展开后鼠标留在状态按钮上或移开都不会自动收起。
- “刘海模式”：保留刘海附近或普通屏上沿的状态条。左侧优先显示待处理数量，没有待处理时显示运行数量或暂停、完成等状态；右侧显示真实剩余额度，两个周期分两行，内容避让摄像头占用区域。收起和展开保持相同横向位置、宽度和顶部边缘。透明底融入系统菜单栏的建议尚未实施，目前保留原有玻璃外观。

D-48 取消全部拖放自动切状态栏：浮窗或圆环拖到屏幕顶部也保持当前模式，不再显示吸附提示。想收进状态栏时，在菜单中手动选择“仅状态栏”；重新选择“圆环”或“常驻浮窗”可回到桌面，关注列表保持不变。状态栏位置由 macOS 排布。

顶部拖动不需要长按，也不局限于左侧小手柄：在标题、空白或上下留白处按下即可移动；选择任务、图钉、主题和收起等按钮保留点击功能。移动展开圆环会同步更新小球锚点，收起不会跳回移动前的位置。

圆环面板展开时，点击外面的桌面或其他应用会让它缩回，同时原来的点击照常生效。单纯移开鼠标不会收起；常驻浮窗也不会因为外部点击而隐藏。

圆环保留一条状态细线，正常运行时蓝色弧线连续转动，定期刷新任务不重新起转。待回答或出错时，44pt 圆球内增加 11pt 的 `!` 标记和轻微提醒底色，整球从 44pt 缩至约 41.4pt，再恢复，约 1.8 秒一轮；不会额外弹出面板。展开任务面板或处理完事项后撤除提醒标记并停止呼吸。系统“减少动态效果”关闭旋转和呼吸，保留静态颜色、标记与运行数。全部完成时绿色圆环合拢后静止，未知/未运行用灰色。还有任务运行时，新完成任务可短暂显示绿色反馈后恢复蓝色；待处理提示优先。颜色不代表精确完成百分比。

圆环和面板使用同一个窗口，动画结束后收整边界。D-47 将主体、正文和圆环淡入淡出统一到同一弹簧进度，去掉固定的文字等待和额外中心缩放。此前首次展开抖动有用户反馈；新实现与端点截图不能证明完全零抖动，连续开合证据见 [本轮验收记录](validation/notch-orb-refinement.md)。

运行圈按同一时间相位持续旋转，一圈约 1.2 秒；新出现的运行圈和重新显示的运行圈接入当前节奏。系统“减少动态效果”时静止，不可见时停止旋转。各形态保留自己的弧长和起始造型，不因此改成相同尺寸。圆球本身仍为 44pt；完整动画与帧率不由单张截图证明。

点击后球消失，任务面板从原球位置向下展开，让标题靠近点击处；靠左右边缘时向屏幕内侧放置。只有下面空间不足、上面空间更多时才向上展开；仍不够就滚动，不会随着列表变化反复切换方向，收起恢复原球位置。上一真实候选已核对点击后指针靠近标题，全部边缘和物理显示器组合仍按验收记录分别验证。

打开“已结束”时，向下展开的面板保持顶边，回退向上展开的面板保持靠球的底边；收回已结束区也保持同一边缘，空间不足时滚动。已取消自动滚到已结束任务；上一真实候选中，打开和收回该区都保留了当前运行行，滚动位置保持为 0。

纯黑与浅色玻璃在设置里切换；展开面板底部也有一键切换按钮。新主题从按下的位置向外圆形扩散，底色、文字与控件一起揭开，其他窗口和圆环同步采用黑白外观。系统开启“减少动态效果”时使用短淡变。刘海模式的收起状态条和展开面板跟随主题。常驻浮窗与点击展开的圆环面板都不会因鼠标移开而隐藏；刘海模式仍在悬停时展开、离开后收起。

浅色玻璃模糊任务面板后面的内容，任务名、搜索框和按钮文字保持清楚。刘海软件外观仍避让物理摄像头，不能改变硬件黑色区域。

beta.2 的字号按窗口所在屏幕调整：内置屏使用常规字号，外接屏使用紧凑字号；常驻浮窗无论放在哪块屏幕都保持紧凑。显示比例仍由自己的滑块设置决定。常规档标题、任务名、辅助文字的有效下限为 15/14/12pt；紧凑档为 13/12/11pt，低比例时也保留对应下限。监控列表、选择器、额度和收起摘要同步匹配，原生设置控件仍使用系统字号。

浅色主题的待处理圆环、任务圆点和面板标签统一为同一种橙色；“待处理”小标签使用 12% 淡橙底配深色文字，圆球背景只带很淡的橙色。深色仍保留原琥珀与半透明底，失败仍为红色。用户已认可圆环的新橙色，并将标签改为淡底；面板内外的一致性与各屏幕字号仍按本轮实际窗口结果验收，待处理含义、运行数量及提醒优先级不变。

“运行中”状态文字跟随主题使用主文字色：深色主题亮白、浅色主题深色，便于阅读小字号。旋转环仍是蓝色；待处理、完成和失败的颜色保持各自含义，字号和窗口尺寸不因这次颜色调整变化。

系统状态栏的计数使用原生透明背景，不加黑色胶囊；文字随系统明暗变化，彩色状态点保留，不跟随桌面面板的黑白主题。

状态栏展开面板也跟随显示比例；beta.2 的范围为 60%–120%，窗口、文字和点击区域同步缩放，并保留对应的文字下限。收回后只保留系统状态栏计数，不应留下小黑块。显示器重新排列、主屏变化或找回窗口时重新读取状态按钮位置；按钮暂不可用时回退到选定屏幕可见区上沿。刘海顶部面板的同宽规则不改变菜单栏弹层、圆环和独立常驻浮窗的各自布局。

## 外接屏

圆环拖动到屏幕上沿并松手后保持原大小，不触发额外的悬停放大或自动展开；鼠标移出再移入才恢复普通悬停反馈。待处理的轻呼吸仍保留，点击才展开。

“刘海显示器”可以自动使用系统主显示器，也可固定显示器。断开后回退可用屏幕；“找回窗口”将窗口移回可见区域。两项新增锚点测试验证读取当前坐标及无效坐标回退，不能代替物理重排、拔插、合盖和不同缩放组合验收。

字体档位看各窗口实际落在哪块屏幕，不是整台电脑统一按主屏决定；外接屏即使设成主屏，也仍使用紧凑档。暂时无法确定窗口所在屏幕时保持当前字号，待拿到实际屏幕后再更新；常驻浮窗始终保持紧凑。

## 状态与设置

点击真实任务返回 Codex 中对应的对话；演示任务只显示说明。无法打开 Codex 时会提示并复制任务 ID。等待/批准仍到 Codex 中处理，监控工具不会替你批准或执行命令。

已关注列表里的待处理活动会监听本地任务记录变化，包括聚合到主任务的待处理子任务，最多 64 个文件。连续事件合并约 200ms 后触发增量刷新，原有 2 秒轮询继续兜底。完整用户回复记录落盘并被读取后即可解除等待，不必再等后续完成事件；合并时间不代表从按发送起固定 200ms 就会更新，也不能缩短 Codex 自身的写盘延迟。

正在运行但缺少本轮开始记录时，计时位置显示 `--:--`，悬停可看原因。应用仅为已关注主任务及其子任务分批回查明确的本轮开始记录，再按事件顺序核对到当前状态；确认属于同一活动后补开始时间和必要的缺失轮次关联。不会拿任务创建时间、文件修改时间或应用启动时间估算，也不会为了计时改写任务状态。记录缺失、尚未查完或无法确认时继续保留 `--:--`；等待标签的缺失耗时仍不补造。

“待处理”标签后可显示固定的 `mm:ss`，表示本轮开始到首次进入当前这次等待的经过时间。例如本轮开始两分钟后提问，就显示 `02:00`；等你回答期间数字不再增长。它不是 CPU 用时，也不会自动扣掉本轮更早的等待。回答后清除本次等待计时，若同一轮再次进入等待，重新固定到那次等待开始的时刻；新一轮使用自己的开始时间。

普通输出、额度 token 记录和重复等待事件不会重置这个数字；异步提问后本轮结束而问题仍未回答时也保留。缺少开始或等待时间、时间倒序时只显示状态，不估算耗时。主任务因子任务等待而显示“待处理”时，耗时取该条实际展示的子任务活动，不混用主任务的开始时间。

点击面板底部额度可打开 [Codex 官方用量网页](https://chatgpt.com/codex/settings/usage)。鼠标停在额度上可看来源、更新时间和重置时间；右键额度或进入设置可手动刷新。只显示服务实际返回的窗口：只有周额度时不会补造 5 小时额度。

主界面只显示已登录 Codex CLI 读取的账户额度，自动约 60 秒刷新、手动最短 5 秒，每次实际读取重新获取当前 CLI 账户，单次超过 15 秒提示超时或暂时无法更新。读取失败清除当前余额，不拿上一账号或历史日志回填。换号后需等下一次实际刷新；网络或失败会延长更新，不保证瞬间发现外部登录变化。实际 A→B 换号尚未专门验收。

设置中的“历史日志额度（不代表当前账号）”单独展示日志记录，不代表现在登录的账户。历史记录、来源、观察和重置时间都保留标注；不需要提供或复制 token。

刘海状态条右侧的百分比也表示剩余，按实际周期排序，最多两行；没有记录时显示“额度暂无数据”。超过五分钟的记录有历史提示，已过重置时间的周期显示“待更新”，不会把旧比例当作重置后的余额。收起状态条的悬停说明保留来源、更新时间和重置时间。

“暂停任务刷新”阻止新的自动任务扫描，停止文件监听和待发快速刷新，不会暂停 Codex 任务，也不会暂停独立的账户额度刷新；已经发出的读取可以完成。立即刷新可手动获取最新落盘数据和账户额度。设置文件与演示设置分别保存在应用自己的 Application Support 目录。“备份并恢复默认设置”会先保存一份备份。

没有任务时先检查数据目录；较久没有活动会显示未知。额度不可用时检查所选 Codex 目录、Codex 登录状态和网络，也可直接打开官方用量网页；本工具不要求填写或复制 token。额度没有记录时显示不可用，不填演示百分比。开机启动需在实际应用中设置，演示包禁用；系统权限提示需要在 Mac 上处理。

等待提示依据明确的提问或确认事件，普通助手问句不会被猜成待处理。大量输出造成积压时，任务暂时显示“正在同步任务活动…”，仍留在原列表；追平后恢复可识别状态，普通工具输出不会再清掉已建立的等待。首次启动或记录被替换后的状态读取仍只取有限尾部；针对关注任务的开始时间回查只补时间，不用历史回放覆盖当前状态。因此较早的未答问题仍可能不在状态读取范围，不能保证全部恢复；未落盘的活动也无法直接读取。

如果开启“登录 Mac 时启动”后显示“等待系统允许”，点击“打开系统登录项设置”并在系统中允许；返回应用后会重新读取结果。等待允许不代表已经生效。

当前本地构建包只有 ad-hoc 签名，未提供公证发布版。若下载后的应用被系统阻止，请先核实来源，再按 [Apple 的打开应用说明](https://support.apple.com/zh-cn/102445) 处理。不要为此关闭系统全局保护。
