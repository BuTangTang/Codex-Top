# REQ-001 详细设计

## 模块

```text
只读 SQLite 元数据 + rollout JSONL
             ↓
LocalCodexSource（actor，缓存增量读取）
             ↓
TaskStore（主线程，可观察的应用状态）
       ↙     ↓      ↘
顶部状态条  展开列表  悬浮列表
             ↑
任务选择器 / 监控规则 / 本地设置
```

- `CodexTopCore`：任务模型、状态归约、选择与自动加入策略、只读数据适配、独立设置文件。
- `AccountUsageClient`：独立 Foundation actor，通过所选 Codex 目录的官方 CLI stdio 协议读取账户额度，再交给 TaskStore；不参与任务扫描或窗口控制。
- `CodexTop`：SwiftUI 内容、AppKit 窗口控制和系统菜单。
- `codex-top-inspect`：只读诊断入口；默认只输出数量和耗时，不输出对话正文。
- 使用系统 SQLite，不引入第三方运行依赖；SwiftPM 构建后脚本封装 `.app`。

## 数据来源

按 `CODEX_HOME` 或用户选择目录定位 `state_*.sqlite`，只读打开并检查必要列。任务标题只读取短标题字段，忽略 `first_user_message`、`preview` 和认证文件。归档任务不进入选择器。父子关系来自 spawn edges 或 source 中的父 ID。

首次对 rollout 读取有界尾部，之后通过文件大小、修改时间和文件标识检测变化，只追加解析新增完整行；轮转/截断后重建状态。长行、半行、损坏 JSON 不使应用崩溃。所有日志路径规范化后必须位于所选 Codex 根目录内。刷新采用后台 actor 每 2 秒一次，避免额外文件监控权限；无变更日志不重读，暂停后停止扫描。所有权与读取故障统一作为 source health 显示。

事件处理优先识别明确生命周期：`task_started`、`task_complete`、`turn_aborted` 和错误/等待事件。读取有界尾部未包含开始事件时，可依据近期工具/助手活动显示活动状态，但必须标明它是日志观察结果。15 分钟没有新活动的运行任务显示未知；同步提问的工具结果按调用 ID 匹配，明确输入或本轮结束也可更新状态；异步提问的工具返回和本轮完成不自动消除待回答状态。恢复、继续同一任务按 ID 更新，不新建重复行。

完成、取消和失败共 7 种终止事件统一检查 `turn_id`：当当前轮次和事件轮次都有 ID 且不一致时，忽略该事件，也不推进活动时间。缺少轮次 ID 的旧记录保留兼容解析，不据此宣称已辨明轮次。

明确失败后保持错误状态，普通助手说明、reasoning、工具调用/返回、尾随完成事件均不能把它改回运行或完成；仍可更新独立额度信息。只有明确开始新轮次或用户继续输入/批准才恢复运行，并重设本轮计时。错误状态是否保持与是否归入完成折叠区分别处理，不通过把失败算作完成来规避错误提醒。

### 账户额度与跳转（D-30）

`AccountUsageClient(root:)` 将所选目录仅传给子进程的 `CODEX_HOME`，使用官方 Codex CLI 的 `app-server --stdio`。协议顺序为 `initialize`、收到响应后 `initialized`、`account/rateLimits/read`；不发起线程、MCP、登录、额度重置或购买请求。本工具不直接读取认证文件，登录状态由官方 CLI 管理。协议依据为 [Codex App Server](https://learn.chatgpt.com/docs/app-server)。

账户请求与任务的 2 秒扫描分开：自动最短 60 秒，手动最短 5 秒，失败同样限频；并发请求共用一次连接，单次超时 15 秒。标准错误不缓存，标准输出有界解析，错误统一为安全提示；取消或超时后关闭输入、终止并回收本次拥有的子进程。只保留窗口分钟数、已用百分比、重置时间和本次观察时间，不保留原始响应、账户标识或凭据。

有 `rateLimitsByLimitId` 时以其中 `codex` 为准，缺失该桶不改用其他模型额度；仅缺少多桶视图时兼容 `rateLimits`。缺失、无效或空窗口不当成零用量；返回非 5 小时/周的窗口时保留实际时长。`QuotaSnapshot.origin` 区分 `.account` 与兼容日志的 `.log`。

TaskStore 为账户和日志分别保留快照，以观察时间选择较新记录；界面注明来源、更新时间与重置时间。账户刷新失败保留旧记录并提示无法更新，超过 5 分钟或已过重置时间标记历史/待更新，不把过期百分比当作重置后余额。切换目录时增加代次、取消请求、清除两份缓存并新建客户端，旧目录回调不能回写。暂停阻止新的自动请求，已发出的请求可完成，手动刷新仍可使用。

点击任务通过经过 UUID 校验的 `codex://threads/<id>`，明确交给 Codex 应用打开；失败提示并复制该任务 ID。点击额度打开官方 [Codex 用量网页](https://chatgpt.com/codex/settings/usage)，不猜测应用内的未支持设置 deep link。客户端只读账户请求已成功，合成测试覆盖限频、超时、取消和回收；这些证据不替代真实任务跳转终点与打包界面点击验收。

`Codex Top.app` 用于真实任务与额度，`Codex Top Demo.app` 以单独 bundle 标记和独立偏好保存合成示例。Demo 不启动账户刷新，不把示例 ID 或选择迁移成真实关注集合。切换实际使用时需退出 Demo，避免两个独立应用同时显示圆环。用户反馈当前不再闪烁、使用正常，仅记录该观察，不据此关闭所有动画与物理屏幕验收项。

## 监控集合

持久化关注 ID、手动排除 ID、初始化标记、自动加入起点与启用时已知 ID 基线 `autoBaselineIDs`。首次成功快照只加入活动/等待主任务，并记录该快照已有的全部 ID；重新开启自动监控时重设起点和基线，不清空原有关注集合。关闭自动监控后不再自动加入。

SQLite 的创建时间按整秒记录，而启用时间包含小数秒。自动筛选把创建时间边界对齐到启用秒，同时排除基线已有 ID，再要求任务已有开始或活动/结束证据；因此启用同秒新出现的任务不会因时间精度差漏加，已知旧任务不会因扩大到整秒而涌入。手动排除仍优先于自动规则，子任务的纳入映射到主任务 ID。

`autoBaselineIDs` 为可选字段，旧偏好缺失它时可以继续读取。首次迁移把当前快照中创建时间早于精确起点的 ID 记入保守基线，避免把无法判定先后的同秒历史补进来；明确晚于起点的任务仍允许补加。整秒时间无法证明同秒、从未观察过的任务究竟在开启前还是开启后创建，这类未知 ID 按新出现处理；基线不能替代数据库缺失的更细时间信息。

任务选择器使用草稿，确认时只应用用户相对打开时的差异，避免覆盖打开期间自动加入的新任务。

任务行排序：待处理/错误、运行、未知/未运行，最近完成进入可折叠区域。子任务折叠到主任务，其明确活动/待处理可以提升主任务的可见优先级。

## 窗口与显示模式

AppKit `NSPanel` 承载 SwiftUI。`PanelPlacement` 只有一个当前值，模式切换不改变关注集合：

| 模式 | 常驻内容 | 查看完整任务 |
|---|---|---|
| 顶部 | 刘海左右状态，普通屏回退顶部胶囊 | 悬停或点击 |
| 常驻浮窗 | 紧凑单行列表，保留顶部总数 | 浮窗直接操作 |
| 圆环 | 44×44pt 小圆环，拖动始终留在桌面 | 左键原位展开；右键菜单；悬停仅微动，移开保持，点击面板外缩回 |
| 仅状态栏 | 透明背景的系统 `NSStatusItem` 运行/待处理计数 | 左键显示/收回任务，右键菜单 |

顶部收起与展开使用同一个窗口、同一个连续外壳。物理摄像头区域保留纯黑空白；展开宽度下限包含摄像头安全区，不能随着 80% 缩放挡住摄像头。状态栏展开复用任务视图，在系统状态按钮锚点下方放置，但使用独立的完整尺寸弹层，不复用顶部收起外壳。圆环使用承载它的同一个浮动窗口原位变为面板，展开矩形围绕圆环中心计算并约束在可见区；原始 44pt 锚点保留，关闭后回到该位置。展开时圆环隐藏，不额外显示第二个窗口或残留圆圈。

浮窗等级为 `.floating`，切到其他应用后继续显示。悬停不抢键盘焦点，明确点击显示任务后才允许面板接收键盘；收起释放焦点。选择器与设置是独立键盘窗口。菜单始终提供找回、模式、设置与退出入口；应用激活时 `⌘T` 显示任务、`⌘,` 打开设置。

完成区折叠状态由 `MonitorPanelState` 持有，视图通过 Binding 读取和修改，窗口高度使用同一份状态，防止切换模式后内容已折叠而窗口仍留空。任务列表使用单个稳定任务 ID 序列；每行直接观察当前 TaskStore 并按 ID 读取图标、详情和计时，避免任务从活动区移到已结束区时保留旧行快照。

### 尺寸、配色与圆环

- `Appearance.swift` 统一逻辑点尺寸。100% 时展开宽 410pt、两行任务高 54pt；浮窗宽 360pt、单行任务高 42pt。最多 4 行，其余滚动，已结束入口固定。
- 80%/90%/100% 同步缩放窗口、内容和选择器。80% 的浮窗宽 288pt，展开宽 328pt；圆环保持 44pt，避免缩小后难以点击。物理刘海安全区域独立于比例。
- 按 Atoll 参考调整为纯黑深色背景、系统字体、白色正文与中性灰辅助文字。D-26 将标题调整为 rounded semibold 17pt、任务 medium 16pt、辅助说明和标签 14pt，计时/右侧状态/页脚 13pt；选择器搜索 16pt、筛选/状态 14pt、全选/底部 15pt。窗口逻辑尺寸与缩放比例不变，圆环数字和系统状态栏字号不变。浅色保留公开 `NSVisualEffectView` 磨砂材质与细边框，不降低整个窗口的 alpha。
- D-29：浅色背景和主题过渡中的原生玻璃统一由 `GlassMaterial.makeBackdrop` 创建，使用 `.hudWindow`、`.behindWindow`、`.active` 和固定 `.aqua`。材质视图 alpha 从 0.72 改为 1，避免将未模糊的后方文字重新混入；另用独立白色渐变调节色调。前景文字与控件不使用 blur。源码配置不等于实际背景模糊已通过，需在文字密集背景上检查浅色选择器和面板。
- 一键主题切换采用 D-23 的点击位置圆形揭开，替代此前整块面板 0.26s 交叉淡变。点击所在面板保存当前可见内容的原生快照作临时覆盖层，底层内容直接采用目标主题；从点击点扩大圆孔遮罩，同时揭开新底色、文字、图标与控件。当前设计时长约 0.42s，不增加装饰圆波；减少动态效果时回落 0.10s 短淡变，取消空间扩散与图标旋转缩放。其他窗口同步目标主题，不在各窗口虚构相同点击点。圆环同步使用当前主题，顶部收起胶囊与物理摄像头区域保持黑色；不复制整份可交互任务列表，关注集合、窗口大小和位置不因主题切换改变。
- 圆环仅保留 1.8pt 单条状态细线，不绘制底层轨道、中心圆点和外层阴影。运行蓝色弧线转动；等待回答显示琥珀，失败红色且优先提示，需要处理时由整个收起圆球缩放呼吸，状态内环不再叠加明暗呼吸；全部完成才保持绿色。未知/未运行为灰色，不把部分完成持久标为全部完成。
- 演示任务和额度明确分开；演示包不读取本机任务，也不伪造剩余额度。

### 动画与拖动

主题揭开的原点由实际鼠标事件转换到所属窗口坐标，圆孔半径增长到能覆盖该面板的最远角。快照覆盖层只参与绘制，不拦截点击，也不保存为文件。原生视图快照不包含 WindowServer 的背景模糊，因此正常浅色过渡保留独立的原生玻璃层。快速再次切换时合成当前内容与进行中的遮罩，再替换旧过渡；被打断的浅色玻璃使用近似浅色合成，不能声称与当时背景逐像素相同。动画结束移除覆盖层，模式、窗口尺寸或 backing scale 改变时取消旧覆盖层，重新定位路径同样清理旧坐标。源码时长与遮罩结构不等于已验证中间帧和真实帧率，需在打包窗口核对点击原点、往返和中断效果。

`HoverHostingView` 使用 AppKit `.activeAlways` tracking area。只有顶部模式进入后等待 80ms 展开，离开等待 180ms 收起，进入展开面板取消收起；仅状态栏模式不注册这两种延时动作。圆环悬停仅在 0.14s 内轻微放大，不安排延时展开；点击才启动原位变形。圆环展开面板与常驻列表均不因鼠标离开而收起；圆环面板由外部点击、按钮、Escape 或显式切换显示模式关闭。

圆环展开期间注册本地和全局 `mouseDown` 监听，用于判断点击是否位于面板外；收起或离开圆环模式后移除监听。外部点击触发同窗口 0.22s 反向变形，本地监听返回原事件，鼠标事件仍正常投递其命中的窗口，不阻止其他应用接收原操作。变形期间扩展画布的透明区域仍属于本应用窗口，不做额外事件转发，也不声称能点击穿透到其后方应用。常驻浮窗不使用这套外部点击收起规则。

顶部模式外壳由 SwiftUI `.smooth` 驱动，展开 0.24 秒、收起 0.20 秒；内容使用短延迟的缩放与淡入。AppKit 在开始时准备容纳过渡的窗口画布，结束时收紧边界，取消此前每 16ms 改整个窗口 frame 的循环。进行中的动画可取消并重定目标；遵循系统“减少动态效果”。状态栏使用下述 D-31 独立弹层过渡。源码时长和结构不能证明真实帧率，实际顺滑度仍需实机观察。

圆环本体变形由 `OrbMorphState` 记录可见表面 frame 和展开内容尺寸。过渡前把同一 NSPanel 画布扩到两端的并集，SwiftUI 连续改变表面尺寸和位置；展开 0.26s、收起 0.22s，完成后收紧窗口边界。圆环形态半径 22pt，展开后成为圆角面板；内容淡入时细环淡出。收起按钮或 Escape 可反向收回；收回后继续悬停只产生微动反馈，不会重新展开。

D-27 将展开目标通过 `WindowGeometry.pixelAligned` 按当前屏幕 backing scale 对齐。同一目标的窗口坐标与宽高允许 1 个物理像素误差，避免已经到达目标后被定期刷新重新触发变形；目标确实改变时仍更新。`expandedSize` 与 `surfaceFrame` 使用相同的 `.smooth` 曲线和展开/收起时长，提示出现时内容和外壳同步变化。几何回归覆盖 1×/2× 屏幕及缩放后的提示端点。旧版本没有记录运行时 frame 差值，像素误差是源码分析找到的候选原因，不能写成已抓到闪空根因。

屏幕重排/模式切换取消变形时，同步恢复局部绘制坐标、44pt 窗口、动画目标和键盘焦点，避免窗口收小后图形还偏移在旧画布中。打开设置/任务选择器先取消待执行的顶部悬停；延时到期时再次检查模式、拖动及对话框可见性。圆环没有悬停展开/离开收起计时器。

只有运行外环使用 SwiftUI TimelineView 持续刷新；面板展开后暂停不可见圆环的旋转。待回答/失败不再用 TimelineView 改透明度，而是由 OrbPanelView 在外壳裁切与边缘绘制后、位置布局前应用整体 `scaleEffect`：仅 `attentionCount > 0 && !expanded && !reduceMotion` 时在 1.00 与 0.94 间往返，每半程为 0.9s ease-in-out，约 1.8s 一轮。底板、状态环、中心数字一起缩放，原生 44pt 窗口和锚点不逐帧变化。

整体呼吸使用 `.task(id: shouldBreathe)` 循环有限动画和可取消等待，不用 `repeatForever`。条件变为 false 时取消旧循环并恢复比例 1；展开和减少动态效果还会强制使用比例 1，避免隐藏动画残留。处理完成后用短 0.18s 恢复稳定，不改变中心数字含义。

完成使用一次 0.45s 的绿色合拢。已关注任务由非完成变为完成时记录一次完成事件；如果还有其他任务运行且无待处理，短暂绿色反馈后恢复运行蓝弧。初次载入历史完成项不产生新的完成事件；减少动态效果时停止重复旋转、整体呼吸和短暂反馈。

演示包设置中可切换运行/待回答/完成/出错及恢复原始示例；预览状态不持久化，不影响实际应用或 Codex。

常驻浮窗和展开圆环的整个标题栏提供拖动命中层，通过按钮实际布局锚点在命中形状中扣除按钮区域；标题、数字、空白和留白均可拖。手势 minimumDistance=0 并传入首次位移，不设长按等待。圆环本体继续整体可拖。使用当前鼠标事件转换为屏幕坐标，避免全局指针的异步读取造成距离不一致。所有拖放只约束到工作区并保存新位置，不再计算吸附目标或切换显示模式；“仅状态栏”通过菜单显式进入。展开面板拖动保持展开，同步平移圆环锚点和展开目标；收起使用移动后的锚点。系统状态栏项目排布仍由 macOS 管理。

### 外接屏策略

- 自动模式使用 `CGMainDisplayID` 对应的系统主显示器，不随鼠标偶然移到另一屏而跳动；用户可通过设置固定显示器。
- 以显示器 UUID 保存固定选择，不依赖名称、连接顺序或分辨率；目标断开时回退系统主屏，目标重新连接后恢复选择。
- 刘海屏使用顶部安全区域定位左右状态区；无刘海屏在 `visibleFrame` 顶部下方留出 8pt 间距，避开系统菜单。
- 所有窗口计算使用逻辑点和屏幕全局坐标，允许外接屏在左侧/上方产生负坐标。
- 浮窗拖动结束保存显示器 UUID 与相对可见区的位置；拔插、缩放或合盖后将窗口约束到当前可用区域。
- 设置/选择器完整位于任一可见屏幕时保留位置；部分越界时优先约束到相交面积最大的可用屏幕，完全无相交才回退选定屏。明确点击“找回窗口”时统一移回选定屏，不能以仍有一角相交视为已恢复。
- 只显示一套顶部状态与一份浮窗，所有屏幕使用同一关注集合。菜单中的“找回窗口”重新定位到选定/主显示器。

### 圆度与中心数量（D-21）

收起底板使用 44×44pt、22pt 半径的 circular 圆角路径，避免 continuous 方圆角轮廓；展开仍沿同一形状插值。原位锚点在恢复、布局和拖动结束时按所在屏幕 backingScaleFactor 对齐，保持原生窗口 44pt 正方形；需要处理时的可见内容按 D-28 整体轻微缩放。中心运行数量不参与状态环旋转，但随整个圆球呼吸缩放；等宽数字更新过渡 0.18s，超过 99 显示 99+，全部完成且无运行时改为对勾。继续使用 MonitorStatusSummary 的失败 > 等待 > 运行优先级，不把待处理数混入中心数字。

### 状态栏左右键（D-22）

NSStatusItem 的按钮接收左/右 mouseUp；左键复用现有任务展开入口及状态栏锚点，右键或 Control + 左键展示原生菜单。菜单不常驻绑定到 statusItem，避免 macOS 将左键直接截获为弹菜单。普通浮窗模式继续沿既有显示任务入口激活常驻面板。

### 状态栏完整弹层与比例（D-31）

锚点由状态按钮的 `bounds` 先转到窗口坐标，再转成屏幕坐标，不直接采用整个状态栏宿主窗口 frame。`updateContentSize` 根据该锚点所属屏幕计算完整面板并约束至可见区，按 backing scale 对齐物理像素；关闭态不再生成 44×22pt 黑色表面，系统状态项本身就是收起后的入口。

`TopPanelView.statusPopover` 独立复用 `MonitorView`，按显示比例布局逻辑内容，再同步得到最终窗口宽高；80%/90%/100% 时正常展开宽为 328/369/410pt。开合期间窗口保持完整尺寸，仅内容以顶部为锚点从 0.96 缩放至 1 并改变 opacity，打开 0.20s、关闭 0.16s，均为 ease-in-out。减少动态效果时直接采用端点，不执行空间缩放。

`animateStatusPopover` 在关闭结束后 `orderOut`，非动画和已关闭的早返回路径也保证隐藏。重开、改变目标或切模式时取消旧 `topMotion`，延时完成后再次检查取消状态及模式，防止旧关闭任务隐藏新展开窗口。仅状态栏不进入顶部 hover 的 80/180ms 计时器；左键再次点击收回，右键保持原菜单。真实顶部外壳与圆环原位变形分支保持独立。

D-31 最终包已通过 48 项测试及 universal 构建。D-32 复测补充了仅状态栏 80% 完整面板截图与成功导航后隐藏；状态栏图标实际左右键、快速开合及其余比例仍未验证。以上端点不代表动画中间帧已通过。

### 任务打开回调的线程边界（D-32）

NSWorkspace 的打开结果可能由 LaunchServices 后台队列回调。Swift 6 下，在 MainActor 类型中创建未标 Sendable 的 Objective-C completion，可能在进入闭包时先执行主 actor 断言，内部再创建 MainActor Task 已经太晚。该 completion 显式标记 `@Sendable`；所有任务状态更新和关闭面板仍在内部 MainActor Task 中执行。只确认系统调用成功，不据此宣称目标对话已经读取完成。实际崩溃栈、后台复现和最终包点击复测见额度与跳转验收记录。

### 圆环右键与状态栏外观（D-24/D-25）

桌面圆环右键复用与状态栏相同的菜单内容和动作，包含选择任务、显示方式、设置、找回与退出。菜单中的“仅状态栏”是圆环进入状态栏的显式入口，圆环与常驻浮窗拖动均不会改变显示模式（D-48）。

系统 `NSStatusItem` 移除自绘黑色背景和胶囊轮廓，保留原生透明按钮与彩色状态点。数字使用系统菜单栏对应的语义文字颜色，随系统明暗外观更新，不使用桌面 `PanelTheme` 固定的黑/白端点。此处仅改变系统状态栏；刘海摄像头区域与普通屏顶部模式胶囊的黑底继续保留。

### 刘海摘要、实时锚点与圆环提醒（D-33–D-36）

后续 D-37 外观反馈：保持物理安全区宽高不变，将刘海两翼由各 98pt 收至 88pt；摄像头遮罩底角改为 9pt 连续圆角，避免软件额外画出方形黑块。收起浅色玻璃额外覆 30% 白色调色层，仍保留完整背景模糊；展开时该调色层退去，沿用已确认的面板玻璃。收起边线透明度从 0.65 降至 0.14，外侧底角从 14pt 改为 12pt，摘要 13pt 使用 regular 字重，状态点 5pt。不能通过缩小真实摄像头保留区来美化轮廓。

D-38：圆环拖放结束不主动恢复 hovered；若指针仍在球内，抑制悬停直到真实移出后再次进入。拖动造成的窗口 tracking exit 不解除抑制。专用 OrbDragHandle 传入第一次 onChanged 的 translation，以 AppKit 坐标重建鼠标按下点；松手同时检查累计越界标记、指针总位移与窗口位移，至少 4pt 视为拖动。普通浮窗继续调用原手柄，圆环仍不参与吸附。

D-39 替代 D-37 的逐状态调色：刘海整块表面在收起和展开都采用相同的 24% 白色调色层，边线统一为 0.20 透明度、0.5pt，不再随着 progress 从浅白变灰或突然增强白边。额度摘要明确采用主文字颜色和 14pt medium，覆盖 footer 继承的 13pt 次要灰色。刘海宽度改为收起/展开共用的几何结果，内容仍按实际展开宽度除以显示比例布局，避免二次缩放；摄像头保留区保持逻辑点尺寸。

状态栏按钮创建后安装弱捕获的 `statusAnchorProvider`。每次菜单栏布局都从按钮 bounds 转换到当前屏幕坐标；不保存上一次点击的绝对 frame。`WindowGeometry.statusPanelAnchor` 检查有限值、非零尺寸及当前屏幕范围，provider 尚未安装、暂时缺失或返回已断开屏幕坐标时，回退选定屏幕上沿中心。合成 provider 测试覆盖重排后重读、暂时缺失和恢复，不能替代实际屏幕通知链。

“顶部”只是界面命名改为“刘海模式”，`PanelPlacement.top` 保持不变，旧设置无需迁移。外壳统一用 `GlassFill`；移除收起态强制黑层，将摄像头黑块限于真实 cameraWidth/cameraHeight。两翼按主题使用可读前景色。纯模型 `CompactMonitorSummary` 将待处理置于暂停和运行之前，右侧至多两行真实额度，按周期排序；旧数据有时钟，重置点已过显示待更新。额度含义统一为剩余，完整来源与更新时间留在悬停提示和展开面板中。

运行弧交给 `NativeRunningArc` 的 CAShapeLayer，以固定动画 key 保持 1.2 秒线性一圈，SwiftUI 数据刷新只更新输入。只有进入/退出可见运行状态才开始/停止，停止时保留 presentation 角度，恢复从该角度续转；视图拆除停止动画。跨 backing scale 更新 layer.contentsScale。其他任务状态、完成反馈和中心计数保留原有语义。

圆环原位变形仍为展开 0.26 秒、收回 0.22 秒；使用 SwiftUI `.removed` completion 在实际动画移除后裁剪原生画布。generation、模式和目标检查使旧 completion 失效，替代固定延时的窗口裁剪。待处理的低透明度底色和 11pt“!”都位于同一 44pt 球体内，失败用红色；不增加窗口、不自动展开。动态效果减少时只保留静态提醒。上述改动需要最终包实测，不能声明已达到特定帧率或已匹配所有概念图细节。

### 展开初段与任务行补全（D-41/D-42）

任务行的 `ActivityIndicator.running` 原来只画固定 -70° 的截断圆，未接任何动画；D-35 只覆盖桌面圆环。现在任务行也复用 `NativeRunningArc`，保留 22/24pt 布局、3pt 线宽、25% 淡轨道与原起角。弧画布每侧扩 1.5pt 并同量内缩，避免描边裁切而不改变半径。可见且未启用减少动态效果时旋转；图层 key 保持唯一，拆除或隐藏停止。桌面球默认 1.8pt 线宽、7pt 内缩保持不变。

圆环换画布用 `commitOrbCanvas`：在同一 `NSAnimationContext` 中设置无动画的局部坐标、调整窗口但不立即 display，先完成 hosting view layout，再交给 AppKit 延后显示，避免先画新窗口再更新旧坐标的路径。列表按最终尺寸布局，外层 surface 单独变形，内层额外缩放从 0.72 收敛至 0.96；仍保留淡入和原 0.26/0.22 秒外壳动画。此为针对抖动反馈的改进，不以代码审查代替中间帧/FPS 验收。

`PanelFonts.readable` 在布局字号和 `minimum / uiScale` 中取较大值，避免 80% 时任务名降至 12.8pt、说明降至 11.2pt。主标题/任务名/辅助文字分别设有效 15/14/12pt 下限；辅助色暗主题由白度 0.65 提至 0.76，浅主题由 0.40 降至 0.34。额度使用主文字色和 medium 字重。窗口宽度、行高、图标尺寸不随此修订增大。

透明菜单栏 D-40 仅为讨论方案，未实施；软件摄像头遮罩保留 D-37 的 9pt 底角，物理摄像头安全区不变。

## D-43/D-44 数据隔离与展开高度

TaskStore 的当前 quota 只采用 accountQuota，historicalQuota 独立发布给设置。账户循环不受 paused 影响，失败清空 accountQuota；stopping、sourceGeneration 和 requestID 阻止旧响应回写。ownedUsageRequests 跟踪仍在清理的请求；applicationShouldTerminate 返回 terminateLater，await shutdown 后再回复退出，底层请求执行有界终止与进程回收。

WindowController 保存本次展开 frame、方向和原始 orbAnchor，之后根据展开方向保持靠球边缘：普通向下保持 maxY，回退向上保持 minY，视口超出工作区时限制高度并滚动。D-44 首轮候选使用展开结束后顶对齐，D-45 将其覆盖为首帧就按方向对齐。隐藏面板显式关闭任务行运行弧动画。任务列表已删除延迟 50ms 滚到首个完成任务的 scrollTo，插入从 move(.top) 改为 opacity，避免运行行自动离开视口。

## D-45 从圆环位置向边缘展开（已确认，实施中）

首次开合保存 44pt 的原圆环 frame 与屏幕可见区。默认展开面板的 `top = orb.maxY`（AppKit 向上为正，top 即 maxY），让标题靠近原点击位置；水平方向以原位置为起点计算后 clamp 到可见工作区内侧。比较上下可用高度：只有目标高度无法向下容纳、且上方空间比下方更多时，才选择向上，保持靠球的 bottom；其余情况保留向下并约束高度。无论哪一侧空间不足，都缩短视口并允许内容滚动，不把窗口放到屏幕外。

方向在一次展开时确定，持续到对应收回；增加任务、展开/收起已结束区不重新比较方向。向下时后续高度变化保持 top，向上时保持靠球 bottom，避免用户正在点击的区域随列表变化跳到另一侧。收回回到保存的 orbAnchor，球在展开期间完全隐藏，不残留第二个球；重新打开时才按当时空间重新选方向。

首开先准备最终内容布局和容纳过渡的 canvas，再在同一个 withAnimation 事务中提交 expanded 与 surfaceFrame。内容从首帧即按选定方向顶/底对齐；保留用户 uiScale，只对正文淡入，不再叠加 D-42 的 0.96→1 中心缩放。外壳沿靠球一侧连续揭开，完成时仅做经过代次/目标检查的画布收整，不在 completion 才切换正文对齐。

本节覆盖前文“展开矩形围绕圆环中心计算”“完成后启用顶对齐”和圆环正文额外缩放的旧方式，状态栏独立弹层的过渡不因此改变。方向与边界几何回归需覆盖左右边、向下足够、底部不足但上方更多、两侧均不足、已结束区增减不换方向、回到原锚点；真实连续动画和首次抖动仍需最终包验证。首轮 66 项测试及 universal 只对应 D-43/D-44 候选，不代表本节新增方向已经构建或验收。

## D-46 长会话增量与提醒可靠性

只读核对目标仍关注且未归档；空白列表与旧强制scrollTo一致，另发现IncrementalRollout在追加超过64KB时跳尾并重置Reducer，会丢失等待和turnID。修订为首次/真实文件重置才有界尾读，后续从offset按64KB分块顺序追赶、每轮总预算4MB；保留分段行与归约状态，不回读整段历史。未追平当前文件大小快照时任务行显示未知/正在同步活动，内部等待继续保留，到追平后再公布归约状态。提问和回复以真实结构化事件为准，不以普通助手问句判断。

## D-47 统一动画进度

WindowController 统一使用开 0.32/关 0.28 response、damping 1、blend 0 的 spring，保留真实 removed completion。OrbRevealOpacity 为值类型 AnimatableModifier，animatableData 为 nonisolated 可插值 Double；通过 smoothstep 计算正文与圆环透明度，跟随同一父动画事务，无 70ms 独立等待。高度刷新在 orbMotion 存在时仅标 pending，完成后读取最新高度，避免用模型终点重新定位尚未完成的画布。显式开关可直接反向。

## D-48 标题栏自由拖动

D-48 覆盖先前左侧手柄和常驻浮窗吸附设计。非按钮拖动层按 GeometryReader 解析按钮边界，并使用偶奇填充扣除这些矩形，避免透明拖动层吞掉选择任务、图钉、收起及主题按钮。刘海与系统状态栏弹层继续使用其固定锚点；可自由移动的是桌面浮窗和圆环展开面板。
