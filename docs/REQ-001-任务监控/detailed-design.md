# REQ-001 详细设计

## 模块

```text
只读 SQLite 元数据 + rollout JSONL
             ↓
LocalCodexSource（actor，缓存增量读取）
             ↓
TaskStore（主线程，可观察的应用状态）
       ↙     ↓      ↘
顶部状态条  展开列表  悬浮列表
             ↑
任务选择器 / 监控规则 / 本地设置
```

- `CodexTopCore`：任务模型、状态归约、选择与自动加入策略、只读数据适配、独立设置文件。
- `CodexTop`：SwiftUI 内容、AppKit 窗口控制和系统菜单。
- `codex-top-inspect`：只读诊断入口；默认只输出数量和耗时，不输出对话正文。
- 使用系统 SQLite，不引入第三方运行依赖；SwiftPM 构建后脚本封装 `.app`。

## 数据来源

按 `CODEX_HOME` 或用户选择目录定位 `state_*.sqlite`，只读打开并检查必要列。任务标题只读取短标题字段，忽略 `first_user_message`、`preview` 和认证文件。归档任务不进入选择器。父子关系来自 spawn edges 或 source 中的父 ID。

首次对 rollout 读取有界尾部，之后通过文件大小、修改时间和文件标识检测变化，只追加解析新增完整行；轮转/截断后重建状态。长行、半行、损坏 JSON 不使应用崩溃。所有日志路径规范化后必须位于所选 Codex 根目录内。刷新采用后台 actor 每 2 秒一次，避免额外文件监控权限；无变更日志不重读，暂停后停止扫描。所有权与读取故障统一作为 source health 显示。

事件处理优先识别明确生命周期：`task_started`、`task_complete`、`turn_aborted` 和错误/等待事件。读取有界尾部未包含开始事件时，可依据近期工具/助手活动显示活动状态，但必须标明它是日志观察结果。15 分钟没有新活动的未结束任务显示未知；等待事件保留待处理状态，直到回复、结果或结束事件。恢复、继续同一任务按 ID 更新，不新建重复行。

## 监控集合

持久化关注 ID、手动排除 ID、初始化标记与自动加入起点。首次成功快照加入活动/等待主任务，随后自动加入起点之后创建且已开始的任务；已有历史不会因启动时扫描而全部涌入。用户取消关注优先于自动规则。任务选择器使用草稿，确认时只应用用户相对打开时的差异，避免覆盖打开期间自动加入的新任务。

任务行排序：待处理/错误、运行、未知/未运行，最近完成进入可折叠区域。子任务折叠到主任务，其明确活动/待处理可以提升主任务的可见优先级。

## 窗口

AppKit `NSPanel` 承载 SwiftUI。顶部窗口只占实际条带空间，展开窗口位于条带下方。通过 `NSScreen.safeAreaInsets` 与辅助顶部区域识别刘海，物理摄像头区域保持空白；无刘海屏幕使用紧凑胶囊。屏幕参数改变后重新定位并约束在可用范围内。

浮窗为 `.floating` 等级、`hidesOnDeactivate=false`、可拖动，不抢走常规键盘焦点；选择器/设置可以成为键盘窗口。收起和关闭仅隐藏相应面板。菜单栏保留入口用于找回窗口、设置和退出。

### 外接屏策略

- 自动模式使用 `CGMainDisplayID` 对应的系统主显示器，不随鼠标偶然移到另一屏而跳动；用户可通过设置固定显示器。
- 以显示器 UUID 保存固定选择，不依赖名称、连接顺序或分辨率；目标断开时回退系统主屏，目标重新连接后恢复选择。
- 刘海屏使用顶部安全区域定位左右状态区；无刘海屏在 `visibleFrame` 顶部下方留出 8pt 间距，避开系统菜单。
- 所有窗口计算使用逻辑点和屏幕全局坐标，允许外接屏在左侧/上方产生负坐标。
- 浮窗拖动结束保存显示器 UUID 与相对可见区的位置；拔插、缩放或合盖后将窗口约束到当前可用区域。
- 只显示一套顶部状态与一份浮窗，所有屏幕使用同一关注集合。菜单中的“找回窗口”重新定位到选定/主显示器。

## 本地保存与开放边界

设置在用户 Application Support/Codex Top 中原子写入 JSON，损坏时提示并使用安全默认值，不自动覆盖损坏文件。演示与测试使用独立状态目录。任务正文、密码、cookie、token 不进入设置或公开日志。提供 `codex://threads/<id>` 跳转；第一版不实现任务命令执行、代替用户批准或修改 Codex 设置。
