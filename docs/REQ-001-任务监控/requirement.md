# REQ-001 任务监控

## 目标

用户不用持续切回 Codex，就能看到关注任务的活动、待处理事项与最近完成情况；支持在刘海附近展开和悬浮置顶。第一版交付可构建、可运行的原生 macOS 应用、测试、使用说明和真实验收记录。

## 已确认决策

- D-01：重建紧凑界面。保留刘海总览和紧凑浮窗，避免单任务大卡片。
- D-02：所有显示模式共用一份监控列表，图钉仅放在顶部，不再按任务分别钉住。
- D-03：历史任务支持搜索、多选、全选当前筛选结果；新建并开始运行的任务默认自动加入。
- D-04：首次启动纳入正在活动和明确待处理的任务；子任务归入主任务；完成任务可折叠。
- D-05：使用 Swift、SwiftUI、AppKit；Codex 数据只读，工具自己的设置独立保存。
- D-06：项目开源在 BuTangTang/Codex-Top，用户已选 GPL v3；实现和文档同步，阶段性提交并 push。
- D-07：任务创建和回答、批准操作仍在 Codex 中完成；监控界面提供返回对应任务的入口。
- D-08：用户会外接屏幕。多显示器、合盖/断开后的恢复是正式功能；关键决定与已做/待做工作持续写入项目状态文档。
- D-09：以 `docs/design/main.png` 和 `picker.png` 为视觉基准，不能只改颜色便认为完成。中文工具栏、磨砂蓝灰材质、蓝色运行环、琥珀色等待提示、任务名称/说明的层次必须还原。
- D-10：用户反馈文字难读，同时拒绝整体面板放大。当前取展开任务名 15pt、浮窗 14pt、说明/计时 12pt，菜单条 13pt；通过文字对比度和紧凑间距兼顾可读性与占屏面积。
- D-11：鼠标移到顶部自动展开，进入列表后保持；离开约 400ms 后收起。置顶浮窗不因鼠标离开而隐藏。
- D-12：提供深/浅两种透明玻璃配色；不能只淡入内容，主体轮廓与尺寸变化也要有类似 macOS 的连续动画。参考 Atoll。先在桌面演示应用中试效果。
- D-13：用户确认只做 Codex 专用工具，继续使用独立的 Codex Top 工程。Atoll 单独克隆到仓库外作设计与实现参考，不以整个 Atoll 工程作为产品基础，不扩展音乐、天气、剪贴板或系统监控功能。
- D-14：用户要求背景和字体按 Atoll。深色默认采用纯黑背景、系统字体、白色主文字和中性灰辅助文字，替代此前偏蓝灰材质；浅色玻璃保留为可选配色。标题使用系统 rounded semibold 16pt、任务名 medium 14pt、辅助说明 12pt。
- D-15：用户反馈新版动画仍偏慢，要求更流畅、更快；新增 80%/90%/100% 显示比例、可拖动常驻桌面小浮窗、靠近顶部松手后自动吸附，以及仅状态栏显示方式。浮窗移开鼠标后不收起。先提供常驻小浮窗概念图 `docs/design/desktop-compact-v1.png`，不把图片当成已经实现/验收的功能。

- D-16：新增仅圆环显示，常驻桌面的小圈可拖动，悬停/点击查看同一份列表；接近顶部拖放可收进状态栏。圆环固定 44pt，列表可选 80%/90%/100%。

- D-17：圆环点击后必须由圆环本体原位放大成任务窗口；展开时不留下独立圆圈。收起反向回到原位置，圆环和列表使用同一个 NSPanel。
- D-18：圆环简化为单条细环，去除双层描边、中心圆点和明显阴影。悬停轻微放大，运行蓝弧转动，等待回答用琥珀呼吸，失败红色提示，完成绿色合拢后静止。演示包提供可手动切换的动画预览。
- D-19：用户明确“点击才放大”。圆环悬停仅保留轻微动效反馈，点击才原位展开；展开后鼠标移开不自动收起，通过收起按钮、Escape 或显式切换显示模式关闭。顶部模式继续悬停展开、离开收起。
- D-20：圆环展开后点击面板外也要反向缩回，原来的外部点击照常生效；单纯鼠标移开仍保持展开，常驻浮窗不受影响。纯黑与浅色玻璃可一键切换，背景、文字和控件配色有平滑动态过渡，圆环也同步切换黑白外观。

- D-21：圆环底板必须为正圆，固定 44pt，落点按所在屏幕物理像素对齐。中心数字展示关注任务中的运行数量（超过 99 显示 99+）；需要操作时外环优先琥珀呼吸，失败优先红色，中心仍为运行数；全部完成且无运行时显示绿色对勾，空闲显示 0。数量不等于待处理数或所有本机任务数。

- D-22：系统状态栏图标或计数胶囊左键直接显示任务，再次左键收回；右键打开原菜单，保留选择任务、切模式、设置、找回和退出。Control + 左键等同右键。
- D-23：黑白主题切换要从按下的位置向外圆形扩散，新底色、文字和控件一起揭开，替代整体淡变；不额外绘制装饰圆波。快速再次切换从当前可见外观接续，模式或窗口几何变化不留下旧遮罩；系统减少动态效果时回落短淡变。其他窗口同步主题，不改变关注集合或布局。
- D-24：圆环拖到屏幕顶部后仍留在桌面，不再自动吸附。右键圆环打开与系统状态栏相同的菜单，可手动选择“仅状态栏”；常驻浮窗拖到顶部自动吸附的行为保留。
- D-25：系统 `NSStatusItem` 计数使用透明背景，去掉自绘黑色胶囊；数字跟随系统菜单栏明暗，彩色状态点保留。此规则针对系统状态栏，不改变桌面面板主题，也不移除刘海摄像头区域的黑底。
- D-26：提高文字可读性，保持窗口宽高与缩放比例不变。标题改为 17pt、任务名 16pt、辅助说明 14pt、选择器搜索 16pt；计时、右侧状态与页脚 13pt。圆环中心数字和系统状态栏字号不随此修订改变。
- D-27：展开面板新增提示或定期刷新时，主体和内容尺寸要同步变化，已经到达的同一展开目标不反复播放变形；修订像素对齐与动画目标判定，减少整块闪空的可能。端点稳定记录不能作为完整中间帧或真实帧率的证明。
- D-28：需要处理时整个收起圆球轻微缩放呼吸：仅 `attentionCount > 0`、收起且未启用减少动态效果时，从 44pt 缩到约 41.4pt，再恢复，每半程约 0.9s；中心仍表示运行数量。展开后停止、事项处理完恢复稳定，正常运行只旋转外环；原生窗口尺寸保持 44pt，取消原待回答/失败状态环的透明度呼吸，避免动效频率叠加。
- D-29：浅色玻璃要模糊窗口后方内容，避免选择任务窗口后面的文字清晰透出；前景任务名、搜索和控件文字保持清楚。使用完整强度的原生背景材质，另以浅色渐变控制色调，不靠降低材质透明度或模糊前景文字获得玻璃效果。本轮修订仍需实机核对。
- D-30：实际使用打开 `Codex Top.app`，显示本机真实任务与可用账户额度；`Codex Top Demo.app` 只保留合成示例，不读取账户。账户额度经官方 Codex CLI 接口自动每 60 秒读取，手动刷新最短间隔 5 秒，单次超时 15 秒；显示返回的真实窗口、剩余、重置时间和更新时间，不为缺失的 5 小时窗口编造数值。点击任务返回对应 Codex 对话，点击额度打开官方用量网页。用户已反馈当前不再闪烁、使用正常，该观察不代表全部动画中间帧与其他未验场景通过。
- D-31：修复仅状态栏展开后只出现小黑块及比例不一致。左键应在状态按钮下方展开完整任务面板，再次左键完全收回，不留残余块；鼠标停在状态按钮上或移开不触发自动收回，右键仍打开菜单。80%/90%/100% 的窗口、内容与点击区域一致，快速开合或切模式后不被旧的关闭动作误藏。圆环与顶部刘海交互保持原有规则。

D-14–D-31 是最新视觉、交互与数据决定，覆盖 D-09–D-12 中旧的蓝灰材质、字号与 400ms 离开等待，以及 D-16 中圆环悬停展开的规则。D-20 在 D-19 的点击展开基础上增加外部点击收起；D-23 将 D-20 的主题过渡具体化为点击位置向外揭开的圆形扩散，覆盖此前整体淡变。D-24 覆盖 D-16 的圆环顶部自动吸附，保留常驻浮窗吸附；D-25 覆盖 D-22 所述状态栏计数胶囊的黑底外观，左右键操作不变。D-26 覆盖旧字号，当前采用纯黑/浅色玻璃和 16pt 任务名；D-27 补充刷新与主体尺寸过渡稳定性。D-28 将 D-18/D-21 中需要处理时的呼吸具体化为整个圆球轻微缩放，覆盖原状态环透明度呼吸。D-29 补充浅色背景模糊与前景文字清晰的要求，D-30 将额度扩展为账户接口与日志两种来源，并明确实际应用入口。D-31 明确状态栏完整展开、关闭无残留与比例一致，取消状态栏对顶部悬停计时的复用。180ms 离开等待只适用于顶部模式，圆环面板通过点击面板外或其他显式操作收起。这些时序仍需真实使用验收。

## 状态证据边界

本机当前 Codex 没有提供可连接的 App Server 控制 socket。第一版以本机只读数据库和 rollout 事件为来源，不声称能读取另一进程未持久化的内存状态。只有明确等待事件才显示待处理；无法识别的批准流程显示已有活动或未知，并引导回到 Codex 查看。未落盘的远程/云任务不冒充本机已接入任务。

任务状态仍来自落盘记录；额度可另经官方 Codex CLI 的 `account/rateLimits/read` 获取，不依赖桌面进程的控制 socket。认证由 Codex CLI 管理，本工具不直接读取、复制或缓存凭据，也不发起登录、重置或购买操作。日志与账户快照保留各自来源和观察时间；缺失显示不可用，旧记录标明时效，不能由模拟值掩盖。

生产账户额度客户端已完成一次只读请求并成功解析返回窗口；公开记录不包含个人额度值。该证据不代表打包界面的额度点击、真实对话跳转终点或全部显示场景已实测。

D-31 修复所在最终包已通过 48 项测试和 universal 构建；原生状态栏展开、收回、连续点击及 80%/90%/100% 的实际显示仍待验证，不能以构建通过替代该项实机验收。
