# Codex Top Windows 版开发提示词

更新：2026-09-11。交给同事或开发 AI 使用。本文合并已确认的产品目标和交互规则，不逐字复制聊天，也不把已取消的设计尝试作为新需求。本次只整理交接材料，没有实现 Windows 版。

## 使用方式与边界

先把“总提示词”完整交给同事或开发 AI，再按阶段追加提示词；各阶段均继承总提示词，不另选一套交互或颜色。数据回归清单供实现后逐项验证，源码映射用于按模块阅读。仓库地址：[BuTangTang/Codex-Top](https://github.com/BuTangTang/Codex-Top)；“参考仓库”由接手者指定本地副本，不复制原开发者的绝对路径。

本文是截至 **D-59** 的确认需求合集。macOS beta.5 本轮增加 D-54 待处理文件变化刷新及用户回复恢复、D-55 应用内比例快捷键与缺失运行时间占位、D-56 常驻浮窗与刘海互斥、D-57 定向开始时间回查、D-58 运行标签主文字色和 D-59 运行弧共享相位。最终源码已有 110 项测试通过，构建、实际窗口与发布结果以 [beta.5 验收](../validation/beta5.md) 为准；中途 102 测试与 beta.2/beta.3 截图不代表本轮全部内容已验收。Windows 版尚未实现。

视觉参考优先看 [README 实际应用截图](../../README.md)（最终程序窗口、合成示例任务），概念图只作设计参考。已取消的圆环 hover 展开、拖放自动吸附、深棕待处理色和实色橙底标签都不再采用。浅色标签最终为 **12% 淡橙底、82% 黑色文字**；D-40 透明横条融入系统菜单栏仍只是讨论建议，不属于确认交付范围。

平台边界：

- Windows 用屏幕边缘摘要代替物理刘海，不绘制假摄像头或中央空洞；托盘不能假定支持左右文字或两行额度。
- 不预设 WPF、WinUI、最低 Windows 版本、CPU 架构、数据路径、WSL 来源或任务深链。先核对现场环境与原生窗口能力。Swift 业务核心可参考，AppKit/NSWorkspace/Core Animation 调用须用 Windows 适配重写。
- macOS 已验证的端点和测试不等于 Windows 已验；鼠标连续拖动、物理屏幕、真实 A→B 换号、URL 终点与完整 FPS 等边界仍需各自记录。真实与 Demo 隔离，用户的日常应用不临时切成示例模式；用户明确不接受两份监控界面并存，测试不得让示例版与真实版同时可见，收尾确认只剩预期实例。
- 迁移或复制代码遵守本仓库 [GPL v3 许可证](../../LICENSE)，保留必要来源说明；Atoll 仅作已记录的设计参考，不把其代码和素材当成本项目原创。

## 1. 总提示词

```text
请基于参考仓库 Codex Top 的产品需求，为 Windows 实现一个专门监控 Codex 任务的桌面小工具，项目名沿用 Codex Top。先阅读仓库 AGENTS.md、docs/STATUS.md、REQ-001 的 requirement.md、detailed-design.md、docs/usage.md 和最新验收记录；以最新明确需求覆盖旧决定。不要逐句移植 macOS API，不要自行扩大成音乐、天气、剪贴板、系统监控或聊天客户端。

先检查现有 Windows 工程和开发环境，给出简短的框架/架构选择理由。不要默认已经选定 WPF、WinUI 或其他框架；最低 Windows 版本、CPU 架构、发布方式和 Codex 安装来源需以实际环境为准。先完成独立业务核心，再实现 Windows 平台适配和窗口。日常工作主动完成，只有影响范围或无法推断的平台条件才集中提问。

产品目标：不用持续切回 Codex，也能看到关注任务的运行状态、待回答/批准、失败和最近完成；点击任务返回对应 Codex 对话，输入/批准/执行仍由用户在 Codex 完成。只读监控，不创建新 Codex 任务，不代替批准，不向第三方发送任务内容。

四种入口共用一份关注列表和一套任务状态：
1. 屏幕边缘摘要：Windows 上代替刘海模式。左侧优先显示待处理数量，没有待处理时显示暂停、运行数量或明确的其他状态；右侧显示实际剩余额度，最多两个周期。悬停或点击展开任务，移入列表保持，移开短暂延迟后收回。收起/展开共用横向位置、宽度和顶部，主要向下展开，不为不存在的摄像头留空。
2. 常驻浮窗：紧凑列表，置顶；整个顶部的标题、空白和上下留白都可按下直接拖动，无需长按，不局限于小手柄，按钮区域排除在拖动命中范围外。鼠标移开或点击其他应用不自动隐藏。顶部图钉切换窗口模式，不为每个任务另做图钉；D-56要求钉住后只显示浮窗，隐藏屏幕边缘摘要，取消图钉回到边缘模式，系统托盘入口保留。不同时放两份监控，后台刷新和旧动画回调也不能重新显示已隐藏的摘要。拖到任何屏幕边缘均保持当前模式，不显示吸附提示或自动收入托盘；托盘模式只能由菜单手动选择。
3. 圆球：固定 44×44 DIP 正圆，常驻桌面。鼠标悬停仅轻微反馈，左键点击才从球的位置向下展开同一份任务面板；球消失，不残留第二个球，标题靠近点击位置。左右越界时将面板限制到工作区内侧；向下空间不足且上方空间更多时才回退向上。首次开合选择方向并保持，空间不足滚动，不能随任务高度反复上下翻转。移开鼠标保持，点击面板外、收起按钮或 Escape 缩回球锚点；外部点击继续正常作用于目标。收起时拖动球本体，展开后整个顶部除按钮外可直接拖动，同步平移球锚点，收起回到移动后的位置。所有拖动只移动，不自动切托盘；收起球拖到顶部不展开，松手不额外放大，移出再移入才恢复hover。右键复用托盘菜单。
4. 仅托盘：采用 Windows 支持的图标/工具提示；左键显示或收回完整任务弹层，右键菜单提供任务选择、模式、设置、找回和退出。不要假定托盘支持任意多行文本；完整计数和额度在工具提示/弹层呈现。移开鼠标不自动关闭托盘弹层，关闭不留下黑块。

任务业务：
- 只读本地非归档任务的 ID、短标题、项目、活动元数据和父子关系；任务正文、工具参数、认证文件不得作为展示或持久化来源。
- 搜索任务名/项目，多选和全选当前筛选结果；取消不改动，确认时应用草稿差异，不覆盖选择器打开期间自动加入的新任务。
- 首次成功读取默认关注已有活动和明确待处理主任务，不加入历史完成任务。新建并开始执行的任务默认自动加入；手动排除优先，重新显式勾选可解除排除。关闭自动关注后不继续加入。
- 记录自动关注启用时间与启用时已知 ID。处理整秒创建时间和同秒新任务，兼容旧偏好；不能因为放宽时间边界把已知历史任务全加进来。
- 子任务聚合到主任务，不重复显示成独立卡片；子任务活动/待处理/失败可以提升主任务显示状态。处理缺失父节点、循环关系和乱序，聚合后计数，不重复计算子任务。
- 明确区分运行、待处理、失败、完成、停止、未运行、未知。等待只能来自明确输入/批准事件或已识别的request_user_input/request_user_input_async工具调用，不因助手写了问句就猜测。运行状态15分钟无新活动变未知；明确待处理不因等待时间长而自动消失，证据不足或日志未追平另行标明未知/同步。
- 终止事件带 turn ID 时统一校验，旧轮完成/失败/取消不能结束新轮。失败保持到明确新轮或用户继续，普通助手说明、工具返回、尾随完成不能自动消除失败。同步回答按 call ID 匹配；异步待回答不能仅因工具返回或轮次完成就消失。
- D-54将已落盘的response_item/type=message/role=user作为明确继续输入，读取到完整记录即可解除等待并恢复运行，不必等item_completed/UserMessage或后续完成事件。只检查类型、角色与时间，不读正文猜意图；旧时间、轮次与批准关联守卫仍有效。
- 待处理标签后显示固定mm:ss，计算本轮startedAt到首次进入当前waiting的waitingStartedAt；等待回答期间不涨，不当CPU用时，也不自动减去本轮更早的等待。普通输出/token/重复waiting不能重置锚点，回答/新轮清空，异步问题仍未回答时complete保留；缺失、无效或倒序时间不估算，首次等待缺时间也不能拿较晚的重复等待补造。多个同步/异步问题混合时不能因一个工具返回就解除全部等待。聚合到父任务的等待必须用实际显示子任务activity自己的起止时间，不混父子字段。
- 状态排序优先待处理/错误，其次运行，再未知/未运行；已结束放入可折叠区域。面板已经展开时，向下展开的面板打开/收回已结束区保持顶边；首次因底部不足回退向上的面板则保持靠球的底边。同次开合方向不变，超出工作区时滚动。不要自动scrollTo已结束区而把正在运行的任务卷走，列表插入只做克制淡入。计时必须有依据，不制造完成百分比。
- D-55运行状态缺少可靠的本轮开始记录时显示等宽--:--，悬停和辅助功能说明缺少开始记录；不拿应用启动、最后输出或任务创建时间补造时长。有真实开始记录后再显示运行计时；D-51固定等待耗时的缺失值仍只显示待处理标签，不与运行占位混用。
- D-57仅对已关注根及任意层child中原始running/waiting、startedAt缺失且主reader已追平的活动回查时间。逆向找最近明确task_started/turn_started，再临时正序replay到主reader当前offset；最近明确开始缺时间时不越过它借更老轮次。phase和lastEventAt一致、已有turnID兼容、开始时间有效且不晚于最后事件与已有等待锚点，才补startedAt及原nil turnID；不回写phase/detail/lastEvent/等待标志/waitingStartedAt/主offset/pending/quota。未查完、缺失或不兼容继续保留原状态与占位，不用mtime估算，也不声称恢复所有历史等待。

圆球状态：
- 一条细状态环，不加第二圈、中心点、霓虹或大阴影。中心数字始终是关注列表中正在运行的主任务数量，超过 99 显示 99+，不是待处理数或本机总任务数。
- 正常运行用蓝色不完整弧持续旋转；需要回答/批准时，浅色主题用统一橙色、深色保留原琥珀，失败优先红色。提醒时在球内增加很淡的对应色底和约 11 DIP 的 !，中心仍保留运行数。浅色任务圆点与小待处理标签采用同一橙色，标签用12%淡橙底配深色字，不只改变文字颜色。
- 需要处理且收起时整球视觉轻呼吸：44→约41.4→44 DIP，每半程约0.9秒。原生命中窗口保持44 DIP，不逐帧改顶层窗口尺寸。展开、处理完或系统减少动态效果时停止呼吸。
- 全部完成且没有运行才显示绿色对勾；空闲0，未知灰色。部分任务完成可以短暂绿色反馈后恢复当前运行状态，待处理提示优先。

视觉与动画：
- 原生桌面工具的紧凑比例，中文系统字体，深色纯黑/白色主文字/中性灰辅助文字；浅色有真实背景模糊，前景文本清楚。参考 Atoll 的克制风格，不复制其完整工程、代码或素材。
- 任务面板基准宽约410 DIP，独立紧凑浮窗约360 DIP，圆球44 DIP；列表是共享背景上的紧凑行，不是每任务大卡片。边缘摘要开合同宽且不越出工作区。长标题可以尾部省略并提供完整提示，不为了标题加大窗口。
- 显示比例用原生60%–120%滑块，每5%一档，共13档，按住可连续拖动，旁边显示当前百分比并提供恢复100%。UI以整数百分比60...120、step5作为刻度，绑定写回时除以100，core仍为0.6...1.2；避免小数步长截断120%末档。偏好、滑块位置和数字双向同步，恢复100%也要移thumb；macOS用NSSlider，Windows用所选框架可靠的原生等价控件，不照搬AppKit。与Windows显示DPI区分；窗口和内容统一使用MonitorScale等纯模型，拒绝非有限输入、限制范围、按5%步长四舍五入；旧80/90/100偏好继续兼容。圆球始终44 DIP，不随滑块缩放。60%–75%的展开头部选择入口只留加号，保留悬停说明/可访问名称与原动作，标题保持单行。
- 字号依据每个窗口实际所在屏幕：外接屏compact、内置屏regular，screen暂不可得时保持该窗口原档位，不用全局主屏替代。常驻浮窗无论在哪块屏幕始终compact。regular标题/任务/辅助基准17/16/14 DIP，有效下限15/14/12；compact的base减2、minimum=max(11,oldMinimum-2)，对应基准15/14/12、有效下限13/12/11。先按用户比例计算并保留下限，监控/选择器/额度/收起摘要和错误/空状态/通知一致；低比例的错误与通知区域按至少80%比例保留高度，不能让可读文字挤出窗口。原生设置控件系统字号不改。Windows的内置/外接识别方式需现场核验。
- D-55加入应用内放大/缩小快捷键，与滑块共用MonitorScale和保存路径，每次5%，范围60%–120%。macOS参考⌘+或⌘=放大、⌘-缩小；Windows按选定框架的菜单快捷键机制映射并核对键盘布局，不照搬Command键、不注册全局钩子或拦截其他应用输入。快捷键后滑块、数字与窗口同步；不另增无需求的全局重置组合键。
- 监控窗口已经取得键盘焦点时缩放快捷键也需生效；macOS非激活Panel将匹配键转给本应用菜单，Windows实现按框架原生焦点/菜单机制处理。其他应用持有键盘焦点时不截获。
- 浅色waiting accent统一归一化RGB(0.91,0.43,0.06)橙色，圆环与任务圆点复用该色；小待处理标签用12% 淡橙底、黑色opacity0.82文字，圆角4 DIP、水平5/垂直2 DIP留白。浅色球底叠白色opacity0.36，attention橙色叠层仅0.04（覆盖旧0.12）；深色保留原亮琥珀和tint opacity0.12半透明标签底，失败仍红。图标、标签与环要一致，不只改文字；保持背景模糊与前景清楚，不宣称未经实测的对比度合格。
- 圆球参考临界阻尼弹簧：macOS开/关response参数0.32/0.28、damping=1、blend=0；response不是固定持续秒数，Windows需按所选动画系统映射，不写成“0.32秒结束”。先准备最终布局和canvas，再同一动画事务提交展开状态与外壳目标；正文与圆环透明度用同一插值进度经smoothstep衔接，无固定文字delay。首帧按方向顶/底对齐，主体从球所在边缘揭开，正文只淡入，保留用户uiScale，不叠加中心缩放；坐标、窗口和布局共同提交。完成由真实动画回调和代次校验判定，不能靠猜测秒数裁剪。
- D-58“运行中”标签使用主题主文字色，深色亮白、浅色深色；蓝色只保留给运行环等状态图形。所有标签消费者共用规则，紧凑行不能绕过；waiting已认可颜色、完成/失败、字号和尺寸均不改。
- D-59运行圈持续旋转，参考22/24 DIP、3 DIP轨道、1.2秒线性一圈。所有可见且允许动态的运行圈共享一个单调时间epoch；新增/重新显示接当前相位，可见前端角度一致，不能各自从0或旧暂停角度起转。保留44 DIP球与任务行各自弧长/半径/线宽，以path起点+trimEnd的差补偿前端角度。macOS通过layer.convertTime转换共同beginTime，Windows用选定合成系统的等价时间空间，不直接复制CA API；不用墙钟或全局Timer/SwiftUI逐帧刷新。颜色/计数/hover不重加动画，实际起点/trimEnd变更才调整alignment但不重置epoch；隐藏/拆除/减少动态时停止并保留静态，恢复重新对齐当前节奏。
- 主题按钮在设置和面板底部均可用。从实际点击点圆形揭开新底色、文字和控件，约0.42秒；快速切换从当前可见状态接续。切模式、尺寸或DPI改变时清掉旧遮罩。系统减少动态效果时用约0.10秒淡变并停旋转/空间缩放，仍保留静态状态提示。
- 主题快照外轮廓与实际窗口一致：逐边圆角、continuous/circular曲线、用户缩放与DPI转换均匹配，不把四角统一20/22当作通用轮廓。普通缩放面板的参考半径为20×uiScale DIP，圆球外壳22 DIP在内容缩放之外；Windows边缘摘要按自身真实轮廓处理，不画假刘海。圆角裁剪与径向揭开取交集，不能删掉裁剪后让旧色覆盖表面之外，也不能把圆角轮廓直接与圆孔做even-odd异或而填出外角。
- 不能用固定睡眠假装动画完成；只在实际完成且代次/模式/目标仍有效时收整画布。定期刷新相同目标不重播动画；外部点击不被透明画布误吞。

数据与额度：
- 在Windows现场确认Codex安装位置、官方CLI、当前数据目录、SQLite schema与rollout格式。尊重用户选择的根目录和合法CODEX_HOME覆盖；不猜Windows默认路径，不修改全局变量，不修改源数据库、日志或登录设置。
- 任务数据约每2秒后台读取，首次有界尾部、随后按偏移增量；无变化不重读，截断/轮转可恢复，损坏JSON、半行和大行有界处理。仅首次/文件真实重置允许尾读；后续从offset顺序消费，不能因追加超过64KB跳尾清掉等待/turnID。参考64KB分块、每轮4MB预算；未追平时仅该任务unknown+“正在同步任务活动…”，内部归约状态保留，后续继续追赶，不加使整个窗口变高的全局提示。记录上次observedSize识别同大小原位重写、缩短但仍大于offset；isCaughtUp只表示到达本次采样EOF，末尾半行仍等换行再解析。冷启动尾64KB可能缺少更早未答事件，预算追赶也有延迟，不能宣称全部恢复或无条件实时。任务扫描不阻塞UI、不触发网络查询。
- 额度独立读取官方app-server，每次实际刷新使用新的独立CLI进程，读取该时刻CLI所登录的账户。只执行已验证的初始化与account/rateLimits/read；不能发thread/start、turn/start、发送提示词、工具/MCP调用、登录、重置或购买。协议以官方文档及现场CLI schema为准，不因检测换号擅自扩展认证访问。
- D-54在2秒轮询兜底之外，监听已关注根任务对应的waiting活动文件，包括实际处于waiting的子任务，最多64个本地文件。监听本身只报变化不读内容、不监控全盘；连续事件约200ms合并后走现有后台增量读取，扫描忙时保留一次待刷新需求，完成后补读。变更不触发额度网络请求。规范化路径、同路径update去重、文件替换/删除后重建、旧监听代次防回写；取消关注、源切换、暂停和退出清理监听及待发动作。Windows使用可靠的原生文件变化机制适配，不照搬Darwin O_EVTONLY/DispatchSource；权限失败、事件漏报或未监听任务仍由轮询覆盖。200ms是合并窗口，不是发送到界面的延迟承诺。
- D-57时间恢复的额外I/O预算：每snapshot全部候选总计最多8MiB，每task最多4MiB，逆向search与正序replay共享预算，候选轮转；64KiB块及单行上限，临时拼接最多约128KiB，cursor跨轮保留，无固定总回查距离。额外字节计入bytesRead。成功、到文件开头无证据或IO失败按文件代次缓存，普通append不反复重扫；inode变化、缩短、等长rewrite重置，主reader读到新start取消旧恢复。持有文件句柄并在结束路径复核元数据，防替换期间跨代补时。Windows需适配文件身份与共享打开规则，不扩大所有任务默认64KiB冷尾读。
- 自动额度刷新约60秒一次；手动最短间隔5秒，失败也限频、并发合并，单次约15秒超时。不是每2秒查账户，不下载更新，不额外遥测。CLI不可用/未登录/新账户读取失败时清除当前账户余额并显示不可用，提供官方用量页入口；不复用上一账户或示例余额。
- 只显示实际返回的额度窗口；5h或周缺失不能补成0%/100%。清楚注明是剩余比例、来源、观察时间、重置时间；未知周期按真实时长显示。超过5分钟显示陈旧标记，过重置点显示待更新；陈旧不改变account/log来源，也不把旧账户值放进当前余额。
- 主界面余额只来自账户接口。日志额度独立保留在设置的“历史日志额度（不代表当前账号）”折叠区，不按时间新旧与账户余额混选，不在当前账户读取失败时拿日志回填。目录/请求/停止状态有代次守卫，旧响应不能回写新源；同目录A→B换号后，下一次真实刷新读取B，失败则清空当前余额，不回退成A。自动刷新以约60秒为间隔，网络和失败可能延长实际更新，不宣称瞬间检测所有外部登录变化。
- 不直接读取或记录auth/token，不向UI、错误日志、公开文档或Git输出邮箱、账户ID、额度原响应。若后续确需新增账户身份查询，应先核对官方只读接口及其必要性，不解析认证文件。失败文案不拼接服务端error.data或stderr。
- 超时、取消、目录切换和应用退出均要结束并回收本工具拥有的子进程；不要杀用户自己的Codex。退出必须有有界清理等待，不能cancel后立即让父进程消失。标准输出/错误输出有界，避免管道堵塞。
- 界面名称用“暂停任务刷新”：停止新的自动任务扫描、文件监听和待发快速刷新，不暂停Codex，也不暂停独立的60秒账户额度读取；在途读取允许完成，手动刷新仍可用。

平台与交付：
- 默认主显示器、可固定显示器、找回窗口；处理负坐标、不同DPI、任务栏四边/自动隐藏、侧边Dock、物理拔插、主屏变化、睡眠恢复。不能把旧绝对托盘坐标永久缓存。
- D-53设置窗口从任意入口打开时，先于激活应用捕获鼠标全局位置，以完整显示器边界选屏（包含任务栏区域），在该屏工作区布局，不跟随边缘摘要的固定屏。首次、关闭再开或已打开但不完整位于目标工作区时居中并约束整窗；已显示且完整同屏则保留用户位置，只激活置前。复用窗口及设置内容，保留滚动状态；无鼠标命中时依次回退原设置屏、系统主屏、首屏。按Windows现场DPI和坐标约定实现，不直接混用物理像素与DIP。
- Windows的任务深链和URL handler必须现场验证。参考macOS路由但不直接宣称Windows支持；不支持时提供明确提示和用户可用的任务ID，不调用内存注入或隐藏UI绕路。额度页候选为官方 https://chatgpt.com/codex/settings/usage，交付前核对仍可用。
- 设置和真实/Demo状态独立，自己的偏好支持备份和恢复；开机启动使用正式平台机制、显示真实结果，不越过系统权限。Demo只用于隔离测试，不读取真实账户，不临时替换用户的真实桌面应用。
- 维护需求、设计、任务清单、进度、使用说明、限制和验收证据。合成测试、真实应用端点、物理硬件和逐帧/FPS分别记录，截图或编译成功不能等于全部验收。
- 完成有区分力的核心/数据/进程测试和实际Windows打包验证后，向已确认的目标仓库阶段性提交并push。首版通过GitHub Pre-release分享可运行包及SHA-256，安装器或便携形式按阶段A的平台决定，不照搬macOS DMG；版本/tag/源码/包对应，新版本不覆盖旧版附件。保留许可证，禁止提交凭据、真实标题/正文、私有路径、原始响应、示例临时目录和构建产物。不要强推，不把未完成项勾成完成；只在真实发布回执后记录发布成功。
```


### 阶段 E：视觉与动画专项


## 5. Windows 交接时必须现场核实

| 核实项 | 要取得的证据 | 未满足时的处理 |
|---|---|---|
| 最低系统、CPU架构与框架 | 实际环境、构建和窗口能力探针 | 不预写支持版本；文档标明待定 |
| Codex 原生Windows/WSL来源 | CLI版本、安装来源、数据schema兼容性，不公开私人路径 | 明确只支持已验证来源；允许用户指定目录 |
| 官方额度与换号 | 当前CLI协议、一次只读额度成功、合成A/B隔离及授权范围内实际换号验证 | 无身份归属证据时不显示旧账户余额；不把macOS验证借用过来 |
| 任务链接 | 系统handler、实际打开对应任务及失败路径 | 未验证不承诺自动直达；提示并提供任务ID |
| 托盘锚点与恢复 | 主/副任务栏、自动隐藏、Explorer重启、左右键与弹层位置 | 可回退到工作区，但不能缓存离屏坐标或隐藏找回入口 |
| 设置窗口选屏 | 各入口、主副屏及任务栏鼠标位置、关闭再开、同屏位置保持、跨DPI和滚动复用；原生屏幕坐标或完整桌面位置证据 | 不以窗口内部截图冒充跨屏通过，不把固定摘要屏当设置目标；缺设备场景保留未验 |
| 玻璃和高对比 | 原生模糊、系统禁用透明/动画、高对比下的真实截图 | 提供可读实色/静态回退，保持状态含义 |

| 进程和低流量 | 自动/手动请求计数、无turn/tool调用、取消/退出后的自有进程消失 | 先修生命周期，不通过全局杀进程掩盖 |
| 发布与隐私 | 与源码对应的Windows包、依赖/签名状态、Git内容审查 | 不泄露真实任务/账号/原始响应；未发布条件如实保留 |

本文中的账户隔离和退出回收是 Windows 验收目标。macOS 已有当前账户/历史日志分离、有界退出、合成换号回归和两次生产只读额度成功证据，但未替用户实际登录切换账号；不把这些写成 Windows 或真实 A→B 已验收。分阶段测试、代码审查和 Windows 实机验收都完成后，才将对应条目标记通过。
