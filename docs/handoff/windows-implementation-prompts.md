# Codex Top Windows 版开发提示词

更新：2026-09-11。交给同事或开发 AI 使用。本文合并已确认的产品目标和交互规则，不逐字复制聊天，也不把已取消的设计尝试作为新需求。本次只整理交接材料，没有实现 Windows 版。

## 使用方式与边界

先复制“总提示词”，再按阶段追加对应提示词。仓库地址：[BuTangTang/Codex-Top](https://github.com/BuTangTang/Codex-Top)。提示词里的“参考仓库”指收到的本仓库副本，使用者自行指定本地位置，不复制原开发者的绝对路径。

- 已确认的业务和视觉需求可迁移；SwiftUI、AppKit、NSPanel、NSWorkspace、Core Animation 的调用不可直接照搬到 Windows。
- Windows 没有本产品所依赖的物理刘海布局。对应入口称“屏幕边缘摘要”，不绘制假的摄像头黑块，也不留一段不存在的摄像头空白。
- 托盘与屏幕边缘摘要是不同入口。不能假定 Windows 托盘能内嵌两行文字或 macOS 风格的左右计数；先验证平台能力，再设计图标、工具提示和点击弹层。
- 不预先限定 WPF、WinUI 或其他框架。先核对现有工程、最低 Windows 版本、透明/模糊、置顶、DPI、动画与发布约束，再确定方案。
- D-40 的“收起横条透明、文字随系统明暗”仍是讨论建议，未作为确认功能实施。Windows 第一版保持已确认的深色/浅色玻璃方向；是否融入 Windows 任务栏另外讨论。
- 圆环首次展开方向已确认并实现：点击后球消失，面板从原球位置向下展开，标题靠近点击位置；左右靠边时限制到屏幕内侧，底部不足且上方空间更多时才向上；空间不足滚动，同次开合不反复换方向，收起恢复原锚点。macOS D-47 检查点通过 76 项测试，D-48 后为 78 项测试、universal 和严格签名通过，上一真实候选已见标题接近指针、已结束开合保留运行行；不能借此声称 Windows 或全部动画已验收。
- D-48 已确认取消所有拖放自动切状态栏；常驻浮窗和展开圆环的整个顶部除按钮外均可直接拖动，包含标题、空白和上下留白，无需长按。展开圆环移动后收起到移动后的球锚点。该修订覆盖旧的常驻浮窗顶部吸附规则，macOS 本轮验收另行记录，Windows 以此作为目标需求。
- D-49–D-51 是 beta.2 的已确认目标：外接屏与常驻浮窗采用紧凑字号，内置屏常规，按各窗口实际screen更新、nil保持。浅色圆环、任务圆点与小标签统一橙色，标签最终采用12%淡橙底配黑色0.82文字，覆盖中间被否定的橙色实底。原生比例滑块60%–120%、每5%一档和100%恢复，整数13刻度确保末档可达、thumb与数值同步；60%–75%展开头部选择入口改为加号，旧80/90/100偏好兼容，圆环保持44 DIP。待处理标签后显示本轮到当前等待的固定耗时。最终测试、真实包与发布范围另行记录，不能把早先结果或圆环颜色认可当成全部验收。
- 账户切换后的额度隔离在本交接中是必须验证的 Windows 目标。macOS 已补当前账户/历史日志分离和有界退出，合成 A→B 读取及换号后失败不复用缓存纳入最终测试，两次独立只读账户请求成功；没有替用户登录或进行真实 A→B 换号，不能写成真实换号已验收。接手时核对最终代码和验收记录。
- 本仓库使用现有 `LICENSE` 中的 GPL v3。复制或迁移代码时保留许可证与必要来源说明，不把参考项目的代码或素材当成自己原创。

## 1. 总提示词

```text
请基于参考仓库 Codex Top 的产品需求，为 Windows 实现一个专门监控 Codex 任务的桌面小工具，项目名沿用 Codex Top。先阅读仓库 AGENTS.md、docs/STATUS.md、REQ-001 的 requirement.md、detailed-design.md、docs/usage.md 和最新验收记录；以最新明确需求覆盖旧决定。不要逐句移植 macOS API，不要自行扩大成音乐、天气、剪贴板、系统监控或聊天客户端。

先检查现有 Windows 工程和开发环境，给出简短的框架/架构选择理由。不要默认已经选定 WPF、WinUI 或其他框架；最低 Windows 版本、CPU 架构、发布方式和 Codex 安装来源需以实际环境为准。先完成独立业务核心，再实现 Windows 平台适配和窗口。日常工作主动完成，只有影响范围或无法推断的平台条件才集中提问。

产品目标：不用持续切回 Codex，也能看到关注任务的运行状态、待回答/批准、失败和最近完成；点击任务返回对应 Codex 对话，输入/批准/执行仍由用户在 Codex 完成。只读监控，不创建新 Codex 任务，不代替批准，不向第三方发送任务内容。

四种入口共用一份关注列表和一套任务状态：
1. 屏幕边缘摘要：Windows 上代替刘海模式。左侧优先显示待处理数量，没有待处理时显示暂停、运行数量或明确的其他状态；右侧显示实际剩余额度，最多两个周期。悬停或点击展开任务，移入列表保持，移开短暂延迟后收回。收起/展开共用横向位置、宽度和顶部，主要向下展开，不为不存在的摄像头留空。
2. 常驻浮窗：紧凑列表，置顶；整个顶部的标题、空白和上下留白都可按下直接拖动，无需长按，不局限于小手柄，按钮区域排除在拖动命中范围外。鼠标移开或点击其他应用不自动隐藏。顶部图钉切换窗口模式，不为每个任务另做图钉。拖到任何屏幕边缘均保持当前模式，不显示吸附提示或自动收入托盘；托盘模式只能由菜单手动选择。
3. 圆球：固定 44×44 DIP 正圆，常驻桌面。鼠标悬停仅轻微反馈，左键点击才从球的位置向下展开同一份任务面板；球消失，不残留第二个球，标题靠近点击位置。左右越界时将面板限制到工作区内侧；向下空间不足且上方空间更多时才回退向上。首次开合选择方向并保持，空间不足滚动，不能随任务高度反复上下翻转。移开鼠标保持，点击面板外、收起按钮或 Escape 缩回球锚点；外部点击继续正常作用于目标。收起时拖动球本体，展开后整个顶部除按钮外可直接拖动，同步平移球锚点，收起回到移动后的位置。所有拖动只移动，不自动切托盘；收起球拖到顶部不展开，松手不额外放大，移出再移入才恢复hover。右键复用托盘菜单。
4. 仅托盘：采用 Windows 支持的图标/工具提示；左键显示或收回完整任务弹层，右键菜单提供任务选择、模式、设置、找回和退出。不要假定托盘支持任意多行文本；完整计数和额度在工具提示/弹层呈现。移开鼠标不自动关闭托盘弹层，关闭不留下黑块。

任务业务：
- 只读本地非归档任务的 ID、短标题、项目、活动元数据和父子关系；任务正文、工具参数、认证文件不得作为展示或持久化来源。
- 搜索任务名/项目，多选和全选当前筛选结果；取消不改动，确认时应用草稿差异，不覆盖选择器打开期间自动加入的新任务。
- 首次成功读取默认关注已有活动和明确待处理主任务，不加入历史完成任务。新建并开始执行的任务默认自动加入；手动排除优先，重新显式勾选可解除排除。关闭自动关注后不继续加入。
- 记录自动关注启用时间与启用时已知 ID。处理整秒创建时间和同秒新任务，兼容旧偏好；不能因为放宽时间边界把已知历史任务全加进来。
- 子任务聚合到主任务，不重复显示成独立卡片；子任务活动/待处理/失败可以提升主任务显示状态。处理缺失父节点、循环关系和乱序，聚合后计数，不重复计算子任务。
- 明确区分运行、待处理、失败、完成、停止、未运行、未知。等待只能来自明确事件，不因助手写了问句就猜测；活动记录过旧或证据不足显示未知。
- 终止事件带 turn ID 时统一校验，旧轮完成/失败/取消不能结束新轮。失败保持到明确新轮或用户继续，普通助手说明、工具返回、尾随完成不能自动消除失败。同步回答按 call ID 匹配；异步待回答不能仅因工具返回或轮次完成就消失。
- 待处理标签后显示固定mm:ss，计算本轮startedAt到首次进入当前waiting的waitingStartedAt；等待回答期间不涨，不当CPU用时，也不自动减去本轮更早的等待。普通输出/token/重复waiting不能重置锚点，回答/新轮清空，异步问题仍未回答时complete保留；缺失、无效或倒序时间不估算。聚合到父任务的等待必须用实际显示子任务activity自己的起止时间，不混父子字段。
- 状态排序优先待处理/错误，其次运行，再未知/未运行；已结束放入可折叠区域。面板已经展开时，向下展开的面板打开/收回已结束区保持顶边；首次因底部不足回退向上的面板则保持靠球的底边。同次开合方向不变，超出工作区时滚动。不要自动scrollTo已结束区而把正在运行的任务卷走，列表插入只做克制淡入。计时必须有依据，不制造完成百分比。

圆球状态：
- 一条细状态环，不加第二圈、中心点、霓虹或大阴影。中心数字始终是关注列表中正在运行的主任务数量，超过 99 显示 99+，不是待处理数或本机总任务数。
- 正常运行用蓝色不完整弧持续旋转；需要回答/批准时，浅色主题用统一橙色、深色保留原琥珀，失败优先红色。提醒时在球内增加很淡的对应色底和约 11 DIP 的 !，中心仍保留运行数。浅色任务圆点与小待处理标签采用同一橙色，标签用12%淡橙底配深色字，不只改变文字颜色。
- 需要处理且收起时整球视觉轻呼吸：44→约41.4→44 DIP，每半程约0.9秒。原生命中窗口保持44 DIP，不逐帧改顶层窗口尺寸。展开、处理完或系统减少动态效果时停止呼吸。
- 全部完成且没有运行才显示绿色对勾；空闲0，未知灰色。部分任务完成可以短暂绿色反馈后恢复当前运行状态，待处理提示优先。

视觉与动画：
- 原生桌面工具的紧凑比例，中文系统字体，深色纯黑/白色主文字/中性灰辅助文字；浅色有真实背景模糊，前景文本清楚。参考 Atoll 的克制风格，不复制其完整工程、代码或素材。
- 任务面板基准宽约410 DIP，独立紧凑浮窗约360 DIP，圆球44 DIP；列表是共享背景上的紧凑行，不是每任务大卡片。边缘摘要开合同宽且不越出工作区。长标题可以尾部省略并提供完整提示，不为了标题加大窗口。
- 显示比例用原生60%–120%滑块，每5%一档，共13档，按住可连续拖动，旁边显示当前百分比并提供恢复100%。UI以整数百分比60...120、step5作为刻度，绑定写回时除以100，core仍为0.6...1.2；避免小数步长截断120%末档。偏好、滑块位置和数字双向同步，恢复100%也要移thumb；macOS用NSSlider，Windows用所选框架可靠的原生等价控件，不照搬AppKit。与Windows显示DPI区分；窗口和内容统一使用MonitorScale等纯模型，拒绝非有限输入、限制范围、按5%步长四舍五入；旧80/90/100偏好继续兼容。圆球始终44 DIP，不随滑块缩放。60%–75%的展开头部选择入口只留加号，保留悬停说明/可访问名称与原动作，标题保持单行。
- 字号依据每个窗口实际所在屏幕：外接屏compact、内置屏regular，screen暂不可得时保持该窗口原档位，不用全局主屏替代。常驻浮窗无论在哪块屏幕始终compact。regular标题/任务/辅助基准17/16/14 DIP，有效下限15/14/12；compact的base减2、minimum=max(11,oldMinimum-2)，对应基准15/14/12、有效下限13/12/11。先按用户比例计算并保留下限，监控/选择器/额度/收起摘要一致；原生设置控件系统字号不改。Windows的内置/外接识别方式需现场核验。
- 浅色waiting accent统一归一化RGB(0.91,0.43,0.06)橙色，圆环与任务圆点复用该色；小待处理标签用12% 淡橙底、黑色opacity0.82文字，圆角4 DIP、水平5/垂直2 DIP留白。浅色球底叠白色opacity0.36，attention橙色叠层仅0.04（覆盖旧0.12）；深色保留原亮琥珀和tint opacity0.12半透明标签底，失败仍红。图标、标签与环要一致，不只改文字；保持背景模糊与前景清楚，不宣称未经实测的对比度合格。
- 圆球参考临界阻尼弹簧：macOS开/关response参数0.32/0.28、damping=1、blend=0；response不是固定持续秒数，Windows需按所选动画系统映射，不写成“0.32秒结束”。先准备最终布局和canvas，再同一动画事务提交展开状态与外壳目标；正文与圆环透明度用同一插值进度经smoothstep衔接，无固定文字delay。首帧按方向顶/底对齐，主体从球所在边缘揭开，正文只淡入，保留用户uiScale，不叠加中心缩放；坐标、窗口和布局共同提交。完成由真实动画回调和代次校验判定，不能靠猜测秒数裁剪。
- 任务行运行圈也要旋转，不能只画固定角度弧线；参考22/24 DIP、3 DIP轨道、约1.2秒线性一圈。持续动画由合适的合成层驱动，数据刷新不能反复起转；隐藏/拆除停止，重新显示正确恢复。44 DIP圆球默认细环参数不要被任务行样式覆盖。
- 主题按钮在设置和面板底部均可用。从实际点击点圆形揭开新底色、文字和控件，约0.42秒；快速切换从当前可见状态接续。切模式、尺寸或DPI改变时清掉旧遮罩。系统减少动态效果时用约0.10秒淡变并停旋转/空间缩放，仍保留静态状态提示。
- 不能用固定睡眠假装动画完成；只在实际完成且代次/模式/目标仍有效时收整画布。定期刷新相同目标不重播动画；外部点击不被透明画布误吞。

数据与额度：
- 在Windows现场确认Codex安装位置、官方CLI、当前数据目录、SQLite schema与rollout格式。尊重用户选择的根目录和合法CODEX_HOME覆盖；不猜Windows默认路径，不修改全局变量，不修改源数据库、日志或登录设置。
- 任务数据约每2秒后台读取，首次有界尾部、随后按偏移增量；无变化不重读，截断/轮转可恢复，损坏JSON、半行和大行有界处理。仅首次/文件真实重置允许尾读；后续从offset顺序消费，不能因追加超过64KB跳尾清掉等待/turnID。参考64KB分块、每轮4MB预算；未追平时仅该任务unknown+“正在同步任务活动…”，内部归约状态保留，后续继续追赶，不加使整个窗口变高的全局提示。记录上次observedSize识别同大小原位重写、缩短但仍大于offset；isCaughtUp只表示到达本次采样EOF，末尾半行仍等换行再解析。冷启动尾64KB可能缺少更早未答事件，预算追赶也有延迟，不能宣称全部恢复或无条件实时。任务扫描不阻塞UI、不触发网络查询。
- 额度独立读取官方app-server，每次实际刷新使用新的独立CLI进程，读取该时刻CLI所登录的账户。只执行已验证的初始化与account/rateLimits/read；不能发thread/start、turn/start、发送提示词、工具/MCP调用、登录、重置或购买。协议以官方文档及现场CLI schema为准，不因检测换号擅自扩展认证访问。
- 自动额度刷新约60秒一次；手动最短间隔5秒，失败也限频、并发合并，单次约15秒超时。不是每2秒查账户，不下载更新，不额外遥测。CLI不可用/未登录/新账户读取失败时清除当前账户余额并显示不可用，提供官方用量页入口；不复用上一账户或示例余额。
- 只显示实际返回的额度窗口；5h或周缺失不能补成0%/100%。清楚注明是剩余比例、来源、观察时间、重置时间；未知周期按真实时长显示。超过5分钟标历史，过重置点显示待更新。
- 主界面余额只来自账户接口。日志额度独立保留在设置的“历史日志额度（不代表当前账号）”折叠区，不按时间新旧与账户余额混选，不在当前账户读取失败时拿日志回填。目录/请求/停止状态有代次守卫，旧响应不能回写新源；同目录A→B换号后，下一次真实刷新读取B，失败则清空当前余额，不回退成A。自动刷新以约60秒为间隔，网络和失败可能延长实际更新，不宣称瞬间检测所有外部登录变化。
- 不直接读取或记录auth/token，不向UI、错误日志、公开文档或Git输出邮箱、账户ID、额度原响应。若后续确需新增账户身份查询，应先核对官方只读接口及其必要性，不解析认证文件。失败文案不拼接服务端error.data或stderr。
- 超时、取消、目录切换和应用退出均要结束并回收本工具拥有的子进程；不要杀用户自己的Codex。退出必须有有界清理等待，不能cancel后立即让父进程消失。标准输出/错误输出有界，避免管道堵塞。
```
