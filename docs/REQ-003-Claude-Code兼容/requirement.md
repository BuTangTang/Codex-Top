# REQ-003 兼容 Claude Code（第一阶段：Mac 端）

版本：v0.2，2026-10-08。v0.1 已通过（用户：“可以，下一步”）；v0.2 加入设计审核时用户提出的 D-06、D-07，待确认。设计通过前不拆任务、不改代码。

## 1. 目标

Codex Top 的 Mac 端目前只监控 Codex 任务。本需求让它同时监控本机的 Claude Code（下称 cc）会话：在同一份关注列表、同一套刘海／浮窗／圆环／状态栏里，看到 cc 会话是否在运行、是否在等你处理、是否已结束，并能点击回到对应窗口。

用户原话（2026-10-08）：“接下来，我希望我们这个软件可以兼容cc”，随后“我们先做mac的视线”（按“实现”理解）。

## 2. 范围

本阶段只做 Mac 端。以下不在本阶段：

- 手机端显示 cc 会话。界面方向已记为 [REQ-002 D-45 草案](../REQ-002-局域网多设备监控/requirement.md#多来源界面增量需求-d-45草案2026-10-08未实施)，另行审核和实施。
- cc 额度（D-05）。
- 在面板内直接批准权限或回复 cc；这些仍回到 cc 自己的窗口完成，与现有 Codex 的做法一致。
- 应用改名。名称和图标保持“Codex Top”。
- Windows 版。

| D-05 | 第一阶段不做 cc 额度。 | 用户选“先不做” |

## 4. 需求

### 发现与列表

- **R-01 发现会话**：本机 cc 产生的会话出现在任务选择器里，可搜索、多选、加入或移出关注，操作方式与 Codex 任务相同。终端、桌面 App、IDE 插件里开的 cc 会话都应覆盖；实际能覆盖哪些入口以验收记录为准。
- **R-02 标题与项目**：显示会话标题和所属项目名。用户给会话起过名字时用该名字；没有标题时显示“未命名会话”，不拿对话正文拼标题。
- **R-03 来源标记**：当前显示的列表里同时有 Codex 和 cc 两种来源时，每个任务行都有来源标记，Codex 为 CX，Claude Code 为 CC，形状和颜色都不同。列表里只有一种来源时（全是 Codex 或全是 cc）不显示标记（D-06）。面板按关注列表判断，任务选择器按它自己列出的任务判断。标记不占用状态图标的位置。
- **R-04 混排**：两种来源共用一份关注列表，沿用现有排序（待处理、出错、运行中、未知、未运行、已停止、已完成）。刘海、浮窗、圆环、状态栏的运行数和待处理提醒把 cc 会话一并计入。
- **R-05 关注规则**：新开始的 cc 会话默认自动加入关注，手动移出优先；7 天自动整理、右键“移出监控”对 cc 会话同样生效。
- **R-06 子代理**：cc 会话派生的子代理归入其主会话，不单独成行；子代理在运行或等待时，主会话相应显示。

### 状态与计时

- **R-07 状态**：cc 会话使用与 Codex 相同的七种状态。待处理包含等待权限审批和等待回答提问两种，文字上分别说明。
- **R-08 不伪装**：无法判断、记录缺失或较久没有新活动时显示“状态未知”，不显示成运行或完成。未启用 hooks 时能识别到什么程度就显示到什么程度，识别不出的等待不猜测。
- **R-09 计时**：运行计时和待处理的固定耗时沿用现有规则。缺少可靠的本轮开始时间时显示 `--:--`，不用创建时间、文件修改时间或当前时间估算。
- **R-10 刷新**：cc 会话状态变化后，面板在与 Codex 任务相近的延迟内更新；暂停任务刷新时一并暂停。

### hooks（D-02）

- **R-11 明确开启**：hooks 默认不安装。设置里提供一个开关，开启前说明会修改 cc 的哪个配置文件、加入什么内容；用户确认后才写入。
- **R-12 最小改动**：只添加本应用自己的条目，不改动、不重排用户已有的 hooks 和其他设置。写入前保留一份可恢复的备份。
- **R-13 可撤销**：关闭开关即移除本应用添加的条目，其他内容保持原样；设置里能看到当前是否已安装。
- **R-14 只记元数据**：hooks 只上报会话编号、事件类型和时间，不记录对话正文、命令内容、文件内容或密钥。
- **R-15 不拖累 cc**：hooks 必须很快结束；本应用没在运行、上报失败或出错时，cc 自身照常工作，不报错、不卡住。
- **R-16 可降级**：未开启 hooks 时本功能仍可用，只是状态精度按 R-08 降低。

### 跳转（D-04）

- **R-17 点击任务**：桌面 App 里的会话打开 Claude 桌面 App，能定位到具体会话时定位，只能打开 App 时也算完成。终端或 IDE 里的会话本阶段不做窗口定位（D-07）：点击时给出简短提示并复制会话编号，不假装已跳转。

### 设置与兼容

- **R-18 数据目录**：默认使用 cc 的标准数据目录，支持其环境变量覆盖，也可在设置里手动选择。
- **R-19 可关闭**：设置里可以整体关闭 cc 来源；关闭后界面和行为与现在的版本一致。
- **R-20 未安装 cc**：本机没有 cc 或没有任何会话时，不报错、不出现空的 cc 区域，Codex 功能不受影响。
- **R-21 文案**：提示文字按来源区分，例如 cc 任务出错时写“请回到 Claude Code 查看”。
- **R-22 额度**：底栏和额度悬停只显示 Codex 额度，并标明是 Codex 的；不显示任何 cc 额度数字或占位进度条。

### 数据与隐私

- **R-23**：只读取 cc 的会话元数据和判断状态所需的事件信息，不保留对话正文、工具参数和命令输出；不上传任何内容。
- **R-24**：除 R-11～R-13 的 hooks 条目外，不修改 cc 的对话记录、配置、认证或任何其他文件。
- **R-25**：诊断材料不包含对话正文、密钥和完整本机路径。

## 5. 验收要求

- 单元测试使用合成的 cc 样例和独立临时目录，覆盖七种状态、子代理归并、缺失时间、格式不识别、未安装 cc、hooks 安装与移除前后的配置内容。
- `swift test` 与 `swift build -c release` 通过；Codex 既有测试全部保持通过。
- 打包后的真实窗口验收，内置屏和外接屏各一次，四种显示方式都在两种来源并存时看到 CX／CC 标记，只有一种来源时不显示标记，计数正确。
- 真实 cc 会话：以桌面 App 为主，实际观察开始运行、等待权限、回答后继续、完成、手动中断这几种变化，分别在开启和未开启 hooks 两种情况下记录。终端会话只验证能出现在列表里并显示状态。
- hooks：开启后回读配置，确认只多了本应用的条目；关闭后回读，确认恢复原样；本应用退出时 cc 仍正常运行。
- 点击跳转：桌面 App 会话验一次，如实记录能定位到哪一级；终端会话验证给出提示并复制编号。
- 关闭 cc 来源后，界面和行为与现版本一致。

验收按项记录，未验证的保留为未验证，不以构建通过代替。

## 6. 可行性证据与待核实

2026-10-08 在本机（cc 2.1.293）只读查看到的事实，仅看字段名，未读对话正文：

- cc 数据目录下有按项目分目录的会话记录文件，每个会话一个，逐行追加；记录里有会话编号、项目目录、时间、自定义标题、是否为子代理、每条助手消息的结束原因（继续调用工具或本轮结束）、权限模式等字段。
- 另有一份运行中会话的登记，每个进程一个文件，含会话编号、名称、项目目录、入口类型、状态和状态更新时间。当时只见到“忙碌”一个状态取值。

待设计阶段核实，核实结果不改变上面的需求，只影响实现方式和验收结论：

- 登记里状态字段的全部取值，是否包含等待审批。
- hooks 能上报哪些事件，是否足以区分等待审批、等待回答、完成和中断。
- 终端和 IDE 会话能定位到哪一级。
- 这些都是 cc 的内部格式，可能随版本变化；格式不识别时按 R-08 显示未知。
