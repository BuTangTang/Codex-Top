## 最小实现路线

当前 companion 工程已声明 Expo 54、React Native 0.81.5、LegendList 3.3.3、FlashList 2.3.2、Reanimated 4.3.0、Keyboard Controller 1.18.5、Unistyles 3.2.4 和 Paper 5.15.3。已安装基础足以先完成精简版；包存在不等于当前页面已经正确使用。

1. 先核对正式会话页已有消息列表、键盘 provider、输入分派与刷新 owner，沿其单一数据源精简组件。不得为展示层再建一份消息仓库或轮询。
2. 参考 assistant-ui 的页面与组件源码，抽取确有价值的展示单元并删减；复制前固定来源提交与许可，保留必要归属。只借鉴设计时不引入其运行时。
3. [assistant-ui 成品接入](https://www.assistant-ui.com/docs/react-native/existing-app)涉及 Uniwind／Tailwind；其官方示例覆盖 Expo 54／RN 0.81，但不能据此认定能与本项目 Unistyles、Metro 和消息 owner 无缝混用。默认不为几页界面新增第二套主题、运行时和构建配置。
4. 单个组件若经小范围验证确实更简单，主管可在既有写权内选择复用；不整套导入后再遗留大量无用入口。不要为视觉改版迁移服务端或重写认证、发送、审批、来源状态。

## 页面规格

### 会话首页

- 只有一个按现有约定排序的会话列表；新对话自动加入前列。标题“会话”居中，搜索点图标才展开。沿用底部“会话／电脑／我的”。
- 每条两行：标题＋时间；项目／电脑来源＋状态。普通行高以 80dp 起调，外侧 16dp；长标题与大字体允许增高。图里的五六条不构成产品条数限制。
- 小型状态符号约 18–20dp，实际点击整行；蓝色双弧运行、橙色待处理、绿色勾完成，均配文字。失败、取消、未知明确表达，完成仅代表当前轮。
- 删除三态分类栏、项目／电脑大筛选器、统计大卡、完整路径、重复消息预览和满屏操作按钮。正常同步静默；异常只给一行可恢复提示。
- 正在翻列表时不立即把正在阅读的行移走；保留可见位置，最新结果可通过回到顶部查看。不能为了稳定位置永久关闭自动发现。读取失败保留已加载数据并明确不完整。
- 本批不恢复此前延后的手机新建任务能力；没有真实能力的加号不展示。行操作复用已经支持的动作，不新增删除、归档等语义。

### 对话详情

- 紧凑顶栏：返回、标题、更多；来源放短副标题。正文页隐藏底部三个导航入口。
- 用户消息用浅蓝小气泡；助手长回答直接排在页面上，减少头像、气泡外框和重复时间。保留 Markdown、代码、复制与必要的现有附件能力。
- 工具执行过程默认一行折叠，展开后看详情。待审批只在真实可操作请求存在时出现；按钮与请求提供的选项一致。取消、过期和已处理请求不能继续提交。
- 输入框初始一行，随输入增高到约 5 行后内部滚动。保留草稿、发送反馈和单飞保护。只展示已支持的常用操作，其余收进更多；已获准的业务能力不能因删减按钮变得不可达。
- 发送中、已受理、等待回复、失败是不同状态。不能因为气泡出现或动画结束就宣称发送成功、任务完成。失败保留文字及明确重试入口，不自动重复提交。

### 电脑、我的

- 电脑页继续展示来源电脑、在线情况及项目／历史入口，使用平面列表。
- 我的保留当前账号、通知、外观、连接和关于等现有必要设置；维持仅简体中文。账号密码入口沿现有业务，日常页面不暴露协议术语。

## 刷新与动效：少做，保证连续

| 场景 | 确定行为 |
|---|---|
| 列表进入对话、返回 | 使用现有原生导航转场，约 220–280ms；允许中途返回，取消后落在正确页面。删除 B 分镜中的整行变形、共享元素和自定义弹性飞入。 |
| 发送消息 | 按下即时反馈；仅新气泡做一次短淡入／小距离上移，约 140–180ms。恢复历史和返回页面不重播消息入场。 |
| 流式回复 | 对同一稳定 ID 的回复增量更新；保留已显示文本。按现有渲染节奏合并高频增量，不每个字符重建整个列表或重播 Markdown 动画。首段可短淡入，后续正文稳定增长。 |
| 看最新消息 | 在底部时维持底部阅读位置；不要每个文本增量触发一次独立 smooth-scroll，造成滚动动画排队。 |
| 翻旧消息 | 用户主动上滚立即停止自动跟随；新消息只显示“回到最新”入口。点击后恢复跟随，加载更早历史时锚定当前消息。 |
| 键盘与输入区 | 复用唯一的 Keyboard Controller／现有键盘 owner。键盘、输入框、可视区域同一次联动，不能叠加第二套避让。原生返回键先收键盘，再返回页面。 |
| 状态变化 | 双弧运行；明确完成后转为勾，约 160–220ms。行本身不跳动。用户启用减少动态效果时停持续旋转，保留静态状态。 |
| 重连、前后台恢复 | 更新现有页面，保留消息、草稿、阅读锚点；不闪空列表，不重播历史入场，不把未知结果重发成新消息。 |

这些时间为首版取值，可由实施任务按实机调节。重点验收稳定、可打断和无重复动作，不做逐像素复刻或逐帧参数审核。

## 实施与验收交接

主管先读取自己最新状态及文件写权，结合当前消息角色、历史加载、revision_gap 和状态来源冲突安排批次。**本次用户已授权设计后继续实施，D-10 不再需要等待用户醒来重新批准界面开工；已有功能问题仍需按依赖处理，不得用新样式掩盖。**

1. 复用“手机 UI 与交互”任务。先交付会话列表＋对话正文＋输入区这一条完整路径，尽量从现有正式页面删减，不另起长期平行产品。
2. 在独立合成环境检验刷新／滚动／键盘，再接现有真实消息链路。数据覆盖约 200 条混合长短消息、长中文回复和代码块；数据量只服务压力与定位验证，可调整。
3. 主管独占统一构建与 Computer Use。Android 打包后实际检查：首次打开历史、发送并流式接收、生成中翻历史、回到最新、上拉加载历史、输入多行、键盘反复开合、系统返回、快速进出同一会话、断线恢复和前后台恢复。
4. 浅／深色、大字号与小屏检查可读性；减少动态效果下功能可用。记录版本、设备、操作、结果和未覆盖项。模拟器／网页不代替小米真机；不承诺截图无法证明的动画流畅度。
5. 新 UI 与旧功能均通过后按项目既有要求阶段提交／推送，只提交本批文件。UI 任务交回写权后由主管整合；业务未通过、真实审批或锁屏推送未验证的项目保留未完成。

本设计任务新增文件仅在本目录：README、prompts 和三张 PNG；未安装依赖、未修改业务、未运行或展示手机演示包、未提交。主仓 `docs/STATUS.md`、REQ、任务表及文档入口由主管接收后统一更新，避免与正在运行的主管并写。
