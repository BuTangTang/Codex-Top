# Codex Top 设备接口文档

给 M5Stack Tab5 等局域网设备用：读 Codex Top 已经算好的任务状态、用量、主题，并能让电脑打开某个任务。

- 适用：Codex Top 原生 Mac 版构建 160 起，接口格式版本 `1`。
- 依据：[需求 v0.2](requirement.md)、[详细设计 v0.3](detailed-design.md)。本文和设计附录 A 一致，有出入以代码为准并回来改本文。

## 1. 先在电脑上打开

1. Codex Top 设置 → 任务监控 → 设备读取，打开“允许局域网设备读取”。
2. 记下下面显示的 6 位数字口令（可以点“换一个”，换完旧口令立刻失效）。
3. 设置里那一行“设备可以访问 192.168.x.x:8770”就是电脑地址。

不打开开关时只有电脑自己能读（`http://127.0.0.1:8770`，不用口令），局域网设备连不上、也搜不到。第一次打开时 macOS 可能弹“接受传入连接”“查找本地网络设备”，点允许。

## 2. 找到电脑

二选一：

- **自动发现**：局域网服务发现（mDNS／Bonjour）查服务类型 `_codextop._tcp`。实例名是电脑名，TXT 记录有 `v=1`（接口格式版本）、`auth=token`（要口令）。查到的地址和端口直接用。
- **手填**：设置里显示的 `IP:8770`。端口固定 8770。

## 3. 带口令

局域网来的每个请求都加请求头：

```
Authorization: Bearer 123456
```

- 没带或不对回 401，不给任何内容（连地址存不存在都不说）。
- 同一台设备连续错 5 次，1 分钟内一律回 401，过后自动恢复。
- 电脑自己（127.0.0.1）请求不用口令。

## 4. 接口一览

| 做什么 | 方法和地址 | 成功 |
|---|---|---|
| 总览：各状态几个 | `GET /api/v1/status` | 200 |
| 任务列表 | `GET /api/v1/tasks` | 200 |
| 用量和额度 | `GET /api/v1/usage` | 200 |
| 主题 | `GET /api/v1/theme` | 200 |
| 打开某个任务 | `POST /api/v1/tasks/<短编号>/open`（不带正文） | 200 |

通用约定：

- 返回都是 JSON（UTF-8），键名是下划线写法。每次回完就断开连接，不缓存。
- 时间都是秒级 Unix 时间戳，字段名以 `_epoch` 结尾；没有就是 `null`。
- 每份内容带 `schema_version`（现在是 1）和 `generated_at_epoch`（这份内容是什么时候拼的）。
- 建议每 2 秒左右读一次；电脑上每次请求只花约 2 毫秒 CPU，不读磁盘。
- 请求头最大 8KB；电脑同时最多处理 8 个连接，5 秒内没发完请求就断开。

## 5. 各接口

### 5.1 总览 `GET /api/v1/status`

```json
{
  "schema_version": 1,
  "generated_at_epoch": 1794452061,
  "computer": "我的 MacBook Pro",
  "state": "waiting",
  "counts": { "running": 2, "waiting": 1, "failed": 0, "fresh_done": 1, "watching": 4, "finished": 56 }
}
```

| 字段 | 说明 |
|---|---|
| `computer` | 系统设置里的电脑名 |
| `state` | 整体状态，和悬浮球一致：`failed` 有出错 → `waiting` 有等你处理 → `running` 有在跑 → `unknown` 看不清 → `idle` 都没有；另有 `loading` 刚启动还在读、`paused` 用户暂停了刷新 |
| `counts.running` / `waiting` / `failed` | 在跑、等你处理（回答或批准）、出错的任务数 |
| `counts.fresh_done` | “刚完成”还没看的任务数 |
| `counts.watching` | 关注中、还没结束的任务数 |
| `counts.finished` | 已结束的任务数（只给个数，不给明细） |

### 5.2 任务 `GET /api/v1/tasks`

```json
{
  "schema_version": 1,
  "generated_at_epoch": 1794452061,
  "titles": true,
  "items": [
    {
      "id": "9f092da7cce9",
      "source": "claude_code",
      "title": "示例任务",
      "phase": "waiting",
      "section": "attention",
      "status_text": "等待你的回答 · 已等 13 分钟",
      "started_at_epoch": 1794451200,
      "waiting_since_epoch": 1794451281
    },
    {
      "id": "c39411a713f2",
      "source": "codex",
      "title": "另一个示例",
      "phase": "running",
      "section": "active",
      "status_text": "正在执行任务 · 1 个子任务",
      "started_at_epoch": null,
      "waiting_since_epoch": null
    }
  ],
  "has_more": false,
  "finished_count": 56
}
```

顺序和面板一样：需要你处理 → 刚完成 → 进行中。最多 20 条，多了 `has_more` 为 `true`。已结束的不在这里。

| 字段 | 说明 |
|---|---|
| `id` | 短编号，12 位十六进制。同一个任务一直不变（重启、换口令都不变），打开任务用它；倒推不出 Codex／Claude 的会话编号 |
| `source` | `codex` 或 `claude_code` |
| `title` | 任务标题，最多 40 个字（超出以 `…` 结尾）。设置里关掉“给任务标题”时**没有这个字段**，同时顶层 `titles` 为 `false` |
| `phase` | `running` 运行中、`waiting` 待处理（等你回答或批准）、`completed` 已完成、`failed` 出错、`stopped` 已停止、`idle` 未运行、`unknown` 状态未知 |
| `section` | `attention` 需要你处理、`fresh` 刚完成、`active` 进行中 |
| `status_text` | 和面板那一行第二行一字不差，直接显示即可；“已等几分钟”按请求那一刻算 |
| `started_at_epoch` | 这一轮开始的时间。没有可靠开始时间就是 `null`（面板上显示 `--:--`），不要拿别的时间代替 |
| `waiting_since_epoch` | 在等你处理时，开始等的时间；不在等就是 `null` |
| `finished_count` | 已结束的任务数 |

不给：对话正文、路径、项目名、账号、内部编号。

### 5.3 用量 `GET /api/v1/usage`

```json
{
  "schema_version": 1,
  "generated_at_epoch": 1794452061,
  "day_starts_at_hour": 12,
  "codex": {
    "quota": {
      "available": true,
      "observed_at_epoch": 1794452000,
      "windows": [ { "kind": "week", "remaining_percent": 100, "resets_at_epoch": 1795054317 } ]
    },
    "today": { "total": 18109145, "input": 684743, "cached": 17409536, "output": 11633, "reasoning": 3233 },
    "yesterday_total": 663502256,
    "days": [ { "start_epoch": 1793898000, "total": 160198070 } ]
  },
  "claude_code": {
    "available": true,
    "today": { "total": 26785660, "input": 3390072, "output": 37792, "cache_read": 23357796 },
    "yesterday_total": 666485725,
    "days": [ { "start_epoch": 1793898000, "total": 134205048 } ]
  }
}
```

（`days` 实际有 7 个，这里只写了一个。）

| 字段 | 说明 |
|---|---|
| `day_starts_at_hour` | “一天”从电脑本地时间几点开始，现在是 12（中午 12 点切天，熬夜到凌晨还算前一天） |
| `codex.quota.available` | 有没有读到 Codex 额度 |
| `codex.quota.observed_at_epoch` | 最后一次读到额度的时间，没读到过是 `null` |
| `codex.quota.windows[].kind` | `five_hour`（5 小时窗口，套餐有才给）或 `week`（周额度） |
| `codex.quota.windows[].remaining_percent` | 剩余百分比 0～100 |
| `codex.quota.windows[].resets_at_epoch` | 重置时间，不知道就是 `null` |
| `codex.today` | 今天的 token。`input`、`cached`、`output`、`reasoning` 互不重叠，加起来就是 `total` |
| `claude_code.available` | 本机有没有 Claude Code 记录 |
| `claude_code.today` | 今天的 token。`input` 含写入缓存的部分，`cache_read` 是读缓存；三项加起来是 `total` |
| `*.yesterday_total` | 昨天的总数 |
| `*.days` | 近 7 天，最早的在前、最后一个是今天；`start_epoch` 是那一天开始的时刻（中午 12 点） |

### 5.4 主题 `GET /api/v1/theme`

```json
{ "schema_version": 1, "generated_at_epoch": 1794452061, "choice": "system", "effective": "dark" }
```

| 字段 | 说明 |
|---|---|
| `choice` | 设置里选的：`dark` 深色、`light` 浅色、`system` 跟随系统 |
| `effective` | 现在实际显示的：`dark` 或 `light`。设备照这个切自己的界面深浅 |

### 5.5 打开任务 `POST /api/v1/tasks/<短编号>/open`

用任务列表里的 `id`，不带正文：

```
POST /api/v1/tasks/c39411a713f2/open
Authorization: Bearer 123456
```

效果和在 Codex Top 面板里点这一行完全一样：Codex 任务在 Codex 桌面 App 里打开对应对话，Claude Code 任务在 Claude 桌面 App 里打开；“刚完成”的随之标为已看。电脑会等桌面 App 回话再回复，一般不到 1 秒。

| 状态码 | 内容 | 意思 |
|---|---|---|
| 200 | `{"opened":true}` | 已打开 |
| 502 | `{"opened":false,"message":"无法打开 Codex，任务 ID 已复制。请确认已安装 Codex。"}` | 没打开，`message` 是电脑面板上同样会显示的提示（会话编号已复制到电脑的剪贴板） |
| 404 | `{"error":"not_found"}` | 编号对不上，或这个任务已经不在任务列表里（已结束的打不开） |
| 405 | `{"error":"method_not_allowed"}` | 用了 GET，要用 POST |

## 6. 错误码

| 状态码 | `error` | 什么时候 |
|---|---|---|
| 400 | `bad_request` | 请求行写错了 |
| 401 | `unauthorized` | 局域网请求没带口令、口令不对，或连续错 5 次正在锁定 |
| 404 | `not_found` | 地址不存在，或打开任务时编号找不到 |
| 405 | `method_not_allowed` | 方法不对：读取接口只认 GET，打开任务只认 POST；响应头 `Allow` 写了该用哪个 |
| 431 | `request_too_large` | 请求头超过 8KB |
| 502 | — | 打开任务时桌面 App 没打开，见 5.5 |
| 503 | `unavailable` | Codex Top 正在退出等，服务暂不可用 |

## 7. 示例

命令行（同一 Wi-Fi 下的另一台电脑）：

```bash
curl -H "Authorization: Bearer 123456" http://192.168.10.178:8770/api/v1/status
```

```bash
curl -X POST -H "Authorization: Bearer 123456" http://192.168.10.178:8770/api/v1/tasks/c39411a713f2/open
```

```bash
dns-sd -B _codextop._tcp local.
```

ESP32 Arduino（3.x，示意）：

```cpp
#include <WiFi.h>
#include <ESPmDNS.h>
#include <HTTPClient.h>

const char *TOKEN = "123456";            // Codex Top 设置里的口令
IPAddress host; uint16_t port = 8770;

bool findComputer() {                    // 自动发现，找不到就用手填的地址
  MDNS.begin("tab5");
  if (MDNS.queryService("codextop", "tcp") == 0) return false;
  host = MDNS.address(0); port = MDNS.port(0);
  return true;
}

String get(const String &path) {         // 读取：/api/v1/status、/tasks、/usage、/theme
  HTTPClient http;
  http.begin("http://" + host.toString() + ":" + port + path);
  http.addHeader("Authorization", String("Bearer ") + TOKEN);
  int code = http.GET();
  String body = code == 200 ? http.getString() : "";
  http.end();
  return body;
}

bool openTask(const String &id) {        // 打开任务：用任务列表里的 id
  HTTPClient http;
  http.begin("http://" + host.toString() + ":" + port + "/api/v1/tasks/" + id + "/open");
  http.addHeader("Authorization", String("Bearer ") + TOKEN);
  int code = http.POST("");
  http.end();
  return code == 200;
}
```

## 8. 注意

- 局域网里是明文 HTTP，口令只防同一 Wi-Fi 下的人顺手读取，别在公共网络打开开关。
- 读取接口不会改电脑上任何东西；打开任务只做面板上点一下会做的事，不回复、不批准、不移出监控。
- Codex Top 没开、开关关了、电脑换了网络，设备都会连不上；设备上请如实显示“连不上”，不要沿用旧数据当成最新。
