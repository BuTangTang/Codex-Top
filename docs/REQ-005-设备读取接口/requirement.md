# REQ-005 让 Tab5 等设备直接读 Codex Top 的状态：需求

版本：v0.2 **已通过**（2026-11-11，用户：“通过”）。v0.1 已通过（用户：“按建议，通过”，D-01～D-09）；v0.2 按用户新要求加“查询主题”“打开任务”两个接口和任务短编号（D-10～D-12），改动处标了 v0.2。

一句话：Codex Top 在电脑上开几个接口，Tab5 这类设备在局域网里自动找到电脑、带上口令来问，就能拿到任务状态、用量和主题，还能让电脑打开某个任务；设备自己不用再读 Codex、Claude Code 的记录。

## 1. 现在怎样

- Tab5（M5Stack 仓库 `m5-stack-tab5`）显示 Codex 状态，靠的是 Windows 上单独跑的一个 Python 状态桥：它自己调 Codex 官方程序读任务、额度、每日用量，再给 Tab5 一个状态地址。
- 这和 Codex Top 做的是同一件事，等于写了两遍：规则可能不一致，而且状态桥只认 Codex，没有 Claude Code，也没有 Codex Top 已经有的“需要你处理”“刚完成”这些判断。
- 用户原话（2026-11-11）：“我 m5stack 也想介入电脑，但是我不想重复写轮子。”

## 2. 改成怎样

- Codex Top 对外提供四个读取接口：**总览**、**任务**、**用量**、**主题**（v0.2）。内容和面板上看到的一致，是同一套规则算出来的结果，不另算一遍。
- 再加一个动作接口：**打开任务**（v0.2）。设备上选中一个任务点一下，电脑就跳到那个任务，和在面板里点它一样。
- 设备在局域网里**自动发现**开着 Codex Top 的电脑，不用手填 IP。
- 局域网访问要在设置里打开，并且要带**口令**；口令简单一点。
- 电脑**只被请求、不主动推**；设备除了“打开任务”，**只看**，不能改电脑上的任何东西（D-12 修改 D-04）。

用户看到什么：Codex Top 设置里多一块“设备读取”，有开关、口令、是否给任务标题；打开后 Tab5 能在列表里看到这台电脑，填上口令就能显示和悬浮球、面板一致的状态和用量，界面深浅可以跟着电脑走；在 Tab5 上点某个任务，电脑上的 Codex 或 Claude 就跳到那个对话。

## 3. 各接口给什么、做什么

### 3.1 总览

- 在跑、等你处理、失败、刚完成各几个——就是悬浮球上显示的那几个数。
- 关注中的任务一共几个、已结束几个。
- 这份数据是什么时候算的；数据读不到或过期时明确说“未知 / 过期”，不伪装成在跑或完成。

### 3.2 任务

- 关注列表里的任务，顺序和面板一样：需要你处理 → 刚完成 → 进行中。已结束的只在总览里给个数，不给明细（D-07）。
- 每个任务给：来源（Codex 还是 Claude Code）、标题（截断，可在设置里关掉）、状态（在跑、等你回答、等你批准、失败、完成、已停止、状态未知等，和面板同一套）、状态文字（比如“等待你确认 · 已等 3 分钟”）、开始时间。
- 没有可靠开始时间的，明确说没有（面板上显示 `--:--` 的那种），不拿创建时间或当前时间估。
- 每个任务带一个**短编号**（v0.2，D-11）：由内部编号打乱算出，同一个任务一直不变，但倒推不出 Codex／Claude 里的会话编号。“打开任务”就用它指定任务。
- 不给对话正文、文件路径、项目路径、账号、任务内部编号。

### 3.3 用量

- Codex 额度：有 5 小时额度才给 5 小时；周额度给剩余百分比和重置时间。读不到就说读不到。
- Codex 和 Claude Code 各自：今天的 token 数、和昨天比、输入／缓存／输出的构成、近 7 天每天的数。
- “今天”和卡片一样，按电脑本地时间中午 12 点切天。

### 3.4 主题（v0.2，D-10）

- 设置里选的：深色、浅色还是跟随系统。
- 现在实际显示的：深色还是浅色（选“跟随系统”时按系统当前的）。Tab5 照这个切自己的界面深浅。

### 3.5 打开任务（v0.2，D-12）

- 设备带上任务的短编号来请求，电脑就打开这个任务，**和在面板里点这一行完全一样**：Codex 任务在 Codex 桌面 App 里打开对应对话，Claude Code 任务在 Claude 桌面 App 里打开；“刚完成”的任务同时标为已看。
- 只能打开任务接口里列出来的任务（需要你处理、刚完成、进行中）；编号不对或任务已经不在列表里，回“找不到”。
- 打不开（比如没装桌面 App）时，电脑上照面板的老样子提示，设备也收到“没打开”。
- 局域网来的请求同样要口令；本机不用。

## 4. 自动发现和口令

- 设置里一个开关“允许局域网设备读取”，**默认关**。关着时只有这台电脑自己能读（本机调试、脚本用），局域网设备连不上也发现不了。
- 打开后：
  - 电脑在局域网里广播“这里有 Codex Top”，带电脑名，Tab5 搜一下就能找到。广播本身不带任何任务数据。
  - 设置里显示一个简单的口令（几位数字或字母），可以一键换一个新的；设备请求时带上口令，口令不对或没带就不给数据。
- 本机自己读不需要口令。

## 5. 边界和规矩

- **只读，外加一个动作**：除了“打开任务”，任何修改类请求一律拒绝；“打开任务”也只做面板上点一下会做的事，不回复、不批准、不移出监控。
- **不多读数据**：接口只是把 Codex Top 已经算好的结果拿出来，设备来问不会让 Codex Top 多读一次 Codex、Claude Code 的记录。
- **不影响电脑**：设备每 2 秒问一次、持续很久，面板和电脑不卡、不明显多耗电。
- **如实**：缺失、过期、无法判断的状态如实给出，和面板规则一致。
- **隐私**：返回内容里没有对话正文、路径、账号、密钥；标题可以关掉。
- 手机连接（REQ-002）不受影响。

## 6. 范围

做（第一版）：

- 原生 Mac 版里做总览、任务、用量、主题四个读取接口和“打开任务”一个动作接口，加自动发现和口令（D-01、D-05、D-10、D-12）。这是 REQ-004 D-03“搬迁期间原生版不加新功能”的一次例外（D-06）。
- 接口格式单独写成一份说明，Qt 版追平后按同一份格式再做，设备那边不用改（D-01）。
- 本需求只管电脑这一侧；Tab5 固件改用新接口在 Tab5 仓库另起需求（D-08）。旧 Python 状态桥等 Tab5 改用新接口、实测通过后再停（D-09）。

不做（第一版）：

- 电脑主动推送变化（D-04）。
- 除“打开任务”以外的操作，比如单独标记已看、回复、批准、移出监控（D-04、D-12）。
- 兼容旧 Python 状态桥的地址和格式（D-05，用户没选）。

## 7. 审核时的问题（已按建议答复，见 D-06～D-09）

| # | 问题 | 建议 | 理由 / 代价 |
|---|---|---|---|
| Q1 | REQ-004 定过“搬迁期间原生版只修问题、不加新功能”（D-03）。这个接口先做在原生版，算一次例外，可以吗？ | 可以，算例外 | 现在就能用上；代价是 Qt 版追平时要再做一遍（按同一份格式，工作量小）。 |
| Q2 | 任务接口里，已结束的任务给不给明细？ | 只给个数，不给明细 | Tab5 一屏放不下几十条已结束的；要看明细再说。代价是设备上看不到具体哪些结束了。 |
| Q3 | Tab5 固件改用新接口，在哪做？ | 在 Tab5 仓库另起需求做，本需求只管电脑这一侧 | 两个仓库各管各的验收；代价是 Tab5 那边要等这边接口做好才能接。 |
| Q4 | 旧的 Python 状态桥什么时候停？ | Tab5 改用新接口、实测通过后再停 | 过渡期两边都能用，不断档。 |

## 8. 验收

| 场景 | 要看到的结果 |
|---|---|
| 开关关着 | 局域网设备发现不到、连不上；本机能读。 |
| 开关打开 + 正确口令 | 四个读取接口的内容和面板逐项一致：各状态个数、每个任务的来源／状态／状态文字／开始时间、额度、今天和近 7 天用量、主题（设置里切深浅后再读跟着变）。 |
| 打开任务 | 用任务列表里的短编号请求，电脑上 Codex／Claude 跳到对应对话，和在面板里点一样；“刚完成”的随之标为已看；编号不对回“找不到”；没口令被拒。 |
| 短编号 | 同一个任务每次读到的编号一样；编号里看不出会话编号。 |
| 没带口令 / 口令错 / 换了新口令后用旧口令 | 不给数据。 |
| 修改类请求 | 一律拒绝。 |
| 关掉“给任务标题” | 任务里没有标题，其他照常。 |
| 自动发现 | 同一 Wi-Fi 下用工具能搜到这台 Mac，显示电脑名；关掉开关后搜不到。 |
| 状态变化 | 面板上状态变了，设备下一次来问就拿到新的。 |
| 长时间轮询 | 设备每 2 秒问一次、持续 10 分钟，Codex Top 的 CPU 和内存没有明显上涨，面板动画不卡。 |
| 隐私 | 返回内容里查不到对话正文、路径、账号。 |
| 真机 | 用户用真实 Tab5 在家里 Wi-Fi 上看过，确认能找到电脑、显示正确。 |

## 9. 已确认决策

| 编号 | 决定 | 依据（2026-11-11） |
|---|---|---|
| D-01 | 接口先做在原生 Mac 版；Qt 版追平后按同一份格式再做。 | 用户选“原生 Mac 版先做” |
| D-02 | 任务标题默认给（截断），设置里可以关。 | 用户选“默认给，可关” |
| D-03 | 局域网访问要打开开关并带口令，口令简单。 | 解释后用户：“口令吧，简单一点即可” |
| D-04 | 只读，设备主动来问，电脑不主动推，设备不能操作电脑。 | 问“只看还是要能操作”，用户选“只看，主动来问”；此前原话“我们是要被请求” |
| D-05 | 第一版做新的三个接口和自动发现，不兼容旧 Python 桥、不做主动推送。 | 用户在第一版范围里选了“新的三个接口”“自动发现电脑” |
| D-06 | 原生 Mac 版先做这个接口，算 REQ-004 D-03“搬迁期间原生版不加新功能”的一次例外。 | 第 7 节 Q1，用户：“按建议，通过” |
| D-07 | 已结束的任务只给个数，不给明细。 | 第 7 节 Q2，同上 |
| D-08 | 本需求只管电脑这一侧；Tab5 固件改用新接口在 Tab5 仓库另起需求。 | 第 7 节 Q3，同上 |
| D-09 | 旧 Python 状态桥等 Tab5 改用新接口、实测通过后再停。 | 第 7 节 Q4，同上 |
| D-10 | 加“查询主题”接口：给设置里选的（深色／浅色／跟随系统）和现在实际显示的深浅。 | 用户：“我希望再加一个查询主题的接口”；问给什么，选“设置里选的 + 实际在用的” |
| D-11 | 任务带打乱的短编号，同一任务不变、倒推不出会话编号；仍不给内部编号。 | 问用哪种编号，用户选“打乱的短编号” |
| D-12 | 加“打开任务”接口，效果和在面板里点这一行一样；这是 D-04“设备不能操作电脑”的唯一例外。 | 用户：“我选择了对应的任务点击了，那么我请求这个接口，你也可以跳转” |
| D-13 | 五个接口一起做完、一起验收、一起提交。 | 问提交节奏，用户选“一起做完再提交” |
