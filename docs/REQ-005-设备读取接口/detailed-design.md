# REQ-005 让 Tab5 等设备直接读 Codex Top 的状态：详细设计

版本：v0.3 **已通过**（2026-11-11，用户：“通过”）。依据[需求 v0.2](requirement.md)（已通过，D-01～D-13）。v0.2 已通过（用户：“8770，通过”）；v0.3 按需求 v0.2 加主题、打开任务两个接口和任务短编号，新增和改动处标了 v0.3。M1～M3 的三个读取接口已按 v0.2 做进构建 159。

一句话：在原生 Mac 版里加一个很小的接口服务，设备来问时，把 Codex Top 内存里已经算好的状态、用量和主题拼成四份内容返回，设备也能让电脑打开某个任务（和面板里点一下一样）；局域网访问靠设置里的开关和口令，设备靠局域网广播找到电脑。

## 1. 整体分三块

| 块 | 做什么 |
|---|---|
| 接口服务 | 在电脑上等设备来问：认四个读取地址和一个“打开任务”地址，检查口令，把内容或结果发回去。打开局域网开关时顺便在局域网里广播。 |
| 内容整理 | 从面板正在用的那份结果里拼出总览、任务、用量、主题四份内容，给每个任务算短编号。不读磁盘，不另算规则。 |
| 设置 | 设置窗口里加“设备读取”一组：局域网开关、口令、是否给标题，并显示电脑地址和服务状态。 |

现在怎样 → 改成怎样 → 用户看到什么：现在 Codex Top 不对外提供任何东西；改成 App 一开就在本机提供三个只读地址，打开开关后局域网设备也能读；用户在设置里看到开关、口令和“设备可以用这个地址访问”。

## 2. 接口服务

- **一直开着，只是范围不同**：App 启动后就提供接口。局域网开关关着时只接受这台电脑自己的请求（方便本机调试、写脚本）；打开后同时接受局域网里的请求。切换开关时服务立刻按新范围重开，不用重启 App。
- **端口**：固定一个端口（建议 8770，见第 9 节），设置里显示出来。端口被别的程序占着时，设置里显示“端口被占用”，接口不可用，App 其他功能照常。
- **只认五个地址**：总览、任务、用量、主题只认“读”；“打开任务”只认“提交”（v0.3）。别的地址回“找不到”；方法不对（比如对总览提交、对打开任务读）回“不允许”。除打开任务外不做任何修改。
- **口令**：局域网来的请求必须带口令，没带或不对回“未授权”，不给任何内容；本机来的请求不用口令。
- **防止拖垮 App**：同时最多处理 8 个连接，每个请求 5 秒内没收完就断开，请求头超过 8KB 直接拒绝。每次回完就关连接，不保持长连接。设备每 2 秒问一次完全够用。
- **返回格式**：统一是 JSON（UTF-8），不缓存；每份内容都带“格式版本”和“生成时间”，设备可以据此判断是不是旧数据。

## 3. 口令

- 6 位数字（S2，用户：“口令我建议 6 位数字即可”）。
- 第一次打开局域网开关时自动生成，存在 Codex Top 的设置文件里；设置里有“换一个”按钮，换完旧口令立刻失效。
- 设备在请求里带上口令（具体写法见附录）。口令只是防止同一个 Wi-Fi 下的别人顺手读到，不是加密传输——家里局域网用够了（D-03“简单一点”）。
- 防止挨个试：同一台设备连续输错 5 次，1 分钟内不再接受它的请求（直接回“未授权”），过后自动恢复。6 位数字有一百万种，这样就没法一个个试出来。

## 4. 自动发现

- 只有打开局域网开关时才广播；关掉就停。
- 广播内容：服务名是 Codex Top 专用的一个名字，显示名用电脑名（比如“butang 的 MacBook Pro”），附带两条小信息：接口格式版本、需要口令。**不带任何任务数据**。
- Tab5 用局域网服务发现查这个服务名，就能拿到电脑的地址和端口，再带口令来问。

## 5. 各接口的内容（字段明细见附录）

### 5.1 总览

- 整体状态：和悬浮球一致——有失败算失败，有等你处理算等待，有在跑算在跑，都没有算空闲；数据源读不到、状态都看不清时算未知；数据还在读取中、已暂停刷新，各自明确标出来。不会把看不清的说成在跑或完成。
- 个数：在跑、等你处理、失败、刚完成、关注中的未结束任务、已结束（D-07 只给个数）。
- 电脑名、生成时间。

### 5.2 任务

- 关注中的未结束任务和“刚完成”的任务，顺序和面板一样：需要你处理 → 刚完成 → 进行中。最多给 20 条，多了标“还有更多”。
- 每条：
  - 来源：Codex 或 Claude Code。
  - 标题：设置里“给任务标题”打开时才有，最多 40 个字，超出截断（D-02）。
  - 状态：七种之一（在跑、待处理、已完成、出错、已停止、未运行、状态未知），和面板同一套。
  - 状态文字：和面板那一行第二行一样，比如“等待你确认 · 已等 3 分钟”“正在执行任务 · 1 个子任务”“本轮执行已结束 · 1 分钟前”。“已等几分钟”按设备来问的那一刻算。
  - 分段：属于“需要你处理”“刚完成”还是“进行中”。
  - 开始时间：有可靠开始时间才给，没有就明确给“没有”，不估（和面板的 `--:--` 一致）。
  - 等待开始时间：在等你处理时给，方便设备自己显示“已等多久”。
  - 短编号（v0.3，D-11）：把任务的内部编号加上固定前缀后做一次不可逆的摘要，取前 12 位十六进制字符。同一个任务每次都一样（重启、换口令都不变），倒推不出会话编号；两个任务撞上同一个编号的可能性小到可以忽略。
- 不给：对话正文、路径、项目名、账号、内部编号。

### 5.3 用量

- Codex 额度：每个窗口给“是 5 小时还是一周”、剩余百分比、重置时间；有 5 小时窗口才给 5 小时。读不到就标“读不到”，并给最后一次读到的时间。
- Codex 用量：今天的总数和构成（输入、缓存、输出、推理），昨天的总数，近 7 天每天的总数和这一天从什么时候开始。
- Claude Code 用量：同样的结构，构成是输入、输出、读缓存；本机没有 Claude Code 记录时标“没有”。
- “一天”按电脑本地时间中午 12 点切开，和卡片一致；内容里写明切天的钟点，设备照着显示就行。

### 5.4 主题（v0.3，D-10）

- 设置里选的：深色、浅色、跟随系统三者之一。
- 实际显示的：深色或浅色。选“跟随系统”时就是系统当前的深浅，系统切换后设备下次来读就变。
- 生成时间。

### 5.5 打开任务（v0.3，D-12）

- 设备用“提交”的方式请求，地址里带任务短编号，不需要带其他内容。
- 电脑在“需要你处理、刚完成、进行中”这几段里找编号对得上的任务（就是任务接口列出的范围），找不到回“找不到”。
- 找到后做的事和在面板里点这一行**完全一样**：Codex 任务在 Codex 桌面 App 里打开对应对话，Claude Code 任务在 Claude 桌面 App 里打开；“刚完成”的标为已看；打开成功后面板照常收起。
- 打不开时也和面板一样：把会话编号复制到剪贴板，面板上出提示；设备收到“没打开”和同一句提示。
- 等桌面 App 回话再回复设备，一般不到 1 秒；5 秒内没结果，连接按原规则断开，设备当作没打开。
- 口令、连续错 5 次停 1 分钟的规则和读取一样；本机来的不用口令。

## 6. 数据从哪来

- 四份内容都从面板正在用的那份结果里拼：任务和状态来自关注列表，额度和用量来自已经在后台更新的那几份统计，主题来自设置和系统当前的深浅。打开任务直接用面板点一行的那段功能，只是多告诉调用方成没成。
- **设备来问时不读 Codex、Claude Code 的任何文件**，也不会触发额外刷新；Codex Top 原本多久刷新一次还是多久（D-04 只被请求、需求第 5 节“不多读数据”）。
- 拼内容在主线程上做一次很小的整理（几十条任务以内），然后在后台发出去，不影响面板动画。

## 7. 设置界面

设置窗口“任务”一组下面加“设备读取”一组：

- 开关：允许局域网设备读取（默认关）。
- 口令：打开开关后显示，旁边一个“换一个”。
- 开关：给任务标题（默认开）。
- 一行说明：显示“设备可以访问 192.168.x.x:8770”这样的地址；服务出问题时改为“端口被占用”“未能广播”等具体原因。

## 8. 系统权限

- macOS 15 上，第一次打开局域网开关时，系统可能弹“允许 Codex Top 接受传入连接”（防火墙开着时）或“查找本地网络上的设备”的提示，要点允许。App 的说明文字会写清楚用途。
- 本机版是 ad-hoc 签名，重装新版本后系统可能会再问一次。
- 只开在本机范围时不会弹任何提示。

## 10. 测试和验收

- 自动测试（合成数据，不读本机真实记录）：
  - 内容的整理：各种状态、三个分段的顺序、没有开始时间给“没有”、标题关掉时没有标题、标题截断、内容里查不到路径和正文、中午切天的日期；主题三种选择对应的实际深浅；短编号同一任务稳定、不同任务不同、里面不含原编号。
  - 口令判断：本机不要口令；局域网没带、带错、换口令后带旧的都拒绝；同一台设备连续错 5 次后 1 分钟内带对的也拒绝，过后恢复。
  - 接口服务在本机随机端口上跑起来：四个读取地址回内容，别的地址回“找不到”，方法不对回“不允许”，请求头过大被拒；打开任务：编号对得上时调用打开并按结果回复，对不上回“找不到”，局域网来的没口令被拒。
- 实际验收（打包后的真实 App）：
  - 本机用命令行工具读四个地址，内容和面板逐项对照；设置里切深浅后再读主题跟着变。
  - 用任务列表里的编号请求打开，Codex 和 Claude 各试一个，桌面 App 跳到对应对话；用错编号回“找不到”。
  - 打开开关后，用同一 Wi-Fi 下的另一台设备（手机或另一台电脑）带口令读；不带口令被拒；用局域网服务发现工具能搜到这台 Mac。
  - 每 2 秒读一次、持续 10 分钟，看 App 的 CPU 和内存。
  - 真实 Tab5 的验收在 Tab5 仓库那份需求里做（D-08）。

## 附录 A：接口格式（设备和 Qt 版照这个做，审核可跳过）

请求：`GET http://<地址>:8770/api/v1/status`（`/tasks`、`/usage`、`/theme` 同理）；打开任务是 `POST http://<地址>:8770/api/v1/tasks/<短编号>/open`，不带正文。局域网请求带请求头 `Authorization: Bearer <6 位数字口令>`。

返回状态码：200 正常（打开任务为已打开）；401 口令不对或没带；404 地址不存在或任务编号找不到；405 方法不对；431 请求头太大；502 桌面 App 没打开（v0.3）；503 服务暂不可用。错误时内容为 `{"error": "unauthorized"}` 这类。

自动发现：服务类型 `_codextop._tcp`，实例名为电脑名，TXT 记录 `v=1`、`auth=token`。

时间都用秒级 Unix 时间戳（`*_epoch`），没有就是 `null`。
