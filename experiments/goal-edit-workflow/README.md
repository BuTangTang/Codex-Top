# 目标编辑独立验证版

用户提出通过类似 Computer Use 的界面操作实现目标修改／删除后，先验证最小操作流程。本目录是独立 Swift 包，**不属于正式 Codex Top、手机 APK 或连接组件**。

## 已实现的范围

- 一个一次性编辑会话：读取原目标，核对来源、会话、正文、状态和预算，再发起修改或删除。
- 修改只改变正文；保留原目标状态和预算。用量自然增长不会被当成用户修改冲突，也不会把旧用量写回。
- 动作调用之前登记派发边界；动作开始后出现异常只能显示结果未知，不能当作“没有执行”重发。
- 动作完成后重新读取同一来源，观察到预期状态才确认。未知后可单独重新核对，不再次执行。
- 同一编辑会话内重复或并发点击不会重复派发。不提供跨进程、跨重启的 exactly-once 保证。
- 原生 AppKit 合成窗口展示模拟手机表单和模拟桌面目标；适配器只填本窗口控件并点击本窗口保存／删除按钮。

## 运行

在仓库根目录运行：

```sh
swift test --package-path experiments/goal-edit-workflow
bash experiments/goal-edit-workflow/build-fixture.sh
```

构建成功后打开 `.local/goal-edit-workflow/GoalEditFixture.app`。这是独立测试窗口；不会替换 `/Applications/Codex Top.app` 或手机应用，不申请辅助功能、录屏等权限，不访问网络、真实目标、账号或数据库。

1. 正常场景：输入新目标，提交修改；右侧目标变化且回读确认。重复提交相同文字，实际派发次数仍为 1。
2. 重置后删除：右侧明确没有目标，回读确认；再次删除不增加派发次数。
3. 重置后点击“模拟桌面先修改”，再提交手机旧稿：提示原目标变化，派发次数为 0。
4. 选择“动作成功但回执丢失”后重置，再修改：右侧内容变化，手机侧结果未知；切回正常场景，再点“仅重新核对结果”，确认后动作次数仍为 1。
5. 选择“动作返回但内容未变”后重置，再修改：不报告成功。

关闭窗口即结束样例；再次运行或“重置样例”恢复合成内容。

## 不代表已完成的部分

- 没有真实 Codex 界面执行器、手机传输或生产编辑按钮；此实验不能用于在手机上修改真实目标。
- 当前 Computer Use 工具拒绝操作 Codex 自身。没有通过 AX、AppleScript、坐标脚本、自建代理或内部 IPC 绕过，也没有让其他代理代做受限操作。
- 真实官方编辑路径可能把目标重新设为 `active`。本实验要求保持原状态，不能直接把官方编辑方法接到此适配器并声称行为一致。
- 现有生产目标数据没有强修订编号，秒级 `updatedAt` 不能充当 CAS。实验只是读—操作—回读，不证明原子并发保护，也不能识别删除后重建相同内容的情况。
- 当前适配器即时操作本窗口，尚无真实异步执行所需的超时和取消协议，不能直接当作后台自动化服务使用。
- 后续必须先取得允许且可验证的真实执行路径，核对窗口与会话身份、原控件、预算与状态语义、权限和结果，再整合生产入口。合成窗口通过不能替代这一步。

阶段验证记录见 [目标编辑接入核查](../../docs/validation/goal-read-20261003.md)。
